# Verify Nultron

Agent guardrail, same class as `AGENTS.md`. Not part of the Nultron app.

- **Product** is `apps/`, `packages/`, Chat / Settings / Workspaces / job modes — two products on one renderer since 2026-09-23 (`AGENTS.md`, top table): **Personal** is the Electron desktop app (installer, IPC, no HTTP port; current cut **0.15.1**, under active development again) and **Enterprise** is the hosted multi-user web app. A UI change in `apps/web` usually lands on both; packaging, identity and deploy land on one. Decision record: [`web-pivot-2026-09-18.md`](../../../docs/internal/web-pivot-2026-09-18.md); cut checklist: [`0.15.1-changelog.md`](../../../docs/internal/0.15.1-changelog.md).

- Original pstack skills stay in the Cursor pstack plugin. Call them. Do not copy them into product code or the desktop bundle.
- **Map:** this `features/` map, then pstack `how` for how a subsystem works and where to fix.

A cold agent reads this mid-task. Drive the real app. A green `tsc` or worker summary is not proof.

## Launch

Ready signal (webdev): `GET http://127.0.0.1:3000/chat` returns 200, or the filtered run (`npx pnpm@9.15.9 --filter @agentforge/web dev`, which is `tsx server.ts`) has printed `@agentforge/web:dev: listening on 127.0.0.1:3000` (`apps/web/server.ts:148`). Bind is `127.0.0.1:3000` only. Drive `127.0.0.1`, not a LAN IP.

Ready signal (packaged desktop): Electron window on Chat (or onboarding if no key), and `doctor.mjs --desktop` exits 0 against `host-status.json` (`transport: "ipc"`). **Not** :3000. **Not** `app-url.txt`. **A packaged build cannot be driven over CDP:** `app.exit(1)` fires when it is launched with any debugger switch (`--remote-debugging-port`, `--remote-debugging-pipe`, `--remote-allow-origins`, `--inspect*`; `apps/desktop/main.cjs:24-26`, since 0.14.26), so `win-unpacked\Nultron.exe` driven by Playwright or an F5 config that passes the flag exits with no window. Drive a packaged window by screenshot, keyboard and mouse, and prove the host with `doctor.mjs --desktop`.

**If port 3000 already answers** — that is the **webdev** instance. Doctor that instance for Chat/Settings in the browser. Do not start a second `pnpm dev`. Do not call that the installed app.

**If nothing is listening** (fresh Cloud VM or a stopped local checkout):

```bash
# from repo root; Windows may need npx pnpm@9.15.9
unset DATABASE_URL
export AGENTFORGE_RUNTIME=stub
export AGENTFORGE_DATA_DIR="${AGENTFORGE_DATA_DIR:-$PWD/data}"
# optional; ensureSchema migrates on SQLite open
# pnpm db:push
npx pnpm@9.15.9 --filter @agentforge/web dev
```

Root `pnpm dev` is `turbo dev`, which also starts `apps/portal`. Without `PORTAL_DATABASE_URL` the portal exits 2 and turbo stops the web app with it (driven 2026-09-26: portal "configuration is not usable", web never bound :3000). A UI drive does not need the portal. Playwright's `webServer` is `pnpm dev` inside `apps/web` (`tsx server.ts`), which is the same process as the filter above.

SQLite file: `$AGENTFORGE_DATA_DIR/agentforge.sqlite` (default `data/agentforge.sqlite`). First visit creates the local owner. Optional `pnpm db:seed` is not required for Chat.

**Cloud boot** already runs `scripts/cloud-start.sh` (data-dir prep only: `mkdir data`, unset `DATABASE_URL`). Then `pnpm --filter @agentforge/web dev`. Playwright `webServer` in `apps/web/playwright.config.ts` starts `pnpm dev` from `apps/web` with `AGENTFORGE_RUNTIME=stub` and `AGENTFORGE_DATA_DIR` resolved to repo `data/`. `reuseExistingServer` is on unless `CI`.

**Which runtime a bare `tsx server.ts` gets.** `@agentforge/db` loads the dotenv files in this order and dotenv never overwrites a variable that is already set (`packages/db/src/client.ts:11-14`): `../../.env`, `../../.env.local`, `.env`, `.env.local`, relative to `apps/web`. On this checkout the repo-root `.env` holds `AGENTFORGE_RUNTIME=ai` and `apps/web/.env.local` holds `stub` (`.env.local` also names empty `OPENAI_API_KEY` and `GOOGLE_GENERATIVE_AI_API_KEY`), so the first file wins and a bare start is `ai`; a stub instance needs `AGENTFORGE_RUNTIME=stub` on the command line (it beats both files). Read the values with a length-only `awk`, never print them (checked 2026-10-06; no key sits in either file).

**Stub vs live.** `AGENTFORGE_RUNTIME=stub` until a gateway (or other provider) key is saved. A saved key makes `GET /api/v1/settings` report `runtime: "ai"`. `ci:local --e2e` stays stub with no key. Cursor Cloud may have a secret `OPENAI_API_KEY` for live loop proof — doctor `runtime: "ai"` and `hasOpenai: true` before a live send; if the env is missing, stay stub. This Windows machine may already be live — doctor first. Never echo the key.

**Teardown.** Only if this run started `pnpm dev`: stop that PID (Ctrl+C / kill the shell job). Never `taskkill` by image name. Never stop a server you did not start.

## Doctor

Run this first whenever anything looks off, and before every drive:

```bash
# local webdev on :3000 (the operator's instance)
node .cursor/skills/verify-agentforge/scripts/doctor.mjs

# an isolated webdev instance you started yourself on another port
node .cursor/skills/verify-agentforge/scripts/doctor.mjs --base http://127.0.0.1:3200

# packaged desktop (reads OS userData host-status.json — not :3000, not HTTP)
node .cursor/skills/verify-agentforge/scripts/doctor.mjs --desktop
```

It is read-only. Default GETs `/chat`, `/api/v1/settings`, `/api/v1/models`, `/api/v1/knowledge` (reported as `knowledge`) and `GET /api/v1/edit/doctor` on `http://127.0.0.1:3000`. `--desktop` reads `host-status.json` (IPC; no HTTP) from the newest of the candidate userData dirs that exists: `Nultron`, `Kemenkeu AI` and `AIHub Metranet` on every OS, plus the legacy `%APPDATA%\@agentforge\desktop` on Windows (`desktopUserDataDirs`, `.cursor/skills/verify-agentforge/scripts/desktop-app-url.mjs:45-75`). Override the webdev base with `--base http://127.0.0.1:<port>` (or `--base=…`), `PORT`, or `AGENTFORGE_VERIFY_URL`, in that order of precedence (`baseFromArgv` and the `||` after it, `.cursor/skills/verify-agentforge/scripts/doctor.mjs:195-213`) — still loopback only, and ignored with `--desktop`. Exit `0` prints JSON. Stdout is the JSON block, then a blank line, then optional note lines (an edit-endpoint note, for example) and a one-line verdict, so a saved `doctor.json` must keep only the JSON block (or parse up to the first blank line). The verdict for `runtime: "ai"` branches on `hasOpenai`: with a key it says the runtime is live and a provider key is saved; without one it says the runtime is live but no key is saved, so the gateway gate is closed and the desk shows onboarding (drive the gate and onboarding recipes, not Chat). Webdev: `url`, `surface`, `chatStatus`, `runtime`, `hasOpenai`, `gateway` (`{ status, allowed, grace }` from the settings payload's `gateway` object, and nothing else from it: no endpoint, no message; `null` when the payload has none — a recipe that needs "the gate says `needs_key`" reads it here without a second call; on a fresh no-key `ai` desk expect `status: "needs_key"`, and on a keyed desk whose gateway cannot be reached `status: "unreachable"` with `allowed: false`, so read it before a keyed Chat send), `keyFingerprint`, `modeKeys`, `chatCount`, `curation`, `knowledge`, `knowledgeRetrievals`, `knowledgeGraph` (`nodes` / `edges`), `knowledgeVerified`, `knowledgeBackend`, `gatewayName`, `dataDirThisShell`, `sqliteHint`, `edit` (`ffmpeg` / `asr`, or `{ available: false }` when the endpoint is missing). Desktop: `url: "ipc"`, `transport: "ipc"`, `pid`, `dataDir`, `productName`, `gatewayName`, `gatewayBaseUrl`, `edit.ffmpeg` from `host-status.json` `editFfmpeg` when present (the packaged app adds that key a moment after its window loads, not before it, so the doctor waits up to 3 s for it; if it never appears, `edit.ffmpeg` is `null` and `edit.ffmpegPending` is `true`, whereas a `null` with `ffmpegPending: false` means the host could not say). Desktop `curation` / `modeKeys` / `chatCount` stay empty — no HTTP models probe. Exit `1` means do not drive. A missing edit endpoint is a note, not a fail. A cold-start race was seen once (2026-10-05): the first doctor call right after `listening` returned `edit: { available: false }`, and every later call returned ffmpeg and asr. Re-run doctor once before trusting an `edit` miss on a just-started instance. `keyFingerprint` is `true` only on webdev when a gateway key is saved and `openaiKeyFingerprint` is a non-empty `sha256:` string. Cloud and `ci:local --e2e` have no key — expect `false`, do not fail. `gatewayName` is Toko Token on public webdev. `dataDirThisShell` is **this shell's** `AGENTFORGE_DATA_DIR`, not the server's — the host does not expose its data dir over HTTP, so on an isolated drive it says nothing about the instance you are doctoring. Webdev `knowledge: true` means `GET /api/v1/knowledge` returned 200; `false` is not a doctor fail — skip the Knowledge drive if it is false.

Refuse to drive when:

- The URL is not loopback
- `/chat` does not connect or returns 4xx/5xx
- Settings JSON is missing, or the body is not JSON (`doctor.mjs:242`, `:250`)
- `GET /api/v1/models` answers non-200 or a body that is not JSON (`doctor.mjs:268-277`)
- You were about to start a second process on :3000 (webdev)
- You were about to treat :3000 as the packaged desktop app
- `--desktop` is missing `host-status.json`, or `transport` is not `"ipc"`
- `--desktop` finds `ready` is not `true` (`doctor.mjs:125`), or finds no usable `pid` or no `dataDir` in `host-status.json` (`doctor.mjs:129`, `:144`)
- `--desktop` finds the `pid` in `host-status.json` not running. The file outlives the app, so a closed or crashed Nultron leaves `ready: true` behind. Since 2026-09-23 doctor checks the pid with `process.kill(pid, 0)` and fails on a dead one (before that it reported `ok: true` for a stale file — driven: pid 2084 absent, doctor said ok)

**Doctor does not work against a hosted instance.** The review instance (`https://localhost:3443`, [login.md](features/login.md)) sits behind a self-signed certificate, which Node's `fetch` refuses, and a signed-out hosted `GET /api/v1/settings` answers 401, which doctor treats as a fail (`scripts/doctor.mjs`, the `settings.status !== 200` check). So the hosted drives, [login.md](features/login.md) and the signed-in half of [plans.md](features/plans.md), are not doctored: their recipes say what to record in doctor's place. The `/pricing` half of plans.md runs on `:3000` and is doctored there as usual.

`runtime: "stub"` — Chat send is a local stub reply. `runtime: "ai"` — Chat send and studio generate hit the live gateway. Do not call that stub proof. Do not paste or save keys during verification.

## Keys (Nultron only — do not use Hermes tools)

The verify harness is this skill + `doctor.mjs`. Do not call Hermes CLI, mint Hermes dashboard session tokens, or talk to `hermes:api`.

How each Nultron secret is processed:

| Secret | Entered | After save | Unlocks |
|---|---|---|---|
| Gateway key (`openai-key`) | Settings | Host process writes AES-256-GCM `settings.enc`. GET `/api/v1/settings` returns `hasOpenai: true`, never the raw key. Input shows “Saved — paste to replace”. | Chat + image/video on Toko Token. Probe is `GET /v1/models` (Bearer). Host auto-routes Chat: GPT-5/GPT-6/o → `/v1/responses`, Claude 5 / Opus 4.7/4.8 / Sonnet 4.6 → `/v1/messages` (`x-api-key` + `anthropic-version`), Gemini chat → generateContent, else `/v1/chat/completions`. Same key. |
| Wrap key | Never in UI | Electron: Windows Credential Manager `Nultron` / `wrap-key` (keytar) set as `AGENTFORGE_SECRETS_KEY` in the main process itself (`apps/desktop/main.cjs:659`; `host.cjs` is required in-process at `:682`, there is no child). Webdev: gitignored `data/.master-key` or env `AGENTFORGE_SECRETS_KEY`. | Decrypts `settings.enc` |
| Native extras (Google, Anthropic, Ark/Volcengine) | Not in GTM Settings UI (store still holds them) | Same `settings.enc`; UI booleans `hasGoogle` / `hasAnthropic` / `hasVolcengine` only | Optional non-gateway providers |
| Tool keys (Tavily, Brave, FAL, …) | Not in GTM Settings UI | Same file, `hasToolKeys` map | Search / FAL generate |

Do not type into `openai-key` on the operator’s desk unless they asked. `ci:local --e2e` stays stub (`AGENTFORGE_RUNTIME=stub`) and has no key. Cursor Cloud Agents may have a provisioned `OPENAI_API_KEY` secret for live Enhance / Finance / Data proof on that VM only — save it into Settings / `settings.enc` or set `AGENTFORGE_RUNTIME=ai` after doctoring; never print, commit, or screenshot the key. If the env is missing, stay fail-closed on stub. Never paste the Cloud secret on the Windows desk.

**`save-settings` with a blank `openai-key` forgets the saved key.** On Personal and webdev, the Settings form posts `openaiApiKey` on every save, and the field is empty once a key is stored (`apps/web/components/settings-page.tsx:284-289`). Off server mode the host passes the blank on (`keyFieldValue`, `packages/host/src/handlers/settings.ts:226-234`), and `mergeSecrets` deletes the saved key (`packages/core/src/secrets.ts:137-139`). The hosted server drops a blank instead, so this trap is for webdev and the desktop app. Enter inside `settings-edit-turn-cap` (or any field of `settings-form`) submits the same form. `settings-gateway-recheck` probes the real saved key (`handleGatewayCheck`, `packages/host/src/handlers/settings.ts:416`). On `:3000`, read Settings and never submit it: "mutating steps allowed" does not cover Save, Enter in a Settings field or Re-check.

**A stale `unreachable` verdict closes `:3000` for good (driven 2026-10-05).** The host re-checks in the background only an `ok` verdict past its TTL (`needsGatewayRefresh`, `packages/host/src/gateway-gate.ts:559-567`). An `unreachable` or `error` verdict stays on disk, and once `lastOkAt` is older than the 7-day grace the whole desk is onboarding (`:327-330`), even with the gateway up. On 2026-10-05 a timeout recorded on 2026-10-03 had closed `:3000`, so every driver saw onboarding and 403 `gateway_blocked`. Doctor's `gateway` field shows it before a drive: `status: "unreachable"`, `allowed: false`. If the gateway answers (`curl -s -o /dev/null -w "%{http_code}" https://api.tokotokenai.com/v1/models` gives 401 quickly), the orchestrator, not a driver, may run one re-check (`POST /api/v1/settings/gateway/check` with `Origin: http://127.0.0.1:3000`, which costs one unbilled `GET /models`). Record the `gateway` object before and after. It reopened the desk to `ok` that day. Drivers never press `settings-gateway-recheck`.

**Knowledge reads embed, and on a keyed desk they bill (driven 2026-10-01).** On a desk with a live key, `GET /api/v1/knowledge/context?query=…` embeds the query through the gateway. Chat used to fire it with the last message whenever a thread with messages was on screen, so merely opening or reloading a thread billed; since 2026-10-02 it asks with `?threadId=` alone (`knowledgeContextPath`, `apps/web/lib/knowledge-context.ts:17`), which the host answers from the thread's last turn's record with no retrieval and no embedding (`packages/host/src/handlers/knowledge.ts:320-322`), so opening a thread is free and only your own `?query=` calls bill. `POST /api/v1/education/exam` still bills (it calls `retrieveChunks`). Knowledge paste, file and URL ingest, self-check and Map embed too. Only memory add and Soul save are keyless. On a shared keyed desk, answer those routes inside the page with `page.route` (a fulfilled `{"parts":[]}` is enough for the context call) and record the step as "not driven (paid)" against the real host.

## Drive

Stable handles are `data-testid` values from `apps/web`. Prefer those over CSS, coordinates, or tab order. Canonical walk is `apps/web/tests/e2e/foundation.spec.ts`.

**Windows (IDE browser)**

1. `browser_tabs` list. Navigate `http://127.0.0.1:3000/<route>` (omit `position` if you must keep focus).
2. `browser_lock` then `browser_snapshot`.
3. Click / type using snapshot refs. If a ref is missing, `browser_cdp` `Runtime.evaluate` to query `[data-testid="…"]` — do not fall back to clicking by CSS class.
4. Wait on the named testid or URL, not a fixed sleep. Composer send is done when `composer-send` reads `Send` again (up to 30s).
5. Unlock when the whole drive is finished.

**Windows (Claude Code — no IDE browser)**

A Claude Code session has no `browser_*` tool, so it drives with a throwaway Playwright script written to a scratch directory (`playwright` already resolves from `apps/web`). The script is deleted with the run — it never lands in `scripts/`. **Drive `http://127.0.0.1:3000`**: that instance is itself an isolated webdev (throwaway data; it may carry a real, billed key — see the table above), so locale switches and mutating steps belong there, and you clean up what you create. Start your **own** webdev on a free port with its own `AGENTFORGE_DATA_DIR` only when :3000 does not answer, or when the drive needs a state :3000 cannot reach (a closed gate needs `AGENTFORGE_RUNTIME=ai`) — then doctor it with `--base` and stop it yourself. Everything else is unchanged: real composer / form / rail clicks, testid waits, evidence under `evidence/<feature>/<run-id>/`.

```bash
# from the repo root (the doctor path is relative to it)
PORT=3200 AGENTFORGE_RUNTIME=stub AGENTFORGE_DATA_DIR=<throwaway> npx pnpm@9.15.9 --filter @agentforge/web dev &
node .cursor/skills/verify-agentforge/scripts/doctor.mjs --base http://127.0.0.1:3200
```

A throwaway data dir is a **fresh Personal desk**: five rail tabs and no key. To reach the other modes, open `/workspaces`, press `edit-workspace-modes` on Default, press every unpressed `workspace-edit-mode-<id>`, then `save-workspace-modes` (driven 2026-09-30: the rail went from 5 work modes to 14). A scratch script resolves Playwright from `apps/web` (`createRequire("<repo>/apps/web/package.json")("@playwright/test")`), wherever the script itself lives.

Stop only the PID listening on your own port at the end (`Get-NetTCPConnection -LocalPort <port>` → `Stop-Process`), never by image name, and never the operator's :3000 / :3100.

## Harness-wide gotchas

Six traps that cost a driver a drive, in more than one mode. They live **here**, once. A feature file names only its own route or testid and points back at the letter — never restates the rule.

**G1 — Settle before you press a submit button.** A click that lands before React hydrates a real `<form>` is a **native** form submit: the browser reloads the page and the prompt, the rows and any error banner vanish with no request fired and nothing raised — which reads exactly like a swallowed error. Two drives were misread this way (`finance-generate` is `type="submit"` in a real form, `apps/web/components/finance-studio-view.tsx:373`, `:437`). Settle after every `goto` / `reload`, or assert the prompt still holds your text after the click, before concluding anything. The same wait covers the model dropdowns: `useJobModel` leaves the `*-studio-model` of Data, Documents, Finance, Legal, Market, Meeting, Presentations and Research empty and `disabled` for roughly a second (`apps/web/lib/use-job-model.ts:91-118`; `model-select.tsx:63`). Images, Videos and Music do not use that hook: each fills its picker from its own `GET /api/v1/<mode>` and keeps it disabled while the list is empty (`images-studio.tsx:70-91`, `:182`). Either way wait for a non-empty option list, not for the testid. A desk that has never had a key never fills the Images picker: once `images-studio-empty` is up, an empty disabled `images-studio-model` is the pass.

**G2 — A failed job on a `/stream` route is HTTP 200.** `streamJob` flushes the SSE headers before the job runs and returns `{type:"stream", status:200}` unconditionally (`streamJob`, `packages/host/src/job-stream.ts:30`; a rejection becomes the frame at `:57-60`, and the stream is returned at `:85`); a rejection becomes a single `event: job.error` frame carrying the real code and status. **Assert the error testid, never the HTTP status**, on `/api/v1/{research,finance,data,market}/stream`, `/api/v1/legal/matters/:id/run/stream`, `/api/v1/meetings/:id/{transcribe,minutes,run}/stream` and, since Presentations Create moved to streams, `/api/v1/presentations/stream` and `/api/v1/presentations/open-slide/stream` (`presentations-studio.tsx:237`, `:254`). Two exceptions: Documents still posts its plain route, and Presentations' `POST /api/v1/presentations/regenerate`, and both *do* answer a real HTTP 503; and a **closed gate** is a real HTTP 403 `gateway_blocked` thrown before the stream opens, with a **flat** body (`{"error":"gateway_blocked","status":…,"message":…}`), not the nested envelope.

**G3 — A visited studio stays mounted.** `WorkModeKeepAlive` hides an inactive work mode instead of unmounting it (`apps/web/components/work-mode-keep-alive.tsx`: the doc comment at `:40-49`, `WorkModeKeepAlive` at `:50`, the `hidden` pane at `:87`). After one visit, that studio's testid still has **count 1** on every other route, with `isVisible()` false, and its inputs keep their values. So: assert `isVisible()`, never count, for "this mode is not showing"; scope shared testids (`example-gallery`, `example-card`) to the studio's own root or use `.first()`, or Playwright raises a strict-mode violation; and remember a hidden mode's studio is in the DOM even after a `productModes` redirect — assert the **rail** testid for "this desk cannot reach that mode". **Headings too:** once Chat has been visited, its pane's `h1` is first in the DOM on every route, so `page.locator("h1").first()` reads `Chat` on Research and Finance (hit 2026-10-05, two failed assertions in a locale drive). Read the visible heading: `locator("h1:visible")`, or an `h1` scoped to the studio's root testid.

**G4 — Playwright hides scrollbars by default.** Headless chromium launches with `--hide-scrollbars`, so any screenshot meant to prove scrollbar styling, gutter width or overflow shows nothing. Launch with `chromium.launch({ headless: true, ignoreDefaultArgs: ["--hide-scrollbars"] })` for those shots only, and say in the evidence that you did.

**G5 — `page.route` takes a predicate, and an un-awaited handler hangs the drive.** The deterministic repro for the thread-fork race (`page.route("**/api/v1/threads/<id>", async (r) => { await delay(4000); await r.continue(); })`) only works when the pattern matches the **full** URL including the id — a bare `**/threads` also swallows the list request and the rail never paints. Always `await route.continue()` (or `fulfill`), always unroute in a `finally`, and never leave a delayed route installed across navigations.


**G6 — Motion is a context setting, not a CSS hack.** 0.15.0 ends `apps/web/app/globals.css` with one `@media (prefers-reduced-motion: reduce)` block (`:2761` to the end of the file; the banner comment starts at `:2754`) that sets every transition and animation to `0.01ms`. Prove it with `browser.newContext({ reducedMotion: "reduce" })`, then read `getComputedStyle(el).transitionDuration` on `.composer-shell`, `.btn`, `.wash` or `.transition-colors`: `1e-05s` under reduce, `0.12s` (the `--motion-1` step) under `no-preference`. Driven 2026-09-23 on `/chat`. The same setting is why a screenshot under reduce never catches a mid-transition frame.

## Evidence

Write under `.cursor/skills/verify-agentforge/evidence/<feature>/<run-id>/`. That directory is gitignored except `evidence/README.md`. Cleanup must not delete it.

A proof includes:

1. **Action** — what the user did (testid + value), not an internal API poke
2. **Result** — the named end state from the feature file (URL, visible testid, text)
3. **Capture** — IDE screenshot + accessibility snapshot, or Playwright trace on Cloud retry
4. **Doctor JSON** from this run
5. **Side effect** when the feature mutates: thread title in `rail-thread-list`, new workspace name in `workspace-list`. Settings save is out of bounds unless the operator asked to change keys.

Standards:

- Walk the real composer / form / rail click. Do not POST `/api/v1/chat` or `/api/v1/settings` as a substitute for the UI.
- Capture before and after for mutations (empty chat → prompt in `message-list`).
- Stub is the product's own test mode (`resolveRuntimeMode`). It is not a mock you invented. Live generate stays on this machine with the operator's key — never on Cloud.
- A screenshot of the final screen with no action record is not proof.
- Cursor’s browser overlay can inject `data-cursor-ref` and steal clicks. If clicks no-op, say so and use Chrome or Cloud Playwright — do not invent a CSS workaround.

## Helpers

`scripts/doctor.mjs` is the only helper, and `scripts/desktop-app-url.mjs` exists solely because doctor imports it. Nothing else lives in `scripts/`.

| Invocation | What it doctors |
|---|---|
| `node .cursor/skills/verify-agentforge/scripts/doctor.mjs` | webdev on `:3000` |
| `… doctor.mjs --base http://127.0.0.1:<port>` | an isolated webdev instance on another port (`--base=…`, `PORT` and `AGENTFORGE_VERIFY_URL` do the same, in that order of precedence) |
| `… doctor.mjs --desktop` | the packaged app via `host-status.json` |

Do not reverse-engineer it — it prints the fields you need. **Editing these files from a shell mangles backslashes.** The Bash tool collapses `\\` to `\` and `sed` or a heredoc turns `\v` into a vertical tab: on 2026-10-05 `\vendor\sandbox-runtime` became a control character in `features/code.md` and `%APPDATA%\DPSBuddy` lost its backslash in `desktop-brands.md`. Use the Edit and Write tools for any line holding a Windows path or a regex, or build the backslash with `String.fromCharCode(92)`, and finish an edit session with a scan: read every `*.md` here and flag `/[\x00-\x08\x0b\x0c\x0e-\x1f]/` and `%APPDATA%[A-Za-z]`. **A one-off drive script is not a helper.** Write it in a scratch directory, delete it with the run, and never leave it in `scripts/`: fifteen `drive-*` / `loop-*` / `poll-*` / `probe-*` / `reverify-*` files accumulated that way, none of them referenced by any recipe, two of them able to save a real key or decrypt `settings.enc`. They were deleted on 2026-09-15. If a recipe genuinely needs a helper, it goes in this table first.

## Isolate

Two **webdev** instances cannot share port 3000. The packaged app has **no HTTP port** and a different data dir (Electron userData: `%APPDATA%\Nultron` / `~/.config/Nultron` / `~/Library/Application Support/Nultron`), so it can run while `pnpm dev` is up. Playwright’s data dir is the same repo `data/` as the Windows local webdev. Isolation for E2E is the Cloud VM, not a second local port. Do not double-drive the operator’s live window while Cloud Playwright is also pointed at this checkout. If you need a disposable tree, set `AGENTFORGE_DATA_DIR` to a new directory (optional `pnpm db:push`; `ensureSchema` migrates on SQLite open), and optionally `AGENTFORGE_SETTINGS_PATH` so you do not touch the operator’s `data/settings.enc`.
