# Music

Music is the third generate studio (describe-or-lyrics brief, style, title, instrumental, gallery). Without a gateway key the expected state is `music-studio-needs-key` and a quiet Generate. Music stays on the host route `ready` flag (plus `useHostedNeedsKey` on the hosted build), the same rule as Videos: a stub desk with `allowed: true` still quiets Generate. Chat, Documents and Images do not. A keyed desk is ready, so Generate and Write lyrics are live there and a click bills. Two things are unlike Images and Videos and both come from the gateway: **one job returns two takes for one charge**, and the wire is an async Suno relay mounted on the gateway *origin* (`POST /suno/submit/music`, then `GET /suno/fetch/<id>`), not a `/v1` route. That relay has **never been driven live** — Cloud has no egress to the gateway host — so every automated check below stubs `fetch`, and `scripts/probe-gateway-music.ts` is the one-command live proof a keyed desk still owes. Do not paste a gateway key into the shared webdev Settings desk. Map: [`docs/internal/maps/music-mode.md`](../../../../docs/internal/maps/music-mode.md).

## Sub-features

- `music-rail` reaches `/music` from `mode-music` on Default.
- `music-shell` shows `music-studio`.
- `buddy-stage-header` — Nultron on the header's art column (`ModeHeader`, `apps/web/components/mode-header.tsx:66-73`): `buddy-stage-header` and its tap button `buddy-stage-header-tap` (`apps/web/components/buddy-stage.tsx:72`, `:82`) are in the DOM at every width, but the column is `display: none` below 60rem of header width (`apps/web/app/globals.css:1925`; the 60rem `@container` that turns it on is `:1969-1973`), so they are visible only on a wide pane (about a 1280px window and up). While the stage is at least 25% on screen the empty-desk Nultron stands down (see `music-empty`). A visited studio stays mounted, so scope `buddy-stage-header` to `music-studio` or use `.first()`. Detail: [documents.md](./documents.md).
- `music-needs-key` shows `music-studio-needs-key` when no key is ready: the library read said `ready: false` and has finished (`!ready && !loading`), or, on the hosted build only, `useHostedNeedsKey` is true (`apps/web/components/music-studio.tsx:397`). `music-studio-submit` and `music-studio-draft-lyrics` are `disabled` unless both `ready` and the hosted gate allow it (`keyReady`, `:131`, `:367`, `:391`). On a keyed desk `ready` is true, so the note is count 0 and Generate is enabled once there is a brief: a click there is a PAID live generate. Copy points at Settings through `SettingsLinkHint`, so assert the single `<a href="/settings">`, not the word "Settings" (locale-dependent).
- `music-prompt-row` is `music-studio-prompt` and `music-studio-submit` (and, whenever the model has lyrics capability, in either mode, `music-studio-draft-lyrics`, which carries `PROMPT_SUBMIT` too; line 16 below is the right one) in one `PROMPT_ROW` (`apps/web/lib/prompt-row.ts`, used at `apps/web/components/music-studio.tsx:361-402`). Music has no Enhance button. Measured on `:3000` (2026-10-01) in `describe` mode: at a 390px viewport the prompt is 232px wide and `music-studio-submit` is on its own line under it (232px); at 768px the same (446px); at 1280px one line (prompt about 741px, submit about 94px). When present, the draft-lyrics button also takes its own line under 40rem by the same class (not measured). `music-studio-mode` is a plain `select-field` and `music-studio-model` is `select-field min-w-[12rem] flex-1` (`:249`, `:263`). `music-studio-style` and `music-studio-title` (inside the closed `music-studio-advanced`) are `min-w-[10rem] flex-1` inputs in one wrapping row (`:327`, `:339`); that is layout only.
- `music-empty` is `music-studio-empty`, the `StudioEmptyDesk` wrapper inside `music-studio-library` (`apps/web/components/music-studio.tsx:426-431`, `flush`). Count 1 once the library has loaded with no tracks and nothing running (`busy` is generating or drafting lyrics, `:150`); 0 while `loading`, while `busy`, and again once a track exists. It always renders with `data-mode` and `data-tier`, plus `data-staged="true"` only while the header stage is on screen (absent at 1024 and 390 px), holds no text, and draws nothing while the header's Nultron is on screen, so it can be in the DOM with no height. The prompt bar is the page until a track exists.
- `music-modes` shows `music-studio-mode`, a `<select>` with two options, `describe` ("Describe it") and `custom` ("My lyrics"), plus `music-studio-mode-hint` explaining which fields the current mode uses. `custom` adds `music-studio-lyrics` above `music-studio-prompt` (which stays in both modes); `music-studio-style`, `music-studio-title` and `music-studio-instrumental` sit inside the closed `music-studio-advanced` disclosure ("Advanced", `apps/web/components/music-studio.tsx:311`) in **both** modes since 0.15.0 — in the DOM, not visible until it is opened. The header is the title plus one outcome line, `expected-inputs` = "You get: a finished song, saved to the library below and downloadable."; the rail row reads `Music` with no `New` badge. Which fields exist at all is `musicCapabilities(model)` ([`audio-capabilities.ts`](../../../../packages/core/src/models/audio-capabilities.ts)): today only `suno_*` ids carry lyrics / style / title / instrumental, and `resolveMusicMode` silently downgrades Custom to Describe on a model that has no lyrics field. Read the mode back after a model change rather than assuming it stuck.
- `music-no-models` shows `music-studio-no-models` when `GET /api/v1/music` has landed and the desk was offered no music model. `music-studio-model` is then not rendered, and `music-studio-submit` and `music-studio-draft-lyrics` are disabled (`noModels`, `apps/web/components/music-studio.tsx:152`, `:257-275`, `:367`, `:391`). On a desk that lists `suno_music` its count is 0.
- `music-instrumental` shows `music-studio-instrumental`, a checkbox, on a model that supports it. It rides the wire as `make_instrumental`.
- `music-draft-lyrics` shows `music-studio-draft-lyrics` in both modes (driven 2026-09-23). It posts `POST /api/v1/music/lyrics` and fills the lyrics box, switches the mode to `custom` (`music-studio.tsx:175`) and fills `music-studio-title` only when it is blank (`:172-174`). It needs a non-empty `music-studio-prompt` even in custom mode (`:367`), shows whenever the model has lyrics capability (`:362`; both modes on a Suno model, absent otherwise) and is `disabled` while the studio is not ready, and on a keyed desk it is a live model call. **Nothing is stored** — no media row, no gallery tile, no Knowledge card — because it exists so the desk can edit the words before spending a music charge. A draft that is not two sung lines is fetched once more; the box still fills if the second draft is no better.
- `music-harness` is the host path behind the existing Generate and Draft lyrics actions. No new control. A blank title is taken from the sentence (custom mode sends it; describe mode does not add a title field). A music job that returns no takes is submitted once more, then both takes from the try that returned audio are saved. Speech has no control here (see `music-voice-unavailable`).
- `music-estimate` shows the pre-generate cost line `music-studio-estimate` and, beside it, `music-studio-takes-note`, which reads "One job returns two takes and is billed once. Both are saved." (`apps/web/locales/en/music.json:32`). Music is billed flat per job, so the unit is `track`, not `second`. Suno publishes no API list price at all — it sells a consumer subscription — so an id with nothing in the cached gateway catalog omits the price line and **must name no vendor**. Maps: [`music-mode.md`](../../../../docs/internal/maps/music-mode.md) (the spine), [`media-cost-estimate.md`](../../../../docs/internal/maps/media-cost-estimate.md) (the price line), [`renderer-media.md`](../../../../docs/internal/maps/renderer-media.md) (why the gallery `src` is always host-served).
- `music-voice-unavailable` shows `music-studio-voice-unavailable` inside `music-studio-voice` — a sentence, not a control. The host answers `GET /api/v1/music` with `speechUnavailable: "realtime_only" | "no_audio_models" | null`; the studio renders the matching reason, and **renders nothing at all when the value is `null`** (the whole `music-studio-voice` section is behind `speechUnavailable ?`, `apps/web/components/music-studio.tsx:412-413`), so `music-studio-voice-unavailable` can be count 0. `null` means the catalog lists a speech id the job route can reach (`speechReachable`, `packages/core/src/models/audio-capabilities.ts:81-83`, with `speechUnavailableReason` at `:88-93`). Driven 2026-10-01 on `:3000`: the gateway lists `gpt-4o-mini-tts` and `gpt-audio-1.5`, `speechUnavailable` is `null` and the box is count 0. Before that the gateway's only TTS id was `qwen3-tts-instruct-flash-realtime`, which speaks WebSocket behind an `openai` endpoint label and cannot be driven from a job route, so the reason was `realtime_only`. **Either way there is no voice-over button to press, and its absence is the pass.** **Static trace (not driven): the live route cannot return `realtime_only`.** `jobs.ts:161` calls `studioSpeechUnavailable(undefined, tenant)`, which reads `listSpeechModels` (`selectable-models.ts:211-213`) filtered by `isSpeechModelId` (`media-kind.ts:154-156`, role `speech`, realtime excluded), so the reason is only `null` or `no_audio_models`; `studio-generate.test.ts:248` passes only because it hands over an unfiltered list. The recipe's accept-either rule still holds.
- `music-library` shows `music-studio-library` with one `music-studio-track` per saved take — an `<audio preload="none">` element plus `music-studio-download` (`GalleryAudio`, `apps/web/components/gallery-media.tsx`). A take whose file is gone (host `fileMissing`, or a failed load) shows `media-missing` and no download link instead of a player that cannot load; see [videos.md](./videos.md). A single generate adds **two** rows, not one.
- `music-ingest` — a successful generate also writes one `Music` work card per take to the Knowledge Base (prompt or lyrics, model, style, title, duration, `media:<id>` pointer; no bytes). `music-studio-draft-lyrics` adds nothing. See [knowledge-ingest.md](./knowledge-ingest.md).

## How to get to it (user POV)

- Choose Music on the left rail (`mode-music`). A desk that already has it shows the tab. A fresh first-run desk starts with Research, Images, Videos and Presentation only, so turn this one on first (Workspaces, Edit on the desk).
- Open `http://127.0.0.1:3000/music` when the tab is unlocked.

## Driving it with the Nultron harness

Preconditions:

- Doctor exits 0.
- `mode-music` is visible. If not, skip with that precondition — same rule as Images and Videos.
- Do not submit `music-studio-submit` on the shared Cloud `:3000` desk. A live music generate is an operator-asked action on a desk that owns its key.

- **Open Music.** Click `mode-music`. URL matches `/music` (15s). `music-studio` is visible (15s).
- **Settle before asserting.** `loading` starts true and suppresses both `music-studio-needs-key` and `music-studio-empty`. Wait for `music-studio-mode` to be visible and then for either the `music-studio-model` select to gain options or `music-studio-no-models` to appear — that is `GET /api/v1/music` landing — before reading either. Harness-wide gotcha **G1**.
- **No-key state (keyless or stub desk only).** `music-studio-needs-key` is visible when the studio is not ready. Assert the anchor, not the copy. On a keyed desk it is count 0 and `music-studio-submit` and `music-studio-draft-lyrics` enable once there is text, so record that and stop.
- **Empty gallery.** Once the library has settled with no tracks and nothing generating or drafting, `music-studio-empty` count is 1 (`data-mode` and `data-tier` on it, and `data-staged="true"` only while the header stage is on screen; no text, and no height while the header's Nultron is on screen); it is 0 while `loading`, generating or drafting lyrics. The prompt bar stays. Never delete rows to manufacture an empty library.
- **Mode switch.** `selectOption("custom")` on `music-studio-mode` (it is a `<select>`; clicking an option does nothing): `music-studio-lyrics` becomes visible and `music-studio-prompt` stays. `music-studio-mode-hint` changes from "Say what the song is. The model writes the lyrics." to "Paste your own lyrics. Style and title are yours too." Open `music-studio-advanced`: style, title and instrumental become visible. `selectOption("describe")` hides `music-studio-lyrics` again. No POST, no key. Driven 2026-09-23 on `suno_music`.
- **Caps.** `music-studio-prompt` stops at 1 000 characters, `music-studio-lyrics` at 3 000, `music-studio-style` at 200, `music-studio-title` at 80 (`MUSIC_*_MAX`, `audio-capabilities.ts:32-35`). Paste-longer-than-the-cap is truncated, not rejected.
- **Cost estimate.** With a model selected, `music-studio-estimate` is visible when the catalog has a figure for that id. An id with no figure omits the price line (count 0). There is no `music-studio-estimate-unknown` testid. `music-studio-takes-note` sits beside it. No POST, no key, no network: `GET /api/v1/music` is ungated and prices from the already-cached gateway catalog.
- **Voice-over reason.** Read `GET /api/v1/music` first: `speechUnavailable` is `"realtime_only"`, `"no_audio_models"` or `null`. With a reason, `music-studio-voice-unavailable` is visible and non-empty (a catalog whose only TTS id is the realtime one reads the realtime-only sentence). A **blank** box means a missing locale key, which is a fail. With `null` the box is **count 0** and that is the pass: the gateway lists a reachable TTS id (on `:3000` it lists `gpt-4o-mini-tts` and `gpt-audio-1.5`, driven 2026-10-01). Either way assert that no voice-over control exists.
- **Empty-brief guards.** Submit Custom with no lyrics, and Describe with no description. Both are `400` from `parseMusicGenerateBody` before anything can be billed, and the message names the missing field. The studio's own button is `disabled` on an empty brief (`:391`), so this is a direct `POST /api/v1/music` step. A closed gate answers a flat 403 first (`requireGatewayAllowedFor`, `packages/host/src/handlers/jobs.ts:172`); otherwise the parse runs as an argument at `:168`, before any generate, on a keyless desk and on a keyed one.
- **Locale (id).** With the desk on `id` (see [locale.md](./locale.md)), the rail reads `Musik` and the studio strings come from `apps/web/locales/id/music.json`. Testids are locale-invariant. `apps/web/lib/music-locale.test.ts` holds the two key trees aligned.
- **Other handles on this page.** `music-studio-prompt-bar` (the `<form>`), `music-studio-submit`, `music-studio-generating-hint` (shown while a job runs — a Suno job polls for up to ~5 minutes, so this is a long-lived state, not a flash), `music-studio-error` (the red box, `role="alert"`).
- **IDE proof.** Screenshot of the shell, the needs-key banner and the voice-over reason under `evidence/music/<run-id>/`.
- **Harness, stub.** Do not press Generate on a shared desk. The three new skills run in `packages/core/src/music/harness.test.ts` and on the host in `packages/host/src/handlers/music.test.ts` (`runs shape-lyric`, `runs name-song`, `runs both-takes`) against a stubbed relay.
- **Automated proof already in the repo.** `packages/core/src/models/audio-capabilities.test.ts` (roles, reason codes, capability snapping), `packages/core/src/tools/platform/gateway-audio.test.ts` (payload shapes, relay path, poll behaviour, failure reading), `packages/host/src/handlers/music.test.ts` (the whole host path against a stubbed relay: submit → poll → two media rows → gallery → bytes served back), `apps/web/lib/music-locale.test.ts`.
- **Live proof, still owed.** On a desk with a real key: `OPENAI_API_KEY=… pnpm exec tsx scripts/probe-gateway-music.ts`. Exit 0 means the catalog listed a music id, the relay accepted a submit and a finished job returned a playable URL. Exit 1 prints which of the three steps failed; exit 2 means no key. **Record the exit code and the step it reached** — until this exits 0, the relay's request and response shapes are documented, not verified.

## Gotchas

- **One generate produces two rows.** `POST /api/v1/music` answers with a `tracks` array. A recipe that asserts `music-studio-track` count 1 after one submit is asserting the wrong thing. A blank first answer is submitted once more inside the host before that error is shown.
- **There is still no new button on this page.** Draft lyrics, Generate, and the Advanced disclosure are the same controls. The harness runs on those actions.
- **`music-studio-needs-key` is the stub pass.** A missing banner on a keyless Cloud run is a product fail. On a keyed desk its absence is correct.
- **The relay is on the gateway origin, not under `/v1`.** `https://<gateway>/suno/submit/music`, not `…/v1/suno/…`. A 404 there is answered with a purpose-written message naming the path that was tried — if you see it, the mount moved, and the fix is `gateway-audio.ts`, not the studio.
- **A clip URL during `IN_PROGRESS` is the streaming take, not the finished file**, and a failed Suno job still returns `code: "success"` with the real reason in `data.fail_reason`. Both are handled; both will bite anyone reading the relay's JSON by hand.
- **There is no voice-over control and no transcription here.** Speech is wired (`speech_generate`, `POST /v1/audio/speech`) but this studio has no control for it, whether or not the gateway lists a reachable speech id. Transcription is not part of this mode at all.
- **The chat media route stays narrow.** `POST /api/v1/media` accepts image and video only; generated audio never arrives as an upload. This is gotcha G-27 in [`music-mode.md`](../../../../docs/internal/maps/music-mode.md), not one of SKILL.md's G1 to G6; the guard is `packages/host/src/edit/import.test.ts`.
- **A `Music` source on `/knowledge` is a text card pointing at `media:<id>`.** Do not look for an mp3 under `data/media/knowledge/`.
- **A visited studio stays mounted** — harness-wide gotcha **G3**. After `/images` → `/music`, `images-studio` is still in the DOM. Assert `isVisible()`, never `count()`, and scope shared queries to `music-studio`.
- **`music-studio-model` has no literal `data-testid=` in the source.** It is a `testId` prop applied inside `ModelSelect`, exactly like `images-studio-model` / `videos-studio-model`. Grepping `apps/web` for it returns nothing; `getByTestId` finds it.
- **The gateway price catalog is the only price source for music.** There is no curated vendor list price to compare against, so `music-studio-estimate-compare` may be absent where the Videos studio would show one. That is correct, not a missing feature.
- More facts: before the model list lands (`model` is ""), the mode select is disabled and `music-studio-advanced` and `music-studio-draft-lyrics` are absent from the DOM, so settle first; a failed `GET /api/v1/music` sets `ready=false`, so `music-studio-needs-key` and `music-studio-error` ("Could not load music studio") show together; `music-studio-voice` and `music-studio-library` are testids (`music-studio.tsx:413`, `:426`); `music-studio-estimate-compare` appears only with two or more priced peers (usually absent); the `<audio>` element has no testid (select it inside `music-studio-track`); a take with no title reads "Untitled take"; the headless-seeded `media-missing` row cannot be made for audio on a stub desk (`POST /api/v1/media` refuses audio), so the media-missing check in [videos.md](./videos.md) is not available to Music. `mode-skills.test.ts:25-27`, `:41`, `:48` pin the music skills and assert there is no `speak-text`.
- **Driven 2026-10-05 on `:3000` (keyed; maintain3), no submit, no lyrics draft.** The model was `suno_music` and `music-studio-draft-lyrics` present; `music-studio-needs-key` count 0 on a keyed desk and `music-studio-submit` disabled with an empty prompt; `music-studio-mode` `custom` showed `music-studio-lyrics` and `describe` hid it; with Advanced open the prompt, lyrics, style and title truncated at 1000, 3000, 200 and 80 characters; `music-studio-takes-note` visible; `music-studio-estimate` count 0 (no cached price); `music-studio-voice-unavailable` read "This gateway serves no text-to-speech model. Voice-over turns on by itself once one appears in the catalog." and a `music-studio-voice` section was present (a reason, never a control); `POST /api/v1/music` with `{"mode":"custom"}` and `{"mode":"describe"}` each answered 400 and were not billed. The Suno relay itself stays unproven.
