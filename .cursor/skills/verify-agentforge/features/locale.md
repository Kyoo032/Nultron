# Locale

Nultron ships English and Bahasa Indonesia. Settings has one language select; picking a language saves it immediately but **does not retranslate the screen** — a restart banner appears, and only its button applies the new locale to the renderer and re-freezes the host's boot locale. Both the renderer (`apps/web/lib/i18n.ts`) and the host (`packages/host/src/locale-boot.ts`) hold the locale in a module-level frozen variable, which is why a page reload alone is not enough. Testids never change with locale, so every recipe in this map stays valid on an `id` desk — only the visible strings move. Map: [`docs/internal/maps/locale-boot-and-run-harness.md`](../../../../docs/internal/maps/locale-boot-and-run-harness.md).

## Sub-features

- `locale-select` is `settings-locale` on Settings: a `<select>` with `en` ("English") and `id` ("Bahasa Indonesia"). Label `Language` / `Bahasa`, help line "Applies after you restart Nultron…" / "Berlaku setelah Anda mulai ulang Nultron…".
- `locale-restart` shows `settings-locale-restart` (banner "Restart Nultron to apply this language." / "Mulai ulang Nultron untuk menerapkan bahasa ini.") with `settings-locale-restart-button` ("Restart Nultron" / "Mulai ulang Nultron") inside it. The banner is visible exactly while `savedLocale !== locale`. The button stays disabled while `POST /api/v1/settings` is in flight (`localeSaving`).
- `locale-apply` is the button's effect: it waits for that in-flight save, and if the save failed it does not apply. Otherwise `POST /api/v1/settings/apply-locale`, then `applyLocale()` in the renderer and `applySavedLocaleAsBoot()` in the host. Packaged, it also asks the shell to relaunch; on webdev the relaunch is refused and the app just retranslates in place.
- `locale-walk` is the proof that the new locale reached the whole desk: the rail, Chat and at least one job mode read Indonesian.
- `locale-run-output` is the host half — `localeForRun()` (`packages/host/src/run-context.ts`) picks the run's locale, and `withOutputLanguage()` (`packages/core/src/output-language.ts`) appends the output-language rule for Documents, Research, Finance, Data, Videos, Music, Edit, Knowledge, Meeting, Education and Presentations (`OUTPUT_LANGUAGE_SURFACES`, `packages/core/src/output-language.ts:3-15`). This is what makes a generated brief Indonesian, not just the chrome.
- `locale-hosted-default` is the hosted-only first-sign-in default: a person who has never chosen a language is shown, and answered in, the one their browser's `Accept-Language` asks for (`localeFromAcceptLanguage`, `packages/core/src/locale.ts`; `hostedLocale`, `packages/host/src/locale-boot.ts`), in the settings answer, in every job mode and in Chat. An explicit choice always wins and nothing is written. It cannot be driven on `:3000` (the Personal webdev reads no header); the proof is `packages/host/src/hosted-locale-negotiation.test.ts` and `hosted-locale-chat-run.test.ts`, each with a Personal-parity case, and on a deployed hosted build a first sign-in with an `id-ID` browser reaching an Indonesian welcome.
- `locale-error` is `settings-locale-error` (`apps/web/components/settings-page.tsx:462`), a `role="alert"` line under the help text. A failed language save puts the select back on the previous value and shows it (`:332-335`). A failed `apply-locale` call shows it too, but the select and the restart banner stay as they were (`:386-388`). It reads the host's own sentence when it sent one, otherwise `settings.localeFailed` ("Could not change the language. Try again in a moment.").
- `locale-parity` is the source check: the files under `apps/web/lib/*locale*.test.ts` assert en/id key parity per namespace (Market has two, `market-locale.test.ts` and `market-locale-catalog.test.ts`; `common-locale.test.ts` covers the `common` namespace).

## How to get to it (user POV)

- Rail → Settings (`settings-link`), then the Language row near the gateway block.
- Pick Bahasa Indonesia, then press the Restart button that appears under the select.
- Packaged, the app relaunches into the new language. On webdev it retranslates without a relaunch.

## Gotchas

- **Selecting a language retranslates nothing.** Only `settings-locale-restart-button` calls `applyLocale()`. A recipe that changes the select and immediately asserts Indonesian anywhere else fails, and the failure is the recipe's, not the app's. Clicking Restart before the save lands used to apply the previous language, because `apply-locale` re-reads disk. The button stays disabled for that POST, and the click waits for the save and skips apply when the save failed.
- **The hosted default is not a saved language.** For a person who never chose, `GET /api/v1/settings` on the hosted server carries `locale` and `savedLocale` both set to the browser's language, and nothing is on disk: `users[userId].locale` stays absent until they pick one in Settings. A recipe must not read `savedLocale` there as proof that a choice was made, and must not expect the Restart banner. On a desk and on webdev the header is never read.
- **`locale` and `savedLocale` are two different fields.** `savedLocale` is the pending pick and drives the select and the banner; `locale` is the applied, frozen one. The banner is visible exactly while they differ, so asserting the banner is really asserting the mismatch.
- **A page reload does not restart the host.** The Node host freezes its boot locale once (`locale-boot.ts`) and only `apply-locale` re-freezes it, so job output can stay in the old language even after the chrome flips if the apply call did not actually run.
- **A switch can move doctor's `chatCount`.** Each language save is a settings POST, and the host re-lists the gateway's models on every settings POST (`refreshModelCache`, see the settings.md gotcha "A locale-only change is still a settings POST"). On `:3000` doctor's `chatCount` was 120 before a switch and 123 after (2026-10-05). Compare `chatCount` across a locale drive only as "still non-zero", not as equal.
- **Testids are locale-invariant.** `settings-locale`, `settings-locale-restart`, `settings-locale-restart-button` and every `mode-*` id read the same in both languages. Never match a control by its visible text in a locale drive.
- **Some strings are English on purpose.** "English", "Chat", "Edit", "Data", "Ultra", "Toko Token" and the literal `RESET` confirm word are whitelisted by the parity tests. An en value equal to its id value is not automatically an untranslated bug.
- **Model `bestFor` copy is not in the catalogs.** On an `id` desk the job model dropdowns still read "Fast drafts" / "Everyday chat" / "Deep reasoning", because those come from the model registry rather than `apps/web/locales/`. Observed on `/finance` in `id`. Report it as a product gap if it matters; it is not recipe drift.
- **Thread titles follow the locale at creation time.** `defaultThreadTitle(locale)` writes "New thread" or "Percakapan baru", and `isDefaultThreadTitle` recognises both, so a thread made under `en` stays "untouched" after switching to `id`. Do not assert a fresh thread's title matches the current UI locale.
- **The parity count is a moving target.** The glob matched 13 files on 2026-09-15, 14 on 2026-09-17 and 21 on 2026-09-30, with more since, and those files hold about 92 `it(` lines between them (23 files on 2026-10-06), with more locale tests outside the glob in `packages/core` and `packages/host`. Do not script a check that expects an exact number of files or results.
- Smaller facts: the language select is disabled while the save is in flight (`localeSaving`, `settings-page.tsx:453`) and `settings-locale-restart-button` is disabled while it is saving or busy (`:474`), so wait for it to enable before clicking. After the soft apply on webdev the whole shell remounts (`App.tsx:381`, `key={localeEpoch}`), so kept-alive studios and Chat's stale first `h1` reset until revisited and a second `GET /api/v1/settings` fires; if that re-read fails, `App.tsx:288-296` falls back to `applyLocale("en")` and the onboarding gate. More `id` handles: `chat-hero-mascot` (aria-label `chat.empty.mascotHello`), `chat-ideas-hint`, `reasoning-effort-label` ("Berpikir"), `buddy-stage-composer-tap` (only once the chat is non-empty), `desk-buddy-dock` with `data-view` `body|chip|none`; the Finance chooser handles `finance-guide-lead`, `finance-guide-choices`, `finance-guide-<task>` (brief, cashflow, budget, appraisal, ratios) and `finance-guide-change` ("Pilih yang lain"); `finance-primary` holds `finance-parse` ("Baca angka saya") while rows are unconfirmed and `finance-generate` ("Tulis hasilnya") once confirmed (Ratios uses `finance-ratios-parse`).
