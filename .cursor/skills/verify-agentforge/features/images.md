# Images

Images is a generate studio (prompt → gallery), not a canvas editor. It lists gateway image model ids. `images-studio-needs-key` and `images-studio-submit` both follow the host gate: the note shows and Generate is disabled only when `allowed` is false. A stub desk (`allowed: true`) hides the note and can still generate. Live generate is an operator pass on this machine, never Cloud. Maps: [`generate-studios.md`](../../../../docs/internal/maps/generate-studios.md) and [`media-cost-estimate.md`](../../../../docs/internal/maps/media-cost-estimate.md).

Product: both · Instance: main :3000

Same tile as Videos and Music; details in [videos.md](./videos.md).

While the stage is at least 25% on screen the empty-desk Nultron stands down (see `images-empty`). A visited studio stays mounted, so scope `buddy-stage-header` to `images-studio` or use `.first()`. Detail: [documents.md](./documents.md).
- `images-needs-key` shows `images-studio-needs-key` only when the host set `allowed` false (`useDeskNeedsKey`, `apps/web/lib/use-desk-needs-key.ts:36`) and the gallery read has finished (`needsKey && !loading`, `apps/web/components/images-studio.tsx:231`). Documents follows the same hook; Research, Presentations, Videos and Music use `useHostedNeedsKey` instead (always false off the hosted build, `use-desk-needs-key.ts:73`). On a stub desk the note is absent and `images-studio-submit` stays enabled once the prompt is non-empty. While `allowed` is true the button does not protect you: a keyless click is a real POST. On a stub desk that POST saves a local stand-in and does not call the gateway. A keyless non-stub desk derives `needs_key` with `allowed: false` (`gateway-gate.ts:390-391`), so the note shows, the button is `disabled` and a direct POST is a 403 at `jobs.ts:73` before generate runs; the `tool_failed` 400 needs an open gate plus a non-ready image route (`image-generate.ts:63-72`, for example a stored backend selection with no credential) and is bypassed on stub (`studio-generate.ts:308`, `:316-317`). A live click bills.
- `images-harness` — no new control. Generate writes a one-still brief from the sentence, and `images-studio-aspect` follows that sentence until the menu is touched (`poster` → portrait, `banner` → landscape, otherwise square). The call is one image model. A connection that never left (the regex is `ECONNREFUSED|ENOTFOUND|EAI_AGAIN|getaddrinfo|fetch failed|failed to fetch`, `harness.ts:47`; "not found" does not match, and `gateway key`, `is not set` and `does not make images` are never retried) is tried once more with the same brief. A timeout is shown and not retried. A clip or chat model is refused before the call. The gallery still stores the sentence they typed.
- `images-prompt-row` is `images-enhance`, `images-studio-prompt` and `images-studio-submit` in one `PROMPT_ROW` (`apps/web/lib/prompt-row.ts`, used at `apps/web/components/images-studio.tsx:199-236`), and the row answers to its own width, not the window's. Measured on `:3000` (2026-10-01): at a 390px viewport the row is about 232px, `images-studio-submit` is on its own line under the prompt (its top is at or below the prompt's bottom, 232px wide), the prompt keeps 184px, and `images-enhance` is icon-only (40px; its `.enhance-btn-label` is `sr-only`, 1px wide); at 768px the row is 446px, so the submit is still on its own line (40rem is 640px) but Enhance shows its word; at 1280px it is one line (prompt about 700px, submit about 94px). `images-studio-aspect` is a plain `select-field` and `images-studio-model` is `select-field min-w-[12rem] flex-1` (`:163`, `:183-184`).
- `images-empty` is `images-studio-empty`, the `StudioEmptyDesk` wrapper inside `images-studio-gallery` (`apps/web/components/images-studio.tsx:243-246`, `flush`). Count 1 once the gallery has loaded with no items and no generate running; 0 while `loading` or generating, and again once an image exists. It always renders with `data-mode` and `data-tier`, plus `data-staged="true"` only while the header stage is on screen (absent at 1024 and 390 px), holds no text, and draws nothing while the header's Nultron is on screen, so it can be in the DOM with no height. The example/template list (`example-gallery`) comes first; the prompt bar sits under it in normal flow until an image exists.
- `images-estimate` shows the pre-generate cost line `images-studio-estimate` under the controls row (provider list price per image, source + checked date, a cheap/mid/premium word) with `images-studio-estimate-compare` beneath it; an id with no transcribed price omits the price line (count 0). There is no `images-studio-estimate-unknown` testid. Each `images-studio-model` option ends with its own `$x.xx/img` tag. Table: [`docs/internal/research/media-pricing.md`](../../../../docs/internal/research/media-pricing.md). Maps: [`generate-studios.md`](../../../../docs/internal/maps/generate-studios.md) (prompt bar → picker → generate helper → gallery), [`media-cost-estimate.md`](../../../../docs/internal/maps/media-cost-estimate.md) (the price line), [`renderer-media.md`](../../../../docs/internal/maps/renderer-media.md) (why the gallery `src` is always host-served).

## How to get to it (user POV)

- Choose the Images agent on the left rail (`agent-images`), then `agent-open-studio`. Default has the tab on a fresh first-run desk and on every older desk.
- Open `http://127.0.0.1:3000/images` when the tab is unlocked. A hidden generate URL redirects to `/chat`.

## Driving it with the Nultron harness

Preconditions:

- Doctor exits 0.
- `agent-images` is visible on Default. If count is 0, you are on a desk that hid Images (e.g. Legal) — not a missing agent.
- Stub proof: with `allowed: true`, `images-studio-needs-key` is absent and `images-studio-submit` enables once the prompt is non-empty (`apps/web/components/images-studio.tsx`). A stub submit saves a stand-in still and does not bill. Do not submit on a live desk (`doctor` reports `ai`) unless the operator asked: that click bills. A closed gate (`allowed: false`) shows the note and disables the button; both use `needsKey`.

- **Open Images.** Click `agent-images`, then `agent-open-studio` (or go to `/images`). URL matches `/images` (15s). `images-studio` is visible (15s).
- **Closed gate.** When the host set `allowed` false, `images-studio-needs-key` is visible and contains exactly one `<a href="/settings">` (rendered by `SettingsLinkHint`) — assert the anchor, not the word "Settings". `images-studio-submit` is disabled. A keyless stub desk (`allowed: true`) does not show the note. The `id` copy, when the note is shown, is `Tambahkan kunci gateway Toko Token di Pengaturan untuk membuat gambar.`
- **Empty gallery.** The empty state mounts a moment after the load, so wait for it. Once the gallery has settled with no saved images and nothing generating, `images-studio-empty` count is 1 (`data-mode` and `data-tier` on it, and `data-staged="true"` only while the header stage is on screen; no text, and no height while the header's Nultron is on screen). It is 0 while `loading` or generating, and 0 again once an image exists. `example-gallery` is first; `images-studio-prompt-bar` is visible under that list (not a sticky dock).
- **Frame.** Type `a poster of a bakery` into `images-studio-prompt` and do not touch `images-studio-aspect`. Its value is `portrait`. Replace the sentence with `a banner for the shop`; the value is `landscape`. A sentence with no shape stays `square`. Open the menu and pick Square; further typing leaves it on Square.
- **Stub generate.** On a stub desk, submit `a poster of a bakery`. The gallery shows one image and the caption is that sentence. `images-studio-error` is absent. This does not call the gateway. ## Gotchas

- The smoke does not assert `images-studio-needs-key`. On a stub desk (`allowed: true`) the note must be absent. Require it only when the host set `allowed` false.
- The studio posts to `/api/v1/images`, not `/runs/image`. `/runs/image` is fail-closed attach-and-analyze. A closed gate answers 403 `gateway_blocked` (`packages/host/src/handlers/jobs.ts:73`, `packages/host/src/gateway-gate.ts:577-578`). With the gate open and no image route ready (a stored selection with no credential; a plain keyless desk is closed instead, see the sub-feature above), the submit is a 400 `tool_failed` (`packages/host/src/studio-generate.ts:344-348`, from `packages/core/src/tools/platform/image-generate.ts:63-72`), not a silent drop. That 400 holds only on a keyless desk: on a keyed desk (doctor `runtime: "ai"`) the same submit is a PAID image generate. On a stub runtime the same POST saves a 1×1 stand-in instead of calling the gateway; Edit image jobs do not take that stand-in.
- A visible prompt bar is not a successful generate. Proof of generate is a gallery item (or a visible `images-studio-error`).
- Midjourney-style `mj_*` ids appear in the picker whenever the catalog has them — including with no key. The catalog is `models-cache.json` (`cachePath`, `packages/host/src/model-cache.ts:107-115`), written by the last successful `/v1/models` probe and read unconditionally; removing the key does not empty the picker. Only a desk that has *never* had a key (fresh Cloud VM) shows an empty `images-studio-model`. An empty picker is not the needs-key note; the note follows `allowed`. Driven 2026-09-17 on `:3000`: `hasOpenai: false`, 40 image ids including fifteen `mj_*`.
- The estimate is the **provider list price**, not what Toko Token bills (the gateway rate is lower). A mismatch against a gateway invoice is expected, not a bug.
- The line leads with `≈` for an exact figure and `~` for a softened one — never both. `~` means the asked-for tier has no published price, the aspect multiplier is inexact (OpenAI landscape), or the row is low confidence (then "(unverified)" is appended too). OpenAI ids say "at medium quality" because their price is per output token, not per call.
- Read the source clause, not just the number. "… list price" is only used when the vendor’s own page carries the figure; "third-party figure" means a reseller/aggregator transcription (every ByteDance row today); "Unverified estimate, no vendor page" means nobody has a page and the row names no vendor.
- Nothing about the estimate reaches the network. On a desk whose gateway price catalog is not already cached, an unpriced id omits the price line. `images-studio-estimate` count 0 is the pass; do not look for `images-studio-estimate-unknown`.
- A visited studio stays mounted — SKILL.md harness-wide gotcha **G3**. Here that means `images-studio` still has count 1 with `isVisible()` false after you leave `/images`, and `example-gallery` resolves to two elements once Videos has also been visited; scope shared-testid queries to `images-studio`.
- **Do not snapshot the moment `images-studio` becomes visible.** `loading` starts true. Wait until `example-gallery` and `images-studio-prompt-bar` are present. `images-studio-empty` is absent while `loading` is true and mounts (count 1) once the gallery has settled empty. A desk that has never had a key leaves `images-studio-model` with no options and `disabled`; that empty select is the pass. Do not wait for options.
- **How the frame is picked (PR #127, `chooseImageFrame`).** Until the owner touches `images-studio-aspect`, the sentence picks it: portrait words are `poster`, `story`, `cover`, `portrait`, `vertical`, `sampul`, `potret`, `vertikal`, `9:16`, `9x16`; landscape words are `banner`, `header`, `landscape`, `wide`, `cinematic`, `widescreen`, `horizontal`, `lanskap`, `sinematik`, `16:9`, `16x9` (`harness.ts:43-44`, `:65-78`); a clash gives square ("a wide poster" is square), and an untouched menu falls back to square after a generate. The estimate follows the picked frame, so typing a poster sentence with a `gpt-image-2` model selected shows the x1.5 figure with no menu touch: read the estimate with an empty or neutral prompt. A card click only fills the prompt and re-picks the frame (`images-studio.tsx:154`). These examples hold for the full card prompts, not the bare titles. By the regexes: "Quiet kitchen header" and "App in a working desk" give landscape, "About-page portrait" gives portrait, "Launch-page product hero" gives square, "Fog path cover" (a `cover` and a landscape word) gives square.
- A model that does not make images is refused with HTTP 400 `invalid_request` and `images.modelRejected` ("That model does not make images." / "Model itu tidak membuat gambar.", `studio-generate.ts:338-340`), on stub too, because the check runs before the stand-in; it is unreachable from the picker, so only an API POST or a stale `settings.imageGenModel` shows it. While generating, aspect, model, Enhance, the prompt and submit are all disabled and the submit text reads "Generating..." (no testid); after success the prompt clears, the gallery reloads and the model choice is kept. `images-enhance` on a stub desk appends "Name subject, framing, and what must stay out of the frame." (free; the testid becomes `images-enhance-revert`; `images-enhance-error` is an sr-only alert) and on a keyed desk is a paid chat call. `images-studio-error` is hidden when its text is the hosted gateway-blocked sentence; on a non-hosted desk a 403 is a flat body, so the box would read "Image generation failed". An option's price tag is `$x.xx/img` (`$x.xx/gbr` in `id`). A stub submit writes a permanent gallery row and a Knowledge `Images` card (`studio-generate.ts:359-382`): it is free but not free of side effects. `images-header`, `-rail`, `-shell`, `-harness`, `-prompt-row`, `-empty`, `-estimate` and `-needs-key` above are feature ids, not testids (the real hooks are `mode-header`, `expected-inputs`, `images-studio-empty`, `images-studio-estimate`, `images-studio-needs-key`). `buddy-stage-header` and `images-studio-empty[data-staged]` need about 960 px of header width (roughly a 1280 px window).
- **Driven 2026-10-05 on `:3000` (keyed; maintain3), no generate and no enhance.** `expected-inputs` "You get: a generated image, saved to the gallery below."; `images-studio-needs-key` count 0, submit disabled with an empty prompt; with an empty menu untouched "a poster of a bakery" gave portrait, "a banner for the shop" landscape, "a ceramic cup" square and "a wide poster" square, and picking Square then typing kept square; the 10 `example-card` ids (`images-launch-page-product-hero` first), "Quiet kitchen header" gave landscape with a 639-character prompt containing "article header" and "Fog path cover" gave square. The stub half (a real generate adding a gallery row) was driven on an isolated stub instance earlier in the same pass: the gallery grew by one `li` captioned "a poster of a bakery" and the prompt cleared; that instance died with the session and the live generate is paid, so it was not repeated.
