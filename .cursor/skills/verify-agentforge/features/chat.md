# Chat

Chat is the default agent of the chat-first shell on `:3000`: a bare composer, a tier picker (Daily, Fastest, Reasoning) in the header, a usage chip, and its own sessions in a Conversations popover at `/chat`. Stub replies without a gateway key; a saved key uses the live Toko Token gateway. A turn is three layers: **Thinking** (collapsible), **tools** (one row per call; the default agent binds 18 tools and a virtual agent adds `research_dossier`, see `chat-tools`), **output** (the answer only, never a copy of the prompt, never a `Stub reply` prefix). Maps: [`chat-send.md`](../../../../docs/internal/maps/chat-send.md), [`chat-sessions-and-rail.md`](../../../../docs/internal/maps/chat-sessions-and-rail.md) and [`virtual-agents.md`](../../../../docs/internal/maps/virtual-agents.md).

Product: both · Instance: main :3000

Last verified: 2026-10-21 for the greeting and the idea chips (driven on `:3200`); the rest 2026-10-16, tester tree after the OPC strip (P5b).

**Shell (2026-10-12).** `:3000` draws the chat-first shell (`SHELL_LAYOUT` `"chat-first"`, `packages/core/src/agents/product-modes.ts:29`; PR #157). Chat is the generalist agent of the virtual-agents shell ([virtual-agents.md](./virtual-agents.md)). (1) The rail is `agent-rail`: `mode-chat` plus an `agent-<mode>` tile per agent; no session list, `rail-collapse`, `rail-resize` or `workspaces-switcher` ([rail.md](./rail.md)). (2) Sessions are in the header's Conversations popover: `agent-history-toggle` opens `agent-history`, and `rail-thread-list`, `thread-item`, `thread-delete` and `threads-see-all` exist only while it is open (8 rows before Show all, `agent-chat-controls.tsx:166`); `new-chat-link` is a header icon. (3) The header is `AgentChatHeader`: `chat-header`, `agent-name`, `tier-picker`, `chat-header-controls`, and the three icon controls `new-chat-link`, `agent-history-toggle`, `agent-harness-toggle`. (4) The composer is bare: `composer-plus` opens `composer-plus-menu` (`composer-attach`, `composer-enhance`); beside it are `composer-text` (placeholder `Message <name>`) and `composer-send`. `composer-toolbar`, `composer-controls`, `model-picker`, `reasoning-effort` and `chat-header-menu` are count 0; the tier is `tier-picker` ([model-tiers.md](./model-tiers.md)). (5) `composer-send` is an icon button with no text: its accessible name is its `aria-label`, `Send` or `Sending` (`Kirim`, `Mengirim` in `id`), so a wait for the text `Send` becomes a wait for that name. (6) No character stands on the composer: `buddy-stage-composer` is count 0 and `message-list` has no `chat-thread-ledge` class; the character is the head `desk-buddy-chip` in `rail-footer` once a thread has a reply. (7) Since 2026-10-21 the empty Chat has no hero: it is `ChatGreeting`, a greeting, a headline and the key status, with the composer in the middle of the pane and four idea chips under it (`chat-greeting` and `chat-empty-state` below). The steps that need `model-picker`, the composer toolbar or the rail session list are for the `"modes"` fallback layout only and are not driven by this recipe.

## Gotchas

- **Retry usage (DFIND-65).** Run `pnpm --filter @agentforge/core exec vitest run src/runtime/ai-sdk-runtime-blank-reply.test.ts src/runtime/ai-sdk-runtime-resilience.test.ts`. The mocked gateway reports usage before a retryable error, then answers on the second or third attempt; one `run.completed` must carry the sum. The interrupted tool-turn case also checks that a billed tool step survives a failed follow-up.

- **A search refusal is the outbound guard, not a broken search (2026-10-13).** A `web_search` or `web_fetch` row that reads as refused with "Not sent: this search or page address carries the person's private details" (`Tidak dikirim: ...` in Bahasa Indonesia) means the query repeated text from the Knowledge Base, memories, a custom soul or an attachment (five words with at least three that are not stopwords, an account-like code, a figure of six digits or more, or two shorter figures), or a long number or a code from an earlier chat's title. A picture in the turn makes it count as private from the first step. The refusal carries a `kind` (`private`, `stopped`, `too_long`, `credential`, `blob`, `url_too_long`, `url_blob`, `media`, `unguarded`). To drive it on a live key: paste a Knowledge Base source with an unusual sentence of eight or more words, then ask Chat to "search the web for this exact sentence: <the sentence minus its first word>" without typing the whole sentence yourself. Expect the refused row and no results. A search in general terms in the same turn still runs. Not driven yet; the proof so far is `packages/host/src/runs-outbound.test.ts`.

- **An invalid tool call shows no row (AI SDK 5, 2026-11-03).** A call whose JSON fails the tool's schema, a call to a name that is not bound, and a call to a tool that is off are answered by the SDK itself (`parseToolCall`, `ai/dist/index.js:2042`) with an error text the model reads, and the loop goes on. `mapStreamPart` drops the `invalid` call, so the screen shows nothing for it: to see one, read the next request's tool message, not the rows.
- **A closing sentence is not a model answer.** The step-limit sentence is written by the host in the person's language. Do not read it as the model's own summary, and do not look for it in the model's reasoning text.
- A document is read when it is attached but saved when the message is sent, so an attached-then-removed document leaves no desk file. The copy lives under `uploads/~<user>/` and, on a hosted team desk, is visible to that person only (`packages/host/src/desk-files/private-uploads.ts`). Sending the same file again is a no-op (same bytes, same version). The extracted text is masked before it is stored or sent, so a figure that looks like an identifier (a 16-digit value, a card-like number) can come back as `[nik]` or `[card]`. A plain text file attached as `.txt` or `.csv` is read in the browser, not by the host, and is not masked in the thread (the outbound copy still is); it is held to the same 60,000 characters as a document and is not saved on the desk.
