# Desktop

> **Retired 2026-10-14 (Rizky).** The Personal desktop app is being merged into the web app. Its release repo `Kyoo032/Nultron-Desktop` is archived, and no new desktop build will be packed or published. The recipe below stays as a record of the installed app. Do not drive a new pack from it.

Electron is the installed local app. Packaged builds have **no HTTP server**. The renderer talks to the host over IPC. Port 3000 is the **local webdev** (`pnpm dev`) only. Wrap key: keytar uses the product name (`Nultron` / `Kemenkeu AI` / `AIHub Metranet`) plus account `wrap-key`. SQLite and `host-status.json` live in that product's Electron `userData`. Flavor rail names: [desktop-brands.md](./desktop-brands.md). Map: [`docs/internal/maps/desktop-pack-routes.md`](../../../../docs/internal/maps/desktop-pack-routes.md).

## Sub-features

- `desktop-launch` opens the **installed** Nultron. Windows product path: Start menu / NSIS. macOS/Linux: operator-built dmg/zip or AppImage/deb. Splash then Chat (or onboarding if no key) in the Electron window. Main process loads `host.cjs` in-process and the Vite renderer from extraResources. Status file: `host-status.json` under userData (`transport: "ipc"`).
  - Windows: `%APPDATA%\Nultron\host-status.json`
  - Linux: `$XDG_CONFIG_HOME/Nultron/host-status.json` or `~/.config/Nultron/host-status.json`
  - macOS: `~/Library/Application Support/Nultron/host-status.json`
- `desktop-onboarding` (packaged, no saved key): a hello, then the API key field (`onboarding-key`), which accepts Ctrl+V **and** right-click → Paste (0.14.21 fix: Electron Edit menu + context menu in `edit-menu.cjs`). The gateway address is not on the screen (no `onboarding-gateway-host`, no `onboarding-endpoint`). After the host accepts the key, four examples and Start open Chat. There is no "Use offline demo" option and no "Offline demo" copy anywhere since 0.15.0. Skipped once a key exists. Webdev with `AGENTFORGE_RUNTIME=stub` is **not** gated. Full gate states: [gateway-gate.md](./gateway-gate.md).
- `desktop-splash` shows the splash page until the host is ready, then loads the renderer (`loadFile`, not a loopback URL).
- `desktop-chat` loads Chat in the window (not in Chrome on :3000).
- `desktop-dev` (`pnpm desktop:dev`) is the **local webdev in a window**. It waits for `GET /api/v1/ping` on :3000 and does **not** attach preload. That is not packaged proof.
- `desktop-quit` exits `Nultron.exe` (whole process tree) on window close on Windows (a `taskkill /T` of the tree, `main.cjs:162-167`); on Linux it terminates the tracked host children and exits (`terminateHostChildren`, `exitStrategy` "kill-children", `lifecycle.cjs`). On macOS closing the window does not quit; Cmd+Q does (`shouldQuitOnLastWindow` is false on `darwin`, `apps/desktop/lifecycle.cjs:20-22`; `before-quit` at `apps/desktop/main.cjs:893-905`, `window-all-closed` at `:907-911`). No tray, no hidden window. Threads and the saved key stay. Uninstall wipes userData + Credential Manager wrap key. Upgrade (same `appId`) kills the running app, overwrites Program Files / per-user install, and **keeps** `%APPDATA%\Nultron`. It leaves a pre-rename `%APPDATA%\DPSBuddy` folder alone.
- `desktop-updates` (packaged public Nultron only; on macOS the icon renders but the status is `unavailable` with "Updates on macOS are manual for now. Download the new .dmg from GitHub Releases.", `app-updates-check` is disabled and there is no install button, `auto-update.cjs:40`, `:58-63`, `:250-255`): the rail footer icon `app-updates-toggle` (in `rail-footer` beside the theme toggle, always the icon form in `AgentRail`, so assert `data-update-cta`; while a release is available, downloading or ready it becomes a labelled primary button and carries `app-updates-badge`, `sr-only` text that repeats the label, `apps/web/components/app-updates.tsx:141-167`) opens `app-updates-panel`, which checks GitHub Releases in `Kyoo032/Nultron-Desktop` (the repo this tree's `brand.json` names; archived 2026-10-14, no new releases). An installed 0.15.1 copy checks `Kyoo032/Nultron` instead, which now belongs to the private Enterprise repo, so its check fails with an error (source stays private). **Update and restart** downloads `latest.yml` + the hyphenated Setup exe and relaunches. Flavors have no button. Webdev and the hosted web render nothing — `app-updates` count 0, not a disabled strip. An unreachable feed or a release without `latest.yml` is an error state: a short message is shown on `app-updates-status`. The panel has `app-updates-check`, `app-updates-install` (**Update and restart**) and `app-updates-close` (`app-updates.tsx:200`, `:190`, `:207`); install replaces check while a release is available, downloading or ready (`isInstallAction`, `:186-206`). While the desk buddy is the status character (`useBuddyTakesStatus`: the rail's dock is mounted in an expanded rail or a page stage holds the buddy, and no full-body character is on screen; the hook is at `apps/web/lib/desk-buddy-store.ts:333` and the `takesStatus` flag it reads is computed at `:115`) the panel draws no inline `chat-mascot` head and the buddy shows that state instead: charging while a release downloads, surprised once it is ready (`updateMascot`, `apps/web/lib/mascot-triggers.ts:36-51`, which also maps status `error` to the `error` face; `app-updates.tsx:78-82`, `:180`). In a collapsed rail the head still shows. The rail footer can also hold `desk-buddy-chip` between `theme-toggle` and `app-updates-toggle` (`apps/web/components/agent-rail.tsx`, `rail-footer`).
- No mobile Electron/Capacitor/RN target. See [mobile.md](./mobile.md).

## How to get to it (user POV)

- **Packaged Windows:** install the NSIS exe, then Start menu → Nultron. No Node/pnpm on PATH. No :3000.
- **Packaged mac/linux:** operator runs `pnpm desktop:build:mac` or `pnpm desktop:build:linux` **on that OS**. Cloud Linux cannot produce or prove the Windows NSIS exe and must not run `pnpm desktop:build`.
- **Webdev window:** from repo root `pnpm dev` then `pnpm desktop:dev`. That still talks HTTP to local webdev on :3000.

## Driving it with the Nultron harness

Preconditions:

- Packaged proof: Windows — the NSIS app is installed or you launch `win-unpacked\Nultron.exe` after `desktop:build`. mac/linux — the operator-built app on that OS. Cloud cannot prove packaged Windows. Do **not** treat Chrome/`pnpm dev` on :3000 as desktop. A Nultron-named pack has to exist first: on 2026-09-30 `apps/desktop/dist/` still held only the `DPSBuddy Setup 0.15.1.exe` files, `%APPDATA%\Nultron` did not exist, and `doctor.mjs --desktop` exited 1 on the missing `host-status.json`, so this recipe was verified-unreachable on that pass.
- Webdev window proof: `pnpm install` done; `pnpm dev` serving; `pnpm desktop:dev`. If :3000 is already serving, record `desktop-dev` reuse — not packaged.
- Do not run Playwright on Windows for this feature.
- Do not use Hermes tools, Hermes dashboard tokens, or Hermes `hermes:api`. Nultron keys are processed as in the main skill **Keys** section.

- **Packaged launch.** Start the installed app. Splash, then onboarding or Chat in the Electron window (up to ~60s first boot).
- **Doctor.** `node .cursor/skills/verify-agentforge/scripts/doctor.mjs --desktop` exits 0. JSON `surface` is `"desktop"`, `transport` is `"ipc"`, `url` is `"ipc"`. Doctor reads `host-status.json` (Windows also falls back to `%APPDATA%\@agentforge\desktop`). It does **not** GET `:3000` and does **not** require `app-url.txt`.
- **Chat.** In the Electron window: `tier-picker` and `composer` visible (same as [chat.md](./chat.md)), after onboarding if needed.
- **Settings.** In the window, rail `settings-link`; `settings-form` visible. Do not paste a key unless the operator asked.
- **Quit.** Close the window. Process exits. `pnpm dev` on :3000, if running, stays up.
- **IDE proof.** Screenshot of the Electron window on Chat under `evidence/desktop/<run-id>/`. Include doctor JSON (`--desktop`).

## Gotchas

- Cloud / Linux VM: cannot run or rebuild that NSIS exe. Do not run `pnpm desktop:build` here. A missing Cloud `.exe` is not a product fail.
- Packaged Electron **must not** `loadURL('http://127.0.0.1:3000')` and **must not** spawn `node.exe`. If doctor `--desktop` reports an HTTP URL or port 3000, that is a fail.
- Icon/splash flavors: [desktop-brands.md](./desktop-brands.md). Webdev is never a flavor.
- `pnpm desktop:dev` is still the local webdev in a Chromium frame. It is allowed to use :3000. Do not sell that as installer proof.
- Schema is created in-process on first SQLite open (`ensureSchema` / committed drizzle migrations).
- keytar may fall back to a session-only wrap key if the OS keychain is unavailable — doctor still works; note it in evidence.
- Never put `AGENTFORGE_SECRETS_KEY` or the gateway key in the renderer or `NEXT_PUBLIC_*`.
- **A packaged build ignores the dev endpoint hooks.** `bootstrapPackaged` sets `AGENTFORGE_PACKAGED=1` and deletes any inherited `AGENTFORGE_GATEWAY_URL` before `host.cjs` loads (`apps/desktop/main.cjs:673-674`). With that marker the host ignores the dev hooks `AGENTFORGE_GATEWAY_URL` and `AGENTFORGE_TELEGRAM_API_URL` whatever `NODE_ENV` says (`gatewayUrlOverrideAllowed`, `packages/core/src/gateway/pinned.ts:38-40`; `packages/core/src/channels/pinned.ts:31`). `apps/desktop/packaged-env.test.cjs` holds the bootstrap half (`pnpm --filter @agentforge/desktop test`). So setting `AGENTFORGE_GATEWAY_URL` and relaunching the installed app is not a way to point it at a mock; use webdev. The one exception is a flavor's own `brand.json` gateway, see [desktop-brands.md](./desktop-brands.md) `desktop-brand-gateway`.
- Single-instance: a second launch focuses the existing window.
- Cursor browser overlay can steal clicks; the Electron window itself is the primary proof surface for desktop.
- **Uninstall:** NSIS `customUnInstall` taskkills `Nultron.exe` (and the legacy `DPSBuddy.exe` / `Agentforge.exe`, plus `Kemenkeu AI.exe` and `AIHub Metranet.exe`, `apps/desktop/build/installer.nsh:7-11`), `RMDir`s `%APPDATA%\Nultron` plus the legacy `%APPDATA%\DPSBuddy`, `%APPDATA%\Agentforge` and `%APPDATA%\@agentforge` (`:33-36`), and runs `cmdkey /delete` for `Nultron/wrap-key` plus the legacy `DPSBuddy/wrap-key` and `Agentforge/wrap-key`. Only the `RMDir` + `cmdkey` block is gated on **not** an upgrade (`${ifNot} ${isUpdated}`, `apps/desktop/build/installer.nsh:32-40`); the `killRunningApp` taskkill (`:31`) sits outside the guard and runs on every uninstall **and** every upgrade. Reinstall after uninstall must show onboarding. Running setup.exe while the app is open kills `Nultron.exe` then overwrites the existing install. Not driven under the new name yet, and the rename's upgrade path from an installed DPSBuddy is unconfirmed.
- **Upgrade:** same `appId` `com.tokotoken.agentforge`. Desk data and the wrap key stay. Do not treat a missing onboarding screen after upgrade as a fail.
- **userData folder:** packaged `package.json` name used to be `@agentforge/desktop`, so Windows Electron wrote `%APPDATA%\@agentforge\desktop`. Product path is `%APPDATA%\Nultron`. `migrateLegacyUserData()` (`apps/desktop/main.cjs:805-826`, called at `:833`) copies the newest `%APPDATA%\Agentforge` or `%APPDATA%\@agentforge\desktop` desk into `%APPDATA%\Nultron` once, recorded by the marker `legacy-migrated.json` (`main.cjs:82`), and the wrap key is carried forward from the `Agentforge` keychain service (`main.cjs:276-296`). Only DPSBuddy is deliberately not migrated (`LEGACY_PUBLIC_NAMES`, `main.cjs:67-73`), so a DPSBuddy desk is not read and an upgrade from DPSBuddy starts on a fresh desk. Doctor `--desktop` still falls back to the Windows scoped folder if that is all that exists.
- Native rebuild: on Windows, `npx @electron/rebuild -f -w better-sqlite3 -w keytar` after install. Not a Cloud step.
- **WinApp in Cursor** is editor debug for this Windows box (extension `Microsoft-WinAppCLI.winapp`, F5 `type: winapp`, `debuggerType: node`). Stack is **Electron + NSIS**, not WinUI/WPF. Use SDK channel **none**. Do **not** `winapp init` the product tree (no `Package.appxmanifest`, no `@microsoft/winappcli` postinstall, no WinApp SDK bindings in `apps/` / `packages/`). Point `inputFolder` at the install folder (`nsis` is `perMachine: false`, so the default is `%LOCALAPPDATA%\Programs\Nultron`, not Program Files, unless the owner chose it) or `apps/desktop/dist/win-unpacked`. **Do not pass `--remote-debugging-port` or `--inspect`: a packaged build refuses to start with any debugger switch.** `apps/desktop/main.cjs:24-26` is `if (app.isPackaged && lifecycle.hasDebugSwitch(process.argv)) app.exit(1)` (the names are `lifecycle.cjs:161-166` plus any `--inspect-*`; since 0.14.26, `8831bc4`, because the process holds the decrypted gateway key and a bridge into the host), and `win-unpacked` counts as packaged, so it exits 1 with no window. The packaged window is therefore not drivable over CDP, nor by a Playwright `_electron` launch (which adds debugger switches itself): drive it by screenshot, keyboard and mouse, and prove the host with `doctor --desktop`. `.vscode/launch.json` (`:11`, `:21`, `:28`, `:37`, `:47`) still passes the flag, so those F5 configs cannot launch a packaged build. WinApp loose-layout / sparse identity is **not** the NSIS install — doctor `--desktop` + the Electron window still decide packaged proof. Known WinApp sparse-package bug can blank Electron; if that happens, clear debug identity and launch the installed exe directly.
- **macOS packaged launch** is the Mac counterpart of WinApp F5: `pnpm desktop:build:mac:dir` then `pnpm desktop:mac` (the F5 config `Packaged Nultron (macOS .app unpacked)` passes `--remote-debugging-port=9222` and so exits 1, see above). Apple’s Simulator and `Nultron.app` require a Mac. Do not run `desktop:build:mac` on this Windows box or on Cloud Linux. iOS Simulator / Expo are not in this repo.
- **Ship vs desk:** a source edit is not in the app until `pnpm desktop:build`, the Setup exe is installed, and Program Files greps HIT for a string from that edit (`1st try`, `run.probing`, `coerceReasoningEffortForModel`, `readHttpErrorBody` for the 0.14 fixes). Ledger: `docs/internal/0.14-changelog.md` `ship-vs-desk`. `apps/desktop/package.json` reads `0.16.0`; do not trust that number alone for what is installed, check the installed exe.
- **What `doctor --desktop` does and does not tell you.** It fails (exit 1) when the `pid` in `host-status.json` is not running (`doctor.mjs:132-142`), so after a Quit it must fail as stale, and it reads the **newest** `host-status.json` among the `Nultron`, `Kemenkeu AI` and `AIHub Metranet` userData folders, so check `productName` in the JSON. A packaged desk with no key reports `runtime: "stub"` and `hasOpenai: false` (`lifecycle.cjs` `hostStatusRuntime`) and the doctor prints "Safe for Chat send", while the window is on onboarding (`gateway-gate.ts:295`, `needs_key`, closed): read the window, not the verdict line.
- Handles that appear on the first-run screen of a packaged desk: `onboarding-steps`, `onboarding-step-welcome|key|try`, `onboarding-welcome`, `onboarding-next` ("Continue"), `onboarding-form`, `onboarding-continue` ("Check this key", disabled while blank), `onboarding-back`, `onboarding-recheck`, `onboarding-gate-reason`, `onboarding-try`, `onboarding-key-success` ("That key works."), four `onboarding-example` (`data-example` chat, research, images, presentation; each calls `finish()` and opens `/chat`), `onboarding-start` ("Start in Chat"), `onboarding-tour-hint`, `onboarding-setup-check`, `onboarding-desks` / `onboarding-open-desk`. The updates toggle carries `data-update-badge` (`none`, `available`, `busy`) and `data-update-cta` (`none`, `available`, `ready`, `downloading`) with the labels "Update available", "Restart to update" and "Downloading…" (label only on an expanded rail; icon-only when collapsed); `app-updates-install` is disabled while downloading; a startup check that fails fires the updater `error` event, so the panel can show an error before Check is pressed.
- Smaller facts: a boot failure rewrites the splash line to "Could not start the local app. See the data folder: <userData>" (`main.cjs:881-889`); the packaged renderer is a `HashRouter` (`#/chat`); `app.disableHardwareAcceleration()` runs on win32 (`main.cjs:828-830`); `html[data-shell]` is `desktop` only when the preload is present; the right-click menu on non-editable text offers only Copy (`edit-menu.cjs:69`).
