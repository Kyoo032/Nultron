# Documents

Documents is a job: prompt or starter → section preview → DOCX download. It is not a Word editor. Live generate needs a gateway key. Starters load a canned draft without one. Source material is optional and becomes the only facts the model may use. It comes from the **Source material** box (`sourceText`, pasted text, a saved artifact or a Research handoff) and from up to five **desk files** the person picks (`sourceFiles`), under one 120k-character ceiling. A live generate then passes two host checks (structure, and grounding when there is a source) with one repair round, and a draft that still fails ships with a note. A repair call that fails keeps the first draft. With a source, code then cuts any sentence the source still does not support (`documents-source-hold`). Map: [`docs/internal/maps/documents.md`](../../../../docs/internal/maps/documents.md).

Product: both · Instance: main :3000

It renders nothing (count 0) while the desk has no file and none is picked. `desk-sources-toggle` opens `desk-sources-list`, one `desk-sources-option` checkbox per desk file (each carries `data-path`). `desk-sources-hint` reads "Up to 5 files" and becomes the "most that fit" sentence at five picks. A pick shows as a `desk-sources-chip` inside `desk-sources-chips`, removable with `desk-sources-remove`, and stays on screen with the list closed. The sixth pick is disabled, not hidden. `desk-sources-over` appears when the picked file sizes plus the pasted characters pass 120k. Generate, regenerate and `documents-check` all send the picked paths as `sourceFiles` (paths only, never file text). Works without a key; the host reads the files when a request arrives.
- `documents-handoff`, Research's `research-make-document` fills `documents-source-text`, `documents-source-title` and `documents-prompt`, then routes to `/documents`. Renderer-only and consumed once; a reload loses it.
- `documents-starter` loads a preview (`documents-preview`) without a live generate.
- `documents-studio-model` is the generate-bar chat-catalog dropdown.
- `documents-enhance` rewrites the topic via the shared Enhance host (`POST /api/v1/prompts/enhance`, `surface: "documents"`). It is the one Documents control that **works without a gateway key** on a desk (200 in stub, `packages/host/src/handlers/enhance-prompt.ts:49-51`); the hosted server never stubs it, so there it is gated like the rest. After applying, the testid becomes `documents-enhance-revert`. Preview bodies (`documents-preview`, research/data notes, presentation bullets) render markdown the same way Chat `message-output` does.
- `documents-regen` on a section opens `documents-regen-panel` (prompt, model, attach). The panel is the shared `JobRegenPanel`, so it also carries an `sr-only` `documents-regen-file` input; its Cancel button has no testid. Confirm with `documents-regen-submit`; stub/no-key shows `documents-error` with a Settings hint. An empty `documents-regen-prompt` still submits, there is no required-field guard. Regenerate runs no checks and no repair, and a successful one clears `documents-checks-note`.
- `documents-checks-note` is the host's verdict on a live draft that still failed a check after its one repair round. It sits under the header (and under `documents-source-check` when that is open), carries `data-kind="grounding"` or `"structure"`, and says the draft is saved. A grounding note lists the flagged section headings in `documents-checks-sections` and points at `documents-check`, but a live Generate no longer produces one: the source hold cuts the unsupported sentences first and the checks run again on the held draft, so the host answers a structure note (a section held down to a label) or none. The renderer still draws a grounding note when a response carries one. Count 0 for a starter, for a draft that passed (even after a repair), after a regenerate and after a failed generate. The note does not say whether a repair was tried: a draft kept because the repair call failed, or came back empty or unreadable, shows the same note as any other flagged draft (the host log has `document_repair_failed`, and the artifact's `meta.checks.rounds` is 1).
- `documents-check` sits in the header beside `documents-download` and appears only once a draft is on screen. It checks the draft's sentences against the Source material box and the picked desk files (`POST /api/v1/documents/check`, no key, no model call): `documents-source-check` lists `documents-source-supported` and `documents-source-unsupported`, or `documents-source-check-empty` when there is no source.
- `documents-download` builds a DOCX from the in-memory draft. `POST /api/v1/documents/docx` and `POST /api/v1/documents/check` are the only Documents routes with no gateway gate (`packages/host/src/handlers/jobs.ts:218`, `packages/host/src/handlers/documents-check.ts:9`), and the DOCX route also has no tenant lookup, so the DOCX answers 200 even on a stub desk or a closed gate. A regenerated section is included, but the *saved artifact* is not updated, the DOCX and the artifact diverge after any rewrite.
- `documents-source-hold` (a host step name, not a testid: assert the cut text and the checks note) is the host's last step when Generate or a section rewrite has a source (pasted `sourceText` and picked desk files together). Code deletes each body sentence the source does not support, including a sentence that states a number the source never states, before the draft is saved or returned. On Generate it runs after the checks' repair round, and the checks run again on the held draft, so `documents-checks-note` speaks for the draft on screen. A section left empty becomes `documents.harness.sourceGap` in the desk locale (`localeForRun`). A rewrite holds only the section it rewrote. The hold calls no model, adds no button, and skips the finance-flagged route. `documents-check` still only lists overlap, and it now also lists a sentence whose number the source lacks. Stub Generate is still HTTP 503, so the hold is not on the keyless drive; `packages/core/src/documents/source-hold.test.ts` and `packages/host/src/document-generate.test.ts` pin it.

## How to get to it (user POV)

- Choose the Documents agent on the left rail (`agent-documents`), then `agent-open-studio`. A desk that already has it shows the tab. A fresh first-run desk starts with Research, Images, Videos and Presentation only, so hire it first (`/workspaces`, `agent-hire`).
- Open `http://127.0.0.1:3000/documents` when the tab is unlocked.
- Desk files: a file the person or Chat saved on the desk (see [files.md](./files.md)) appears in "Add from desk files" the next time the form is used.

## Driving it with the Nultron harness

Preconditions:

- Doctor exits 0.
- `agent-documents` is visible on Default. If count is 0, you are on a desk that hid Documents, switch to Default or add the tab in Workspaces.
- Stub proof stops at starters + regen 503. Live generate only if the operator asked and doctor reports `ai`.
- The 503 steps below (Source material, Desk files, Generate on stub, Regen without a key) hold only on a stub or keyless desk. On a keyed desk (the operator's `:3000`, `runtime: "ai"`) `documents-generate` and `documents-regen-submit` are PAID live calls, so do not press them there without the operator's say-so. The starter, download, check and desk-file picker steps make no model call on either kind of desk.

- **Open Documents.** Click `agent-documents`, then `agent-open-studio` (or go to `/documents`). URL matches `/documents`. The template list (`example-gallery`, then `documents-starter`) comes first under the title; `documents-studio-prompt-bar` (with `documents-studio-model`) sits under it. `documents-studio-empty` is count 1 on the first open (it always renders, with `data-mode` and `data-tier`, plus `data-staged="true"` only while the header stage is on screen, and may be visually empty); it is 0 while a draft is on screen or a request is busy, and it returns after a failed generate clears the draft. A document preview appears only after Generate or a starter.
- **Starter.** `documents-starter` count is 2. Click the first (`en` "Status memo", `id` "Memo status"), `documents-section` and `documents-regen` are 5. The second (`en` "One-pager brief", `id` "Brief satu halaman"; `apps/web/locales/{en,id}/documents.json:50,75`) is 6, driven 2026-10-05 on an `en` desk. Name the starters by position, not by label, so the step holds in both languages. `documents-preview` is visible. Section bodies show formatted markdown (no extra preview testid).
- **Source material (no key needed).** Click `documents-source-toggle`; `documents-source-text` appears. Type anything and press `documents-generate` (stub or keyless desk only): the request body carries `sourceText` alongside `prompt` and `model` before the 503. Click `documents-source-picker-toggle` to open `documents-source-picker-panel`, on a desk with no artifacts it shows the empty-dossier copy; this is the only picker through which a saved artifact enters Documents by hand (the Research handoff also carries an artifact's Markdown, but `documents-studio.tsx:92-95` never uses its `artifactId`).
- **Desk files as sources (no key needed).** Save a file on the throwaway desk: `POST /api/v1/files` with `{ "path": "notes/plan.md", "content": "..." }`. The picker re-reads the desk on mount, each time the list is opened and each time the form gains focus, at most once every 4 s, so wait that long after the pane mounted. Focus `documents-prompt`. `desk-sources` appears inside `documents-studio` (count 1; it was 0 on an empty desk) and `desk-sources-hint` reads "Up to 5 files". Click `desk-sources-toggle`; `desk-sources-list` lists one `desk-sources-option` per file, with `data-path="notes/plan.md"`. Tick it: one `desk-sources-chip` appears in `desk-sources-chips` and stays after the list is closed. Type a prompt and press `documents-generate` with the route recorded (stub or keyless desk only): the `POST /api/v1/documents` body carries `"sourceFiles":["notes/plan.md"]` and the call ends in HTTP 503 `runtime_stub` on stub. Remove the chip with `desk-sources-remove`: the next request has no `sourceFiles`. Delete the file (`DELETE /api/v1/files?path=notes/plan.md`), refocus after 4 s, and the chip is gone. On a live runtime a path that vanished between pick and send is HTTP 400 `source_file_not_found`.
- **Generate on stub (stub or keyless desk only; a PAID live call on a keyed desk).** `documents-needs-key` has count 0 and `documents-generate` is enabled once the prompt is non-empty. Fill `documents-prompt`, click `documents-generate`. `POST /api/v1/documents` is HTTP 503 and `documents-error` carries the gateway/Settings copy. That also clears any starter draft, `documents-preview` disappears. On a closed gate (`allowed: false`) the button is `disabled` (`documents-studio.tsx:405`: `busy || !prompt.trim() || needsKey`), so a Playwright click waits and times out rather than doing nothing, `documents-needs-key` is visible, and nothing POSTs. That state is unreachable on webdev and the packaged app (a closed gate swaps the whole app for onboarding, and `use-desk-needs-key.ts:22-24` reads the gate once at mount); only the hosted build with a key deferral reaches it, where `documents-needs-key-settings` is the link.
- **Regen without a key (stub or keyless desk only).** Click `documents-regen`. `documents-regen-panel`, `documents-regen-prompt`, `documents-regen-model`, and `documents-regen-attach` are visible. Click `documents-regen-submit`. `documents-error` mentions gateway / Settings / API key. On a keyed desk `documents-regen-submit` is a PAID live rewrite of the section, so stop after the panel opens.
- **Download.** Click `documents-download` to get a DOCX from the starter (no live model).
- **Check against source.** With a starter loaded, paste one of its sentences (six or more words) into `documents-source-text` and add a sentence the source does not contain. Click `documents-check`. `documents-source-check` lists `documents-source-supported` and `documents-source-unsupported`. With the source box empty and no desk file picked, the same button shows `documents-source-check-empty`. A picked desk file counts as source here too. No gateway key and no model call (`POST /api/v1/documents/check`).
- **See a check note.** A real note needs a live generate whose draft fails a check after the repair, which you cannot command. Two ways to see one. (1) Renderer path, no key: with a Playwright route that answers `POST /api/v1/documents` with 200 and the body `{ "title": "T", "sections": [{ "heading": "Alpha", "body": "..." }], "checks": { "passed": false, "rounds": 1, "failures": [{ "check": "grounding", "error": "x", "sections": [0] }] } }`, press `documents-generate`. `documents-checks-note` is visible with `data-kind="grounding"`, `documents-checks-sections` lists "Alpha", and `documents-preview` shows the draft. Use `"check": "structure"` with `"sections": []` for the structure note (no `documents-checks-sections`). Click `documents-regen-submit` on a section (also faked): the note disappears. This proves the display, not the host. (2) Host path, live only: with doctor `runtime: "ai"`, paste a short source into `documents-source-text`, ask for a document on an unrelated topic, and press `documents-generate`. The response carries `checks` only when a check still failed, so a clean first or repaired draft shows no note. With a source the unsupported sentences are cut after the repair, so expect the cut text (or the gap line "Not in the source.") rather than a grounding note. The saved artifact's `meta.checks` records a repair that fixed the draft (`GET /api/v1/artifacts`, then the artifact). The same response carries the first draft, with its note, when the repair call fails. You cannot command that either; `packages/host/src/document-generate.test.ts` pins the branch.
- **Locale (id).** With the desk on `id` (see [locale.md](./locale.md)), this view reads `Dokumen` and `Mulai dari templat`. `Belum ada dokumen` (`documents.emptyTitle`) and `emptyHint` are in the catalog but no component reads them, so neither is ever on the page. Testids are locale-invariant.
- **Cloud.** `foundation.spec.ts` covers starter + regen 503 on Default (no Studio unlock).

## Gotchas

- Default desk unlocks Documents. A Legal desk also has it. Do not open Studio to unlock the tab.
- Regen opens a panel; it does not POST until `documents-regen-submit`. On a stub desk that is HTTP 503, not a silent no-op; on a keyed desk it is a live paid call.
- Do not POST `/api/v1/documents` as a substitute for the prompt bar on a live proof.
- A hidden studio stays mounted, SKILL.md "Harness-wide gotchas" G3; here it means `documents-studio` still has count 1 on `/chat` and `documents-prompt` keeps its typed value.
- A failed generate wipes the preview. The `catch` of `onGenerate` (`apps/web/components/documents-studio.tsx:101`, catch at `:127-130`) does `setDraft(null)` and `setChecks(null)` before it sets the error; the `catch` of `onRegenerate` (`:136`, catch at `:165-167`) does not. Load a starter, then press Generate without a key, and the starter is gone.
- `desk-sources` has count 0 on a desk with no files, so a missing picker on a fresh throwaway desk is not a failure. The desk re-read is throttled to once per 4 s (`REFRESH_MIN_MS`, `apps/web/components/desk-source-picker.tsx:18`): a file saved right after the pane mounted will not show until a later focus.
- The `desk-sources*` testids are shared with Presentation, and both panes stay mounted once visited. A bare `desk-sources` locator can match two elements, so scope it to `documents-studio`.
- The picker sends paths, not text. Whether a path is a valid desk path, readable text and under the ceiling is decided on the host when the request arrives, so on stub the only visible outcome is the 503 and the request body.
- `documents-studio-model` is a real `<select>` carrying the chat catalogue (every mode in `CHAT_CATALOG_MODES` offers the same list, `packages/core/src/models/mode-catalog.ts:22`; the host sends it once, `packages/host/src/selectable-models.ts:245-250`). It does **not** write the desk's `documentGenModel`: `useJobModel` reads `GET /api/v1/models` and `GET /api/v1/settings` and uses that field only to seed the pick (`SETTINGS_KEY`, `apps/web/lib/use-job-model.ts:20-29`), so selecting an option fires no POST (driven 2026-10-01: 0 requests) and the pick rides in the run body as `model` and `modelPinned`. Finance, Market, Legal and Meeting read the same saved field but never see a pick made here.
- Documents runs on the same default job model as Finance (`hy3` since 2026-09-30, then `deepseek-v4-1-flash`, then `deepseek-v4-flash`). The DeepSeek stand-ins think silently before they write, and `hy3` thinks a little (13 to 24 reasoning tokens on a one-word prompt) and has the ordinary watchdog limits, not the reasoning ones: the drafting phase can sit still for a minute or two with no events. That is the model, not a stall, the watchdog now allows 240 s to the first token and 180 s idle for the always-thinking gateway families. A repair round is a second call, so a draft that needed one takes about twice as long. If that second call fails, the first draft is kept and shown with its note. The Finance recipe carries the same long-silence note.
- Cancel now reaches the model call (the request's abort signal goes to the runtime), and a cancelled generate saves nothing. It is not driven here: the Documents UI has no cancel control, so a cancel is a closed tab or an aborted fetch.
- Smaller facts a driver trips on: `documents-starter` has count 0 while any draft is on screen (`documents-studio.tsx:326`), so loading both starters needs a reload between them; Enter in `documents-prompt` submits the form and plain Enter in `documents-regen-prompt` submits the regen, both paid on a keyed desk; `documents-enhance` is disabled with an empty prompt, on a stub desk it rewrites to "<text without the final period>. Name the audience, the sections you need, and the decision the draft should support." and the testid becomes `documents-enhance-revert` (a paid chat call on a keyed desk; `documents-enhance-error` is an sr-only alert); `documents-source-clear` exists only while the box has text, `documents-source-title` only after an artifact pick or a handoff (typing clears it), and the counter reads "x / 120,000 characters" with no testid; the download name on an `en` desk is `Saturday-pickup-week-ending-6-Sep.docx` (`safeFilename` strips the em dash); the starters' `data-path` is on the checkbox input, not the list row, and a file seeded before the pane's first mount shows at once while a later one needs up to 4 s (`desk-source-picker.tsx:18`); `documents-check` on a desk file that vanished answers 400 `source_file_not_found` into `documents-error`, even on a stub desk.
- **Driven 2026-10-05 on `:3000` (keyed; maintain3), no generate, no regen submit, no enhance.** 2 `documents-starter`, then a starter gave a preview with 5 or 6 `documents-section` and as many `documents-regen`, `documents-starter` back to 0; `documents-download` produced `Saturday-pickup-week-ending-6-Sep.docx` from `POST /api/v1/documents/docx` (no model); the check with an empty source gave `documents-source-check` plus `-empty`, with a pasted sentence it classified (1 supported, 19 unsupported); `documents-regen` opened its panel (`-prompt`, `-model`, `-attach`, `-file`); after `POST /api/v1/files` seeded `verify/m3-plan.md`, `desk-sources` appeared with the hint "Up to 5 files" and a ticked `desk-sources-option` gave one `desk-sources-chip`; `documents-source-picker-toggle` opened its panel; a fulfilled fake of `POST /api/v1/documents` rendered `documents-checks-note[data-kind="grounding"]` naming section "Alpha". The seeded file was deleted.
