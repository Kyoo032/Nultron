# Desktop brands

Public git and GitHub releases were **Nultron** (Toko Token) until the Personal app was retired on 2026-10-14. Its release repo `Kyoo032/Nultron-Desktop` is archived. Two local Windows flavors exist on the operator machine only: **Kemenkeu AI** and **AIHub Metranet**. Flavor folders under `apps/desktop/branding/kemenkeu/` and `apps/desktop/branding/metranet/` are gitignored. Do not upload those two installers. The splash, exe, and Start menu can show the flavor while Chat still says Nultron if the renderer never received `brand.json`. Packaged chrome must come from preload (`window.agentforge.brand` + `brandLogo`), not a host ping that can fire before IPC is ready or fail closed to Nultron. Map: [`docs/internal/maps/desktop-pack-routes.md`](../../../../docs/internal/maps/desktop-pack-routes.md).

## Sub-features

- `desktop-brand-agentforge` is the public product: rail `product-brand` is Nultron, Settings gateway is Toko Token, splash/exe match. Webdev on :3000 is always this flavor unless brand env is injected for a proof.
- `desktop-brand-kemenkeu` is the local NSIS `Kemenkeu AI Setup *.exe`. Rail `product-brand` is **Kemenkeu AI**, `product-logo` is the Kemenkeu mark, Settings/onboarding say **AIHub**, and its `brand.json` `gatewayBaseUrl` is `https://aihub.metranet.co.id/v1` (whether an installed flavor uses it is `desktop-brand-gateway` below). userData is `%APPDATA%\Kemenkeu AI`.
- `desktop-brand-metranet` is the local NSIS `AIHub Metranet Setup *.exe`. Rail is **AIHub Metranet** plus the Metranet mark. Same `gatewayBaseUrl` in its `brand.json`. userData is `%APPDATA%\AIHub Metranet`.
- `desktop-brand-preload` exposes `window.agentforge.brand` and a `data:image/png` `brandLogo` from `resources/brand` before React paints. Ping may confirm; it must not replace a flavor name with Nultron. For the public flavor the rail does not draw that data URL: `usesBundledMark` (`apps/web/lib/product-brand.tsx`) sends it to `BrandMark`, the size-tuned Nultron mark bundled with the renderer (in the **collapsed** rail `product-logo` is the `<img srcset=… 1x, … 2x>` itself at 24 px, `workspace-switcher.tsx:169`; in the expanded rail it is a 28 x 28 `span` and the 24 x 24 `BrandMark` img inside it has no testid, `app-rail.tsx:168-174`). Only a flavor with its own name and logo draws `brandLogo`.
- `desktop-brand-logo` (2026-09-29) is the Nultron logo, the painted head in a blue rounded-square tile, in every file the app ships: `favicon.ico` + `favicon-32.png` + `favicon-180.png` (apple-touch) under `apps/web/public/brand/`, the rail mark `apps/web/components/brand-art/mark-{24,32,48,64}.png`, the display logo `logo.png` (256 px, one identical file in `apps/web/public/brand`, `apps/portal/assets`, `apps/desktop/{branding/agentforge,resources/brand,splash}`), `icon.ico` (16 to 256) in `branding/agentforge`, `build` and `splash`, `icon.icns` (`build.mac.icon`) in `branding/agentforge` and `build`, and the 1024 px sources `icon.png` (branding and build) and `mark.png`. The files come from Rizky's app-logo image through `apps/desktop/scripts/brand-icons.mjs` (the master is `apps/desktop/branding/agentforge/source/app-logo.webp`; `--out <dir> --check` compares every regenerated file with the repo's). Checks: `apps/web/lib/brand-assets.test.tsx` and `apps/desktop/brand-assets.test.cjs`.
- `desktop-brand-wordmark` (2026-10-01) only the public name draws a wordmark in the Nultron colours, the helmet's blue running into the gem's cyan. In the expanded rail `product-brand` carries the class `wordmark-nultron` and `data-wordmark="nultron"` (`apps/web/components/app-rail.tsx:263-267`). `usesNultronWordmark` decides, and it is `productName === DEFAULT_PRODUCT_NAME` (`apps/web/lib/product-brand.tsx:49-51`); the rule is `.wordmark-nultron` (`apps/web/app/globals.css:2292-2301`, with a forced-colors override at `:2303-2309`), with `#5fb0f1` to `#44e3eb` on the dark desk and `#116eb8` to `#107589` on the light one (`:426-427`, `:196-197`). The splash draws `<h1 class="wordmark">Nultron</h1>` with the dark-desk stops (`apps/desktop/splash/index.html:36-44`, `:55`), which `pack-brand.mjs` generates for the public name only (`NULTRON_WORDMARK_CSS`, `apps/desktop/scripts/pack-brand.mjs:54-66`, interpolated at `:109`, the `h1` at `:119`). A flavor and a hosted tenant that renamed the product stay plain: no class, no `data-wordmark`. `apps/desktop/brand-assets.test.cjs:123-150` pins the splash and the generator to the dark-desk `--nultron-blue-text` and `--nultron-cyan-text` values in `globals.css`.
- `desktop-brand-pack` is **Nultron first**, then the two local flavors. Same host/renderer; Kemenkeu / Metranet are chrome + `brand.json` only. Pack public with `pnpm desktop:build` (or `AGENTFORGE_BRAND=agentforge node apps/desktop/scripts/pack-brand.mjs` after stage). Prove that exe before `AGENTFORGE_BRAND=kemenkeu|metranet … pack-brand.mjs` or `pnpm desktop:build:all`. After a flavor pack the working tree restores to `branding/agentforge` (`--restore-public`). Missing flavor `icon.ico` / `logo.png` (gitignored) must be rebuilt from `branding/_raw/` before pack — do not invent logos.
- `desktop-brand-updates` — `brand.json` `updates` (`github`, `Kyoo032/Nultron-Desktop` since 2026-10-14, archived; `apps/desktop/branding/agentforge/brand.json:9-12`) is used for the public build only (`pack-brand.mjs:234-235`). A flavor is packed with a disabled generic feed, `https://localhost/disabled-updates` (`pack-brand.mjs:236-237`). `apps/desktop/preload.cjs:12` reports `updates.supported` only when the product name is the public one, the main process enables updates only for that name (`apps/desktop/auto-update.cjs:53-54`), and the renderer draws no updates control for any other name (`apps/web/lib/use-app-updates.ts:43`, `apps/web/components/app-updates.tsx:112-114`). That is why `app-updates` has count 0 on a flavor.
- `desktop-brand-gateway` — a packaged build ignores the dev hook `AGENTFORGE_GATEWAY_URL` whatever the environment holds: `bootstrapPackaged` sets `AGENTFORGE_PACKAGED=1`, deletes any inherited `AGENTFORGE_GATEWAY_URL`, and sets `AGENTFORGE_BRAND_GATEWAY_URL` from `brandGatewayOverride(brand)` before `host.cjs` loads (`apps/desktop/main.cjs:666-680`, `apps/desktop/brand-read.cjs:39-45`). The public Nultron build never gets a brand gateway; a flavor gets its `brand.json` `gatewayBaseUrl` unless it equals the pinned one. The host reads only that variable when packaged, and only an https URL with no credentials (`gatewayUrlOverride`, `packages/core/src/gateway/pinned.ts:72-81`; `resolvedGatewayBaseUrl`, `packages/core/src/gateway.ts:37-39`). Proven in a plain-Node host bundle on 2026-10-01 (SR-85), not on an installed app: the flavor gateway stays unproven until someone reads it from an installed Kemenkeu AI or AIHub Metranet window, and a public build should show the pinned gateway. `AGENTFORGE_PACKAGED=1` also makes the host ignore the Telegram API dev hook `AGENTFORGE_TELEGRAM_API_URL` (`resolvedTelegramApiOrigin`, `packages/core/src/channels/pinned.ts:31`, the same `gatewayUrlOverrideAllowed()` gate); `apps/desktop/packaged-env.test.cjs` holds the bootstrap that sets the marker, and `packages/core/src/gateway/pinned.test.ts:224-229` holds the Telegram rule.

## How to get to it (user POV)

- **Public / webdev:** Start menu Nultron, or `pnpm dev` at `http://127.0.0.1:3000`. Rail says Nultron.
- **Kemenkeu AI:** install the local Kemenkeu NSIS exe (not GitHub). Start menu → Kemenkeu AI.
- **AIHub Metranet:** install the local Metranet NSIS exe. Start menu → AIHub Metranet.
- Rebuild flavors only on Windows. Cloud must not `pnpm desktop:build`.

- Packaged proof is the **installed flavor window**, not Chrome on :3000.

- **Public webdev.** Doctor with no args. Rail `product-brand` is Nultron and `product-logo` has count 1. Settings privacy/onboarding copy names Toko Token. Starting webdev with `AGENTFORGE_PRODUCT_NAME` changes the name but `product-logo` keeps drawing the bundled mark (`usesBundledMark`, `apps/web/lib/product-brand.tsx:38-40`), so that run is not flavor proof.
- **Kemenkeu packaged.** Launch Kemenkeu AI. Splash name + logo match. After Chat or onboarding, rail `product-brand` is `Kemenkeu AI` and `product-logo` is visible. - **Metranet packaged.** Same for `AIHub Metranet`.

To prove the restore without touching the tree, copy `scripts/`, `branding/`, `build/`, `splash/`, `resources/brand/` and `package.json` into a scratch `apps/desktop/`, delete or corrupt the build and splash files there, run `--restore-public` in the copy and `cmp` each file against the real one (2026-09-29: `build/icon.{ico,icns,png}`, `splash/icon.ico`, `splash/logo.png`, `resources/brand/{logo.png,brand.json}` byte-identical, `splash/index.html` equal apart from CRLF, a stale `splash/logo.svg` removed). ## Gotchas

- Splash/exe/appId can be flavor while the renderer still says Nultron if you packed without rebuilding `apps/web` (a flavor packed without `logo.png` shows its own name with a monogram tile, "KA" / "AM", `app-rail.tsx:186`, `app-shell.tsx:17-27`; `pack-brand.mjs:170-174` refuses to pack with no logo; `Nultron` in the renderer means `brand.json` is missing or unreadable or the web bundle is stale). Rebuild web + `stage-renderer.mjs` + `pack-brand.mjs`.
- `pnpm desktop:dev` does not attach preload. That window follows webdev ping (Nultron / Toko Token). Not flavor proof.
- Checking out `main` deletes gitignored flavor `icon.ico` / `logo.png` (folders keep `brand.json` only). Official sources (do not invent marks): Kemenkeu Wikimedia [seal SVG](https://upload.wikimedia.org/wikipedia/commons/5/56/Seal_of_the_Ministry_of_Finance_of_the_Republic_of_Indonesia.svg) + [logo PNG](https://upload.wikimedia.org/wikipedia/commons/7/73/Logo_kementerian_keuangan_republik_indonesia.png); Metranet Brandfetch [logo SVG](https://cdn.brandfetch.io/ida6apCf2g/theme/light/logo.svg?c=1bxid64Mup7aczewSAYMX) + [icon JPEG](https://cdn.brandfetch.io/ida6apCf2g/w/400/h/400/theme/dark/icon.jpeg?c=1bxid64Mup7aczewSAYMX). Rebuild into `branding/_raw/` then ImageMagick (`C:\Program Files\ImageMagick-7.1.2-Q16-HDRI\magick.exe` on this desk): Kemenkeu PNG → `logo.png` + `icon.ico`; Metranet JPEG → splash `logo.png` + `icon.ico` (the Brandfetch light SVG can embed a mismatched raster — do not use it for chrome). Brandfetch CDN can 200 an HTML docs page if curl omits `Accept: image/*`.
- Wrap key service name is the product name (`Kemenkeu AI` / `AIHub Metranet` / `Nultron`) plus account `wrap-key`. Uninstall of one flavor does not wipe another flavor’s `%APPDATA%`, but `killRunningApp` force-kills all three flavor exes on any install or uninstall (`build/installer.nsh:6-15`), so a side-by-side proof loses the other window, and a real uninstall also removes `%APPDATA%\DPSBuddy`, `Agentforge` and `@agentforge` (`:34-41`).
- The public desktop release repo `Kyoo032/Nultron-Desktop` is archived (2026-10-14) and gets no new releases. Do not treat a flavor exe on disk as a GitHub artifact.
- **The doctor's `gatewayBaseUrl` is not the effective gateway.** `doctor.mjs --desktop` copies `gatewayBaseUrl` from `host-status.json` (`main.cjs:314`, the `brand.json` value). `GET /api/v1/ping` answers `resolvedGatewayBaseUrl()` (`packages/host/src/handlers/misc.ts:105-107`), so ping read through the bridge in an installed flavor window is the only proof of the gateway that flavor really uses.
- `applyDeskShell` writes `<html data-shell>` on every shell: `desktop` when `isElectron()`, `browser` otherwise (`lib/shell-motion.ts:22-27`, `main.tsx:25`), so `document.documentElement.dataset.shell === "desktop"` is a cheap proof that the preload attached. `document.title` equals the product name (and the Electron window title follows it); `index.html` ships `<title>Nultron</title>`. A flavor's `product-logo` is `span.icon-orb` around `img[alt=<name>]` with a `data:image/png;base64,` src (16 px expanded, 20 px collapsed). `app-updates` is count 0 on webdev too (`&& isElectron()`, `use-app-updates.ts:43`). `AGENTFORGE_PRODUCT_NAME` / `AGENTFORGE_GATEWAY_NAME` (`main.cjs:84-85`) also reach the host: ping, the docx/pptx author and the Knowledge soul prompt.
- **Driven 2026-10-05 (maintain3), lane A only, on `:3000`.** `product-brand` "Nultron" with `data-wordmark="nultron"` and `linear-gradient(100deg, rgb(17, 110, 184) 0%, rgb(17, 110, 184) 38%, rgb(16, 117, 137) 100%)` on the light desk; `product-logo` a 28 x 28 span around a 24 x 24 `mark-24.png`; `document.title` "Nultron"; every favicon link answered 200 `image/*`; Settings heading "Toko Token gateway"; `app-updates` count 0; `node apps/desktop/brand-assets.test.cjs` exit 0. Lane B (an installed flavor, its effective gateway, the installer) is unreachable: there is no Nultron pack and no flavor install on this desk (`dist` holds only `DPSBuddy Setup 0.15.1.exe`; `%APPDATA%\Nultron`, `Kemenkeu AI` and `AIHub Metranet` do not exist).
- **Lane A driven 2026-10-09 on a throwaway stub instance:** `node apps/desktop/brand-assets.test.cjs` printed ok (exit 0); `/chat` had `product-brand` with `data-wordmark="nultron"`, the `product-logo` image 24 x 24, `document.title` "Nultron", and both favicon links (`/brand/favicon.ico`, `/brand/favicon-32.png`) answered 200. **Lane B (the installed Kemenkeu AI / AIHub Metranet flavors) is verified-unreachable here:** no flavor is installed on this machine and `pnpm desktop:build` is a Windows pack, not a drive.

**Chat-first reading guide (2026-10-12).** The rail is `AgentRail`, so read the old handles below as follows: `product-brand` (name) is the `mode-chat` `aria-label` / `title`, `agent-name` in a thread header, and `document.title`; `product-logo` is `img.agent-rail-mark` (32x32, `mark-32`) inside `mode-chat` on the public build, `img.agent-rail-logo` for a flavor with a logo, and `span.agent-rail-monogram` for a flavor without one. `data-wordmark` and the `wordmark-nultron` class exist only in the `"modes"` fallback (`app-rail.tsx`). The Chat hero greeting follows the brand name (`chat-hero.tsx:40-41`), so "hard-coded Nultron" no longer holds there. Lane A is not re-driven on chat-first beyond `mode-chat` `aria-label` `Nultron`.
