# Virtual agents

Since PR #157 (2026-10-12) the product is one chat screen and the left rail lists **virtual agents**: one per product-mode harness, each with its own conversations. Since the owner's word on 2026-10-09 (his third instruction, quoted in the map) every agent is a full chat: the same composer, model choice, tools and budget, under its own name and specialty, so an Images agent can build a deck and any agent can run Research. The default agent (first in the rail) is the brand's character, set by `AGENTFORGE_ASSISTANT_NAME` and the product's name when that is unset. Research and the default agent run their own harness in chat; the other twelve keep their checked run in a studio screen and say so on their empty conversation. The Workspaces page is replaced by a Virtual agents page where a person hires or lets go of agents. How it works, with `file:line` citations: [`docs/internal/maps/virtual-agents.md`](../../../../docs/internal/maps/virtual-agents.md). **First driven 2026-10-09 on the tester webdev, re-driven on `:3000` on 2026-10-12** with the owner's key (evidence: `evidence/virtual-agents/2026-10-12-maintain/` and `evidence/chat/2026-10-12-maintain/`, gitignored beyond their README). Driven on `:3000`: the rail, the harness panel (18 tools, 12 steps, 40 tool calls), `agent-open-studio` for all twelve studio agents, the history popover and thread delete, `new-chat-link`, hire and let go (Music, restored), the PATCH 500 copy, widths 1280 to 320. **Not driven:** Indonesian, a paid picture or video from an agent's chat, an attached picture in a mode agent's chat, a mode agent using the Knowledge Base or an earlier chat, a run longer than the client's cap, a stopped run, a worker past its 8 minute ceiling, the foreign-thread redirect, the keyboard and accessibility checks beyond Escape, a stub turn, the packaged app, hosted mode, and a brand that sets `AGENTFORGE_ASSISTANT_NAME`. Each step below says which of the two it is. Walked again on 2026-10-16 on a throwaway stub webdev desk: PASS for the rail, the desk's 13 agent tiles and the Virtual agents page with every agent on the desk (`agents-none-available`). Evidence: `evidence/virtual-agents/2026-10-16-maint/`. The rail was restyled on 2026-10-20 (names by default, plain icons, a collapse toggle, and a menu bar under 768 px). It was driven on the tester webdev `:3200` at 1440, 1280, 768, 767, 600 and 390 px, light and dark, on every rail page, plus the guide's stops at 1440 and all five at 390. ## Sub-features

- `agents-rail` is `agent-rail`. From 768 px up it prints every name beside a small plain icon (`data-rail="full"`, 216 px); `rail-collapse` in `rail-footer` shrinks it to an icon strip (`data-rail="min"`, 56 px) and `rail-expand` brings the names back. The choice is kept in localStorage under `agentforge-agent-rail`, and a stored choice beats the default. Under 768 px it is a bar across the top of every page (`agent-rail` has `data-menu`; `rail-bar-name` reads the open agent, such as `Images`, or the page, such as `Settings`, else the product's name): `rail-menu` is the one control that opens the named list as a drawer over the page, with `rail-scrim` behind it, and `rail-collapse`, the backdrop and Escape close it. `rail-expand` is never drawn under 768 px. The default agent is `mode-chat`; every other agent is `agent-<mode>` (`agent-research`, `agent-images`, and so on) with `data-mode`, `data-conversation` (`harness` or `studio`, meaning where the agent's own harness runs) and `aria-current="page"` on the open one. Under a divider come `rail-account-group` with `mode-knowledge`, `channels-link`, `workspaces-link`, `usage-link` and `settings-link`. The footer `rail-footer` holds `theme-toggle`, the updates button where it exists and, as the character, `desk-buddy-chip` (a small head). While nothing is cached the rail draws three `agent-rail-skeleton` blocks, still, not pulsing. There is no desk switcher, no `rail-resize`, no `product-brand` and no session list in this rail.
- `agents-catalog` is `GET /api/v1/virtual-agents`: `{ agents, available }`. `agents` is the default agent plus the desk's modes in catalog order, each with an `agentId` (every agent on the desk has a row), and `available` is every other agent with `agentId: null`. Every agent lists the same 18 `tools`. No row has a `prompt` key. A fresh desk (since 2026-10-21, hosted or not) has Chat alone.
- `agents-ping` is `GET /api/v1/ping`, which carries `assistantName` beside `productName`. With no separate character set, the two are equal.
- `agents-pane` is `agent-chat-pane` (with `data-agent`), at `/chat` for the default agent and `/chat?agent=<mode>` for the others. **Every agent renders `chat-home`** (with `data-agent`, and `data-mode` on a non-default agent). There is no `agent-studio` test id and no studio-only pane. The header is `chat-header` with `agent-name`, the `tier-picker` (the model choice), `chat-header-controls` (the account chip, plus `chat-context` only once the chat has used 80% of its window; hidden under 52rem of header width) and three controls. `chat-context` and `chat-usage` live in the "Context and usage" section at the top of `agent-harness-panel` (`agent-harness-this-chat`) once the thread has a reply; there the breakdown unfolds in place (`role="group"`).
- `agents-home` is `agent-home`, the empty conversation of a non-default agent: greeting, tagline, the skill chips `agent-home-skills`, and on every agent the line `agent-home-everything` ("Ask me anything. I can also write, research, work with your files, and make pictures, clips and decks."). The badge `agent-home-badge` ("Runs on its own harness") is drawn only on a `harness` agent (Research and Finance). On a `studio` agent the home also holds `agent-home-studio` with the button `agent-open-studio`, and only while the conversation is empty. The default agent's empty conversation is the greeting `chat-empty` (`ChatGreeting`, since 2026-10-21): `chat-greeting-hello` reads "Hi, I'm {name}." with the default agent's name, an `h1` reads "What are we working on today?", then `chat-key-status`. The composer sits in the middle of the pane with `chat-suggestions` under it until the first send. There is no `chat-hero` ([chat.md](./chat.md), `chat-greeting`).
- `agents-harness-panel` is `agent-harness-panel`, opened by `agent-harness-toggle` (`aria-pressed`) and closed by `agent-harness-close` or Escape. It has two parts. `agent-harness-in-chat` ("In this chat") holds `agent-harness-tools` and `agent-harness-limits`, the same for every agent (19 tools, 12 model steps and 40 tool calls a turn), and `agent-harness-enforced`. `agent-harness-own` ("The {name} harness", with `data-runs` of `chat` or `studio`) holds `agent-harness-where`, `agent-harness-loop`, `agent-harness-skills` and `agent-harness-checks`. Because every agent binds tools, `agent-harness-no-tools` never draws. The panel says what the agent is made of and changes nothing.
- `agents-history` is `agent-history-toggle`, which opens `agent-history` (a dialog). It lists this agent's conversations as `thread-item` rows with `thread-delete`, `threads-see-all` after eight, and `agent-history-empty` when there are none. `rail-thread-list` is the list's testid and exists only while the popover is open. `new-chat-link` (an icon in the header) goes to the agent's blank conversation.
- `agents-composer` is the bare composer: `composer-plus` (opens `composer-plus-menu`, which holds `composer-attach` and the Enhance row `composer-enhance`), `composer-text` and `composer-send`. `composer-send` is an icon button with no text; its name is its `aria-label`, `Send` (`Kirim`), or `Sending` (`Mengirim`) while a turn runs. There is no tier picker inside `composer`; the placeholder reads `Message <name>`.
- `agents-character` is where the character stands. In this shell it is the head `desk-buddy-chip` in `rail-footer`, and nowhere else (since 2026-10-21 the default agent's empty chat has no hero either): `buddy-stage-composer` has count 0, `message-list` has no `chat-thread-ledge` class, and its end padding is an ordinary gap. Reason, the owner, 2026-10-09: "careful, to not let the IP overlap with the generated content".
- `agents-everything` is any agent doing a job outside its specialty in its own chat: a deck card (`chat-deck-card`, with `chat-deck-open` and `chat-deck-download`) from an Images agent, a dossier card (`chat-dossier-card`) from the default agent.
- `agents-identity` is what an agent says when asked who it is: a mode agent names its own mode and says it can also do the rest; the default agent names the brand's character.
- `agents-research-run` is a turn that calls `research_dossier`, from the Research agent or any other. While it runs, a `message-tool-progress` line shows inside `message-thinking`. After it, `chat-dossier-cards` holds a `chat-dossier-card`. Needs a live key.
- `agents-finance-run` is a turn that calls `finance_task`. The Finance agent's conversation is a harness conversation now. After a workbook is attached and a question asked, `chat-finance-card` shows under the answer, and there is no studio note and no Open studio button on its home or in its harness panel. See [finance.md](./finance.md), the "Finance in Chat" items. Needs a live key.
- `agents-dossier-card` is `chat-dossier-card` with `chat-dossier-title`, `chat-dossier-meta` (sources and sections), `chat-dossier-checks` (`data-failed="true"` when a check failed), `chat-dossier-outline` (first four headings), and `chat-dossier-open`, which shows `chat-dossier-view` with `chat-dossier-text` in place. The opened text starts at the dossier's title: the saved file's front-matter block is removed (`dossierBodyForView`). `chat-dossier-not-saved` replaces Open when the dossier could not be saved.
- `agents-page` is `virtual-agents-page` at `/workspaces`: `agents-on-desk` and `agents-available` sections of `agent-card` rows (`data-agent`, `data-conversation`), each with `agent-kind` (the pill reads "Own harness in chat" or "Own harness in studio") and one of `agent-open`, `agent-hire`, `agent-let-go` or, for the default agent, `agent-always`. `agent-open` is a link to that agent's chat on every desk agent, and its word is `agents.page.open` (Open, `Buka`). `agents-none-available` shows when every agent is on the desk; `virtual-agents-error` shows a failed load or save.

## How to get to it (user POV)

- Open `http://127.0.0.1:3000/chat`.
- The left column is the rail, with each agent's name. Click Research to talk to it. Click the clock icon in the header for past conversations, the pencil for a new one, and the panel icon for how the agent works.
- Click the `+` in the message bar for Add files and Enhance prompt. The model choice (Daily, Fastest, Reasoning) is the chip beside the agent's name.
- Ask any agent for anything. Images can write a deck; the first agent can run Research.
- Click Virtual agents under the divider to hire or let go of agents.

## Gotchas

- Ids moved. `new-chat-link`, `thread-item`, `thread-delete` and `threads-see-all` are in the agent header and the `agent-history` popover now, and `rail-thread-list` exists only while the popover is open. A locator that waits for them in the rail times out. [`model-tiers.md`](./model-tiers.md) and [`chat.md`](./chat.md) describe the forms.
- `composer-attach` is inside `composer-plus-menu`, which is hidden until `composer-plus` is clicked. `composer-file` (the hidden input) is still in the composer.
- `composer-send` has no text. A locator or assertion on its text `Send` fails; read its accessible name or its `aria-label`.
- `workspaces-link` goes to `/workspaces`, but the page is `virtual-agents-page`, not the Workspaces page. `workspaces-page` and its desk testids do not exist here, and neither does `create-new-workspace`: this page cannot create a desk.
