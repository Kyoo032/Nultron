# Finance

Finance is prompt-first. `/finance` with no task is `finance-auto`: a prompt box and a drop zone, where a file is read for free (`POST /api/v1/finance/import`, then `POST /api/v1/finance/auto`, code only, no gateway gate), the page shows which task the numbers fit and a preview, and the one paid step is `finance-auto-write` ("write it up", `POST /api/v1/finance/stream`). The five task cards sit inside a closed `finance-more` disclosure; a card or `finance-auto-check-rows` open `/finance?task=<id>`, which is the older numbers → result → export page. Each task keeps its own inputs and its own result, and one export in Excel, PowerPoint or Word. It is not a spreadsheet. There are no starter cards and no canned preview: every written result comes from a live generate, so the result-and-download surface needs a working gateway key. The host never invents figures. How it works underneath: [`docs/internal/maps/finance-parse-and-generate.md`](../../../../docs/internal/maps/finance-parse-and-generate.md), and the task catalog in [`docs/internal/maps/finance-tasks.md`](../../../../docs/internal/maps/finance-tasks.md).

Product: both · Instance: main :3000

## How to get to it (user POV)

- Choose the Finance agent on the left rail (`agent-finance`), then `agent-open-studio`. A fresh first-run desk does not have the tile: hire it from Virtual agents.
- Open `http://127.0.0.1:3000/finance` when the tab is unlocked. That is the prompt-first page. Drop a file, or open **More** and pick a task card.
- Legal / Marketing / Students presets (and Office, Sales and Product, `templates/library.ts:693-723`) do not add this tab unless the owner checks it.

## Driving it with the Nultron harness

Preconditions:

- Doctor exits 0.
- `agent-finance` is visible on Default. If count is 0, you are on a desk that hid Finance — switch to Default or add the tab in Workspaces.
- Keyless proof stops at the chooser, the task walk, a keyless read that the task allows, the upload and the generate refusal. There is no keyless route to a written result or a download. Live generate only if the operator asked and doctor reports `runtime: "ai"` and `hasOpenai: true`.
- The refusal steps below (Read the brief without a key, Generate without a key, the typed-instruction read, and the brief's catalog sample) hold only on a keyless or stub desk. On a keyed desk (the operator's `:3000`) each of those presses is a PAID live call: `finance-parse` on the brief is a labels-only model call and `finance-generate` is a full run. The cash flow, budget and appraisal reads and the ratios read of a dictionary label call no model on either kind of desk, so those are the steps to drive on a keyed desk.

- **Open Finance.** Click `agent-finance`, then `agent-open-studio` (or go to `/finance`). ## Gotchas

- An existing Default desk unlocks Finance; a fresh non-hosted first desk does not. Seeded Legal / Marketing / Students desks do not.
- **Known issue, now fixed on the hosted build only: a closed gate gave the code-only parses a vague error (driven 2026-10-05).** `financeFailure` (`finance-client.ts:106-116`) now maps a hosted 403 to the needs-key sentence, shown in `finance-needs-key`, `budget-needs-key` and `finance-ratios-needs-key` (`hostedGatewayBlocked` returns null off the hosted build, `gateway-blocked.ts:19`). On webdev and non-hosted builds the generic text below still shows, which is what the drive saw. With the host gate closed (`status: "unreachable"`, `allowed: false`) and the renderer's settings read faked open so the page would render, a sample sentence on each task answered `POST /api/v1/finance/parse` 403 `gateway_blocked`. The page showed only the generic `finance-error` "Could not read those figures" for cash flow and appraisal, and "Could not read that statement" in `finance-ratios-error` for ratios. Budget showed nothing in `finance-error` (null). None of them says the key or Settings is the problem, even though the task never needed a model. It matters for the hosted "Add it later" choice, where the renderer opens the desk on a session while the host gate stays closed until a key is saved. On a non-hosted desk a closed gate sends the renderer to onboarding before any of this shows, which is why the drive had to fake the settings read. A drive on a closed gate should expect 403 here, not a successful read; the same sentences read fine with the gate open (`allowed: true`, driven the same day: cash flow, budget, appraisal and ratios all 200 with the generate step offered). Evidence: `evidence/finance/2026-10-05-maintain-closed-gate/action.md`. Log it in `docs/internal/unreleased.md` as a finding; the skill does not fix it. Update 2026-10-11 (SH-006, code-read and unit-tested, not driven): once the renderer knows the gate is closed, every task's read is disabled and the needs-key note sits above the inputs, so no read is sent.
