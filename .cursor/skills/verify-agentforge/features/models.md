# Models

Chat does not offer a model list. It offers three tiers through `tier-picker` in `chat-header` ([model-tiers.md](./model-tiers.md)), and the host maps the tier to a model. The per-model Chat picker (`ModelPicker`, `apps/web/components/model-picker.tsx:103`) and the Thinking level control are still in the tree, but no screen renders them in either shell layout: `model-picker`, `model-picker-panel`, `model-group-recommended`, `model-best-for`, `model-thinking-badge`, `reasoning-effort` and `composer-toolbar` all count 0 (driven 2026-10-16). What this recipe still covers: the catalogue at `GET /api/v1/models` with its curation, the `*-studio-model` selects in the job studios, the job model fallback, the Thinking self-heal and the dev-only policy tools. Maps: [`docs/internal/maps/chat-send.md`](../../../../docs/internal/maps/chat-send.md) for the send path and [`docs/internal/maps/model-policy.md`](../../../../docs/internal/maps/model-policy.md) for how each model is called and what happens when a call is refused.

Product: both · Instance: main :3000

## Sub-features

- `models-doctor` prints `modeKeys`, `chatCount` and `curation` from webdev doctor (`.cursor/skills/verify-agentforge/scripts/doctor.mjs:283-285`). `curation: true` is expected whenever `chatCount` is above 0. A keyless stub desk can still report a catalogue (47 chat models and `curation: true` on 2026-10-16); an empty catalogue there is not a regression. The retired desktop's `--desktop` doctor could not GET models over HTTP, so `curation: false` was its limit (history).
- `models-catalogue` is `GET /api/v1/models`. It answers `models`, `defaultModel`, `modes`, `defaults`, `tiers` (three entries) and `defaultTier`. `modes` carries only the lists that differ from the chat catalogue (`image`, `video`, `audio`, `other`, `music`, `embedding`), so it has no `chat` key. Models carry `friendlyLabel`, `bestFor` and `tier` (`"everyday"` | `"advanced"`). Driven 2026-10-16 on a stub desk.
- `models-recommended` is the curated order. `recommendedChatModels` (`packages/core/src/models/preferred.ts:330-363`) puts a gateway alias `default` first when it is listed, then the everyday ids in this order when the catalogue lists them: GPT 6 Luna, Claude Sonnet 5.5, DeepSeek V4.1 Flash, Gemini 3.5 Flash, GPT 6 Sol, GLM 5.3 Flash, Qwen3.7 Plus (`EVERYDAY_MODEL_IDS`, `packages/core/src/models/gateway-roles.ts:191`). The Chat default is the first live id of `CHAT_DEFAULT_PREFERENCES` (`preferred.ts:15`). In the shipping UI the order shows only as the **Recommended** optgroup of the studio selects; the old picker's group and hints are proven by unit tests only (`model-picker.test.tsx`, `composer-layout.test.tsx`).
- `models-studio-select` is `ModelSelect` (`apps/web/components/model-select.tsx:41`), a native `<select>` with `<optgroup label=…>` groups: Recommended, then brand groups (`GPT`, `Claude`, …), then Other, and a flat Embeddings group for Knowledge. Option text is `friendlyLabel — bestFor`. Each studio passes its own testid: `documents-studio-model`, `images-studio-model`, `videos-studio-model`, `music-studio-model`, `meeting-model`, `edit-generate-model`, `legal-studio-verifier-model` and the other `<mode>-studio-model` selects; regen panels use `*-regen-model`. Group labels are translated through `pickerGroupLabel` (`apps/web/lib/picker-group-label.ts`).
- `models-job-fallback`: a **job** mode's model is not always the one that answers. When a call fails with a transport-class error, the host retries once on a stand-in and the result carries a `notice` of `{ code: "model_fallback", from, to }` (`packages/core/src/models/job-fallback.ts:9`). Finance renders it as `finance-result-model-fallback` (`apps/web/components/finance-steps/finance-result-notices.tsx:23`), reading "{from} is unavailable; used {to}". Chat has its own line, `chat-model-fallback` (`apps/web/components/chat-model-fallback-notice.tsx:36`, rendered at `chat-session.tsx:543`). Every other job mode gets the same swap and shows nothing.
- `models-thinking-selfheal`: a gateway that refuses a Thinking level is not an error the person sees. When a call fails with a 400 that names `reasoning_effort` (or `thinking`, `effort`) before any token or tool call, the runtime retries **once** with one level less, or with no effort parameter when the model takes none, and remembers what worked for that model, for that tenant, for 30 minutes (`LEARNED_EFFORT_LIMIT_TTL_MS`, `packages/core/src/runtime/effort-selfheal.ts:186`) or until Settings is saved. Chat and every job mode share it. There is no testid: the proof is an answer where an error used to be, one log line on the host (`effort-plan.ts:155`), and the request bodies in the unit tests. A model the policy table (`MODEL_POLICY_TABLE`, `packages/core/src/models/model-policy.ts:177`) does not know is sent no effort unless one was chosen.
- `models-policy-tools`: two dev-only tools keep the policy table honest against the live catalogue. `catalog-diff` shows which live chat ids the table knows or calls `UNKNOWN`, how every ranked list fares, prices, and what is new since the last run. `probe` sends one tiny raw request per Thinking level for the models the table does not know, with the self-heal off, and proposes a table entry per model for a human to review. Code and tests: `packages/host/eval/models/`; map: [`model-policy.md`](../../../../docs/internal/maps/model-policy.md) § 6. They never ship, never call `:3000`, and never edit `model-policy.ts`.
- `models-recommendation-lists`: the order of every list the product ranks by (the Chat default and Recommended set, each job mode's default, the outage stand-ins, the video list) is data in five files under `packages/core/src/models/`, written down in [`model-policy.md`](../../../../docs/internal/maps/model-policy.md) § 7 and, with prices and the probe that chose them, in `docs/internal/gateway-model-selection.md` § 10. Image, video and audio ids that no role line describes say **Image**, **Video** or **Audio** in their `bestFor` hint, not General chat.

- `models-key-availability` (2026-11-11): the pickers show only the models this key can run, and Settings says why the others are missing. `GET /api/v1/settings` answers `modelAvailability` and `GET` and `POST /api/v1/models` answer `availability`: `{ unavailable: [{ id, kind, status, reason, checkedAt }], kinds: { chat|image|video|speech|music|transcription: { offered } } }`. The Settings card is `settings-models` with `settings-models-count-<kind>`, a collapsed `settings-models-unavailable` (one `settings-models-row-<id>` per model, with a plain reason) and `settings-models-refresh`. Map: [model-policy.md](../../../../docs/internal/maps/model-policy.md), "Which models a key can use".
- `models-kind-empty` (2026-11-11, second pass): a kind with no offered model disables its entry point with a reason, in `en` and `id`, that links to the Models card. Images (`images-studio-no-models`) and Videos (`videos-studio-no-models`) had this panel already; Music gets it now because `GET /api/v1/music` no longer re-adds a Settings/agent pin the key refused (`studioMusicPicker`) and answers `models: []`, `defaultModel: ""` (`music-studio-no-models`, and Generate plus Draft lyrics are off). The Edit Generate tab no longer falls back to its demo video/image ids with a key in place: `edit-generate-no-model` disables Generate. Speech is a reason, not a control: `speechUnavailable` is `none_on_key` when the catalogue has a reachable speaker that the key's calls refused (`music-studio-voice-unavailable`).
- `models-poll-refusal` (2026-11-11, second pass): only a refusal at submit time can hide a model. A polled job that fails after the gateway accepted it (Seedance, "may be related to copyright restrictions") carries `phase: "poll"` on its `GatewayRefusalError`, and `classifyGatewayRefusal` answers `null` for it, as it does for any 401 or 429. A submit-time 403 `prepaid_async_requires_fixed_price` still files `account_blocked`.
- `models-media-params` (2026-11-11): every image and video model has a media parameter spec (aspect or size list, length, resolution, sound, quality, tier, count, format, and the body it rides on). `GET /api/v1/images` and `GET /api/v1/videos` answer each model with its spec as `media`; the studios draw only what it holds, and `POST` answers `sent` and `adjusted`. The values come from the gateway's published `config.parameters` (kept in the model cache as `mediaParams`), then a built-in table with evidence per field, then a family default shown as unverified. The account is [`generate-studios.md`](../../../../docs/internal/maps/generate-studios.md) § 5 and [`model-policy.md`](../../../../docs/internal/maps/model-policy.md).

## How to get to it (user POV)

- Open `/chat`. The model choice is `tier-picker` in `chat-header` ([model-tiers.md](./model-tiers.md)). There is no model list and no Thinking control.
- Open a job studio (for example `/chat?agent=documents`, then `agent-open-studio`). The model select is the studio's `<mode>-studio-model`, usually inside More.
- Doctor records `modeKeys`, `chatCount` and `curation` from `GET /api/v1/models`.

## Gotchas

- A `model-picker` count of 0 is the shipping state, not a regression. `ModelPicker` and `thinkingRequestFields` (`apps/web/lib/chat-thinking.ts:67`) have no non-test caller, and `apps/web/lib/chat-thinking-wiring.test.ts` asserts that the composer sends no Thinking fields. Chat posts a tier; the host picks the model.
- Doctor `chatCount` is the chat-kind model count from `/api/v1/models`. It drifts with the catalogue; do not pin it.
- **Label casing.** `friendlyLabel` keeps acronyms and units in capitals and writes a dashed version as one dotted number: `GLM 5.3 Flash`, `DeepSeek V4.1 Flash` (id `deepseek-v4-1-flash`), `Qwen MT Turbo`, `GPT OSS 120B`. The labels are made on the host (`packages/core/src/models/curation.ts`, `ACRONYMS` at `:28`), so read them from `GET /api/v1/models` and assert with a contains-text match. Report any other all-capitals family that reads title case as a finding in `docs/internal/unreleased.md`.
- `isThinkingModel` is a name regex (`curation.ts:103`), not the policy table, and the catalogue also hides `isPickerHidden` ids and dated snapshots from the studio selects.
- **A job mode that answers on a different model than its select shows is not a bug.** `runWithJobModelFallback` (`packages/host/src/job-model-fallback.ts:181`) swaps **once** and only on a transport-class failure: 502/503/504, `unavailable`, `ECONNREFUSED`, `fetch failed`, the response-header abort and the stream watchdog (`GATEWAY_UNAVAILABLE`, `packages/core/src/models/job-fallback.ts:46`). A 400/401/403/404/422/429, a bad key, an unknown model, a context-length error, a content filter or "returned no text" is **never** swapped (`NOT_A_TRANSPORT_FAILURE`, `:58`). Three more hard stops: a model the person picked themselves in the studio select is never swapped (`modelExplicit`), neither is a call that had already started streaming, and neither is a job whose cancel signal has fired (`maySwapModel`, `job-model-fallback.ts:160-168`). If the stand-in also fails, the original error is rethrown untouched, status and all.
- **The stand-in comes from a per-mode list, then a shared tail.** `JOB_MODE_PREFERENCES[mode]` (`packages/core/src/models/mode-defaults.ts:64`) followed by `JOB_FALLBACK_TAIL = ["gpt-6-luna", "claude-sonnet-5-5", "gpt-5.6-luna", "deepseek-v4-1-flash"]` (`packages/core/src/models/job-fallback.ts:38`), filtered to ids live in this desk's catalogue and deduped. Do not pin the chosen id in a recipe.
- **A failed model is skipped for five minutes afterwards.** `JOB_MODEL_DOWN_MS = 5 * 60 * 1000` (`packages/host/src/job-model-fallback.ts:27`); `startModel` (`:153-158`) skips a model still marked down before the *first* attempt, so a second job can land on the stand-in with no failure of its own. Saving Settings, forgetting the key (Start over, `scope: "key"`) and the hosted company erase clear that breaker and the learned Thinking-level limits with it (`resetModelReliabilityState`, `job-model-fallback.ts:80`, called at `packages/host/src/handlers/settings.ts:393` (save), `:572` (forget the key) and `packages/host/src/tenant-reset.ts:385` (erase)), so re-save the key before concluding a model is unreachable.
- **A 400 is still never a model swap.** The Thinking self-heal sits below `runWithJobModelFallback`: a job that heals never reaches it. Do not read a healed job's answer as a `notice`; there is none, the model did not change.
- **The notice is not an SSE event.** It rides the final JSON result, not `job.*`, so a driver watching the stream will not see it. Read `result.notice`, or the `finance-result-model-fallback` line, after the job returns.
- **GPT-6 carries its level on Responses (since 2026-09-30).** A GPT-6 Responses request has `reasoning: { effort, summary: "auto" }` at every level the table allows. Live effect not driven: if the gateway answers 400 to it, the self-heal drops the block for 30 minutes at the cost of one refused call.
- **A job that fails while it is watched does not hide its model.** A refusal at submit time is about the model; a job the gateway accepted and then failed (a copyright refusal on a clip, a bad lyric, an upstream error) is about that one request. The poll branches tag their `GatewayRefusalError` `phase: "poll"` and `classifyGatewayRefusal` ignores it, as it ignores every 401 and 429. If a model disappears after a generation, the lesson came from the submit call, not the poll; `settings-models-unavailable` says which status was learned.
- Doctor must hit loopback only.
