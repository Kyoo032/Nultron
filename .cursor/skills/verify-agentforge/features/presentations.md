# Presentation

Presentation is a job. The first screen is the template list, then the topic box, length and style chips, and Create. The deck that appears is edited by clicking words on the slide. Download is the only primary button after that. Builder, an exact slide count, model, starters, source (pasted text and desk files), movement, save, notes, and shape tools sit in More (`presentations-more`). A selected shape or Open Slide block gets a small toolbar on the slide. The default builder is Open Slide, so Create drafts a deck on a stub desk. Nultron stays in More, and a starter there still opens the Nultron stage. On a live run a Nultron outline passes four host checks with one repair round, and an outline that still fails ships with a note; Open Slide has no structure checks. Both builders then get a layout and design pass. Education does not show the Presentation builder. Its lesson uses the same simple stage, and its own More holds quiz, a page, show, and save. There is no pen, table, chart, or slide master, and no thinking-level control. Map: [`docs/internal/maps/presentations.md`](../../../../docs/internal/maps/presentations.md).

## Sub-features

- `presentations-header` (a feature id, not a testid; the real hooks are `mode-header` and `expected-inputs`), title plus one outcome line in `expected-inputs`: "A few slides you can change, then download." `presentations-download` is the only header button, and only after a deck exists.
- `presentations-rail` reaches `/presentations` from `mode-presentations` on Default.
- `presentations-shell` shows `presentations-studio`. An empty desk shows the template list first under the title, then `presentations-studio-prompt-bar`, then `presentations-studio-empty` (the `StudioEmptyDesk` wrapper, `apps/web/components/presentations-studio.tsx:741`, `flush`): count 1 on an empty desk, 0 once a deck exists or while generating. It always renders with `data-mode` and `data-tier`, plus `data-staged="true"` only while the header stage is on screen (absent at 1024 and 390 px), holds no text, and draws nothing while the header's Nultron is on screen, so it can be in the DOM with no height. `presentations-hint` is not in the source: count 0.
- `buddy-stage-header`, Nultron on the header's art column (`ModeHeader`, `apps/web/components/mode-header.tsx:66-73`): `buddy-stage-header` and its tap button `buddy-stage-header-tap` (`apps/web/components/buddy-stage.tsx:72`, `:82`) are in the DOM at every width, but the column is `display: none` below 60rem of header width (`apps/web/app/globals.css:1925`; the 60rem `@container` that turns it on is `:1969-1973`), so they are visible only on a wide pane (about a 1280px window and up). While the stage is at least 25% on screen the empty-desk Nultron stands down (see `presentations-shell`). A visited studio stays mounted, so scope `buddy-stage-header` to `presentations-studio` or use `.first()`. Detail: [documents.md](./documents.md).
- `presentations-ask` is the topic. The label is `presentation.ask` ("What's your presentation about?"). The box is `presentations-prompt`, a `<textarea>` (it keeps newlines, unlike the one-line prompts of Documents, Research, Images, Videos and Data).
- `presentations-open-slide-choices` (not `presentations-choices`, which is count 0; `presentations-studio.tsx:494`, `:531`) holds two chip rows on the empty screen: length `presentations-length-short|standard|deep` (Short / Medium / Long) inside `presentations-open-slide-pages`, and style `presentations-style-minimal|light|standard` (Simple / Clear / Detailed) inside `presentations-open-slide-density`. Defaults are Medium and Clear. Once a deck is open those chips move into More. On the Nultron builder they only add a "Keep it {length} and {style}." line to the prompt; they do not set a count.
- `presentations-generate` is Create (`presentations-generate`). On the empty screen it is the primary button on its own line, above More, which is a full-width disclosure under it (`apps/web/components/presentations-studio.tsx:505-519`). Once a deck is open Create is a small ghost button inside More (from an empty desk with the engine on `nultron`, `hasDeck` is false because the outline is null, so the first-screen Create stays, `:505-518`; the in-More Create exists only once a deck is open, with the same testid; switching the engine with an Open Slide deck open hides that deck, keeps its state and moves the topic and Create back out) (`:689-698`, testid at `:694`). Create is a streamed job (`useJobStream`): the default builder posts `POST /api/v1/presentations/open-slide/stream` and a stub desk ends the stream with a local draft, while the plain `POST /api/v1/presentations/open-slide` still answers 200 to a direct caller. On a keyed desk the same press is a PAID live call: `generateOpenSlideDeck` takes the live branch whenever the runtime is not stub (`packages/host/src/open-slide-generate.ts:226-233`: the stub return is `:226-229`, the live `collectDeck` call follows at `:233`), so a deck there is model-written, not proof of a stub. Switching More's "Slides from" to Nultron posts `POST /api/v1/presentations/stream`; a stub desk ends that stream with a `job.error` (`runtime_stub`, status 503) that shows in `presentations-error`, and the plain `POST /api/v1/presentations` answers 503 itself (a keyed desk runs the model). While either runs, `presentations-progress` (`JobProgressList`) lists the phases.
- `presentations-harness` runs inside that Create, before the stage. No new control, and `presentations-progress` is its only trace. **Open Slide:** Short stays inside 3–5 pages (the stub draft is 4). Every page has speaker notes. Source text from More and desk files is what the content lines say, and a figure remains only when the topic or that source contains a digit. A live deck that is still too short is asked once more, then shown. Then each page gets one layout (`title`, `section`, `split`, `quote`, `figure`) on `data-layout`; the design check rejects too many bullets, a title that does not fit, and a wall of text. A live desk asks once more for only the failing pages, and a stub desk shortens them in code and opens no socket. The length chip still wins. **Nultron:** the live outline first passes the four host checks with one repair round (`presentations-checks` below), then the same design pass: an empty note is filled, a bullet the source does not support is replaced by a source sentence, a figure the topic never gave is replaced by the "No figure supplied" line, each slide gets a `layout`, and one more ask rewrites only the crowded slides. The slide count never changes in the design pass. `presentations-progress` shows `Round 1 of 1 · Repairing the outline` when a check failed and was repaired, then the phases `designing` and `repairing` (a page was crowded); their visible text is "Assigning a layout" and "Rewriting the crowded pages" (`id`: "Menyusun tata letak", "Menulis ulang halaman yang sesak"), and `presentations-progress` is mounted only while busy (`:703-705`), so a stub drive misses it unless the route is delayed (G5).
- `presentations-more` (`presentations-more`, details `presentations-more-details`) hides `presentations-engine`, `presentations-slide-count` (Nultron only), movement `presentations-open-slide-motion`, `presentations-studio-model`, `presentations-enhance`, source material, desk files, `presentations-starter`, saved decks, and `presentations-save-deck`. None of those are visible until More is opened. There is no density dropdown and no page-role control on the first screen.
- `presentations-slide-count` is the optional "Exact number of slides" field, shown in More only while `presentations-engine` is `nultron`. Digits only, two at most. Empty sends no count. A whole number from 2 to 15 is sent as `slideCount`, and it counts the title slide. Anything else (`1`, `16`) is not sent, and `presentations-slide-count-hint` turns red with `aria-invalid="true"` on the input. Open Slide has no such field.
- `presentations-desk-files` is the optional "Add from desk files" picker in More, below the source box. It is `DeskSourcePicker` (`apps/web/components/desk-source-picker.tsx:135`), the same control Documents uses ([documents.md](./documents.md)), so its testids are `desk-sources*`, not `presentations-desk-files*`. Scope them to `presentations-studio`. `desk-sources-toggle` opens `desk-sources-list`, one `desk-sources-option` checkbox per desk file (`data-path`). A pick is a removable `desk-sources-chip` inside `desk-sources-chips` (remove with `desk-sources-remove`) that stays on screen with the list closed. `desk-sources-hint` turns into the limit message at five picks and the sixth checkbox is disabled. `desk-sources-over` shows when the picked files and the pasted text pass 120k. It renders nothing (count 0) while the desk has no file and none is picked. The paths go out as `sourceFiles` on generate (both builders) and on slide regenerate; never file text.
- `presentations-checks` is the host's verdict on a live Nultron outline that still failed a check after its one repair round: a short note above the preview, never an error, with one `presentations-checks-slide_count|slide_content|duplicate_title|slide_fit` item per failed check. Slide numbers in the sentences are the filmstrip's (the title slide is 1). Count 0 for a starter, a saved deck, a passing outline (even after a repair), an Open Slide deck, and after any slide edit or rewrite. A reply that is not an outline JSON on the first try gets the same one repair round. If the repair call then fails, or answers with nothing or with something unreadable, the first outline is kept and shown with the note, and nothing on screen says a repair was tried (the host log has `presentation_repair_failed`). Only an outline that never read at all is an error, HTTP 502 `invalid_outline` on the plain routes; the studio's stream shows HTTP 200 with a `job.error` frame carrying that status.
- `presentations-gallery` is the shared example gallery above the prompt bar (`example-gallery`, six `example-card`s, `example-result`). A click only fills `presentations-prompt`.
- `presentations-enhance` rewrites the typed prompt. It answers 200 without a key on a desk (`stubEnhancePrompt` short-circuits ahead of the gate off server mode, `packages/host/src/handlers/enhance-prompt.ts:49-51`); the hosted server never stubs, so there it is gated like the rest.
- `presentations-source` is the optional Source material box inside More (`-source-toggle`, `-source-text`, `-source-picker`, `-source-clear`, `-source-title`), sent as `sourceText` on generate and regenerate. It is also what a `*-make-presentation` handoff from Research / Finance / Data / Market / Legal fills.
- `presentations-starter` loads the Nultron editor (`presentations-preview`, `presentations-editor`) without a live generate. Open More first. The filmstrip lists the title plus each content slide. Only the current stage is `presentations-slide-title` or `presentations-slide`.
- `presentations-studio-model` is the chat-catalog dropdown inside More.
- `presentations-regen` is "Rewrite this slide". In the studio it is portaled into More for the current content slide and opens `presentations-regen-panel`. Confirm with `presentations-regen-submit`; stub/no-key shows `presentations-error`. Education does not mount that button. A rewrite runs no checks.
- `presentations-download` builds a PPTX from the in-memory deck. Open Slide posts `POST /api/v1/presentations/open-slide/pptx`. Nultron posts `POST /api/v1/presentations/pptx`. Neither route calls the gateway.
- `presentations-edit` on Nultron is direct text on the stage: `presentations-edit-title`, `presentations-edit-heading`, `presentations-edit-bullet`. On Open Slide, click a block and edit `presentations-open-slide-text` in place.
- `presentations-shapes` on the studio are not a permanent toolbar on the slide. The add-shape buttons live in More, in the row `presentations-shape-toolbar`. Fill, stroke, text, duplicate, and delete appear on `presentations-selection-toolbar` only while a shape is selected. Education uses that same simple stage. Arrow keys nudge a Nultron shape by 1 percent (Shift by 5). Open Slide arrow keys nudge by 8px (Shift by 40) when focus is not in the text.
- `presentations-save` posts to `POST /api/v1/presentations/decks` or `POST /api/v1/presentations/open-slide/decks` (`presentations-save-deck`, inside More). Reload starts empty until reopen.
- `presentations-open-slide` is the default. Set `presentations-length-short`, type a topic, click Create. `presentations-open-slide-stage` appears and `presentations-open-slide-page` count is 4. The filmstrip is `presentations-open-slide-filmstrip`. Click a text block, change `presentations-open-slide-text`, focus the stage, press ArrowRight: that block's `data-x` increases by 8. `presentations-open-slide-toolbar` (color, add text, duplicate, notes) is visible only while a block is selected.

## How to get to it (user POV)

- Choose Presentation on the left rail (`mode-presentations`). Default has the tab on a fresh first-run desk and on every older desk.
- Open `http://127.0.0.1:3000/presentations` when the tab is unlocked.
- Desk files: a file the person or Chat saved on the desk (see [files.md](./files.md)) appears in More under "Add from desk files".

## Driving it with the Nultron harness

Preconditions:

- Doctor exits 0.
- `mode-presentations` is visible on Default.
- Stub proof of Create is the Open Slide draft (200). Nultron Create is 503. Live generate only if the operator asked and doctor reports `ai`.
- The steps below that press Create (Create, Nultron without a key, Slide count, Desk files as sources) or `presentations-regen-submit` (Starter) describe a stub or keyless desk. On a keyed desk (the operator's `:3000`, `runtime: "ai"`) each of those presses is a PAID live call, including the default Open Slide Create, so stop at the control and do not press it without the operator's say-so. The pane gates only on `useHostedNeedsKey`, which is false off the hosted build: there `presentations-needs-key` is count 0 and Create is never quieted, on a stub desk or a keyed one.
- A stub desk cannot show: a real model outline, the saved `presentations / draft` artifact, the `Presentation` Knowledge Base work card, a real `presentations-checks` note, or a `*-make-presentation` handoff (the source studios only render their action row after a live run). Record those as verified-unreachable, not as skips. The checks note display can be driven with a faked response (below).

## Gotchas

- More stays open after a starter click because the `<details>` element is not remounted. Regen is portaled into that open panel. If More was closed, open it before looking for `presentations-regen` or `presentations-add-rectangle`.
- The title entry is not a content slide. Shapes insert onto the current content slide; from the title stage they land on the first content slide and the stage follows.
- A "6-slide" starter has 7 filmstrip entries. The stage shows one of `presentations-slide-title` or `presentations-slide`. The slide-count field and the check sentences count the same way: 6 means the title plus 5 content slides.
- The desk-file picker and `presentations-slide-count` live inside the closed `<details>`, so they are in the DOM but not visible until `presentations-more` is pressed. `desk-sources` has count 0 on a desk with no files.
- The `desk-sources*` testids are shared with Documents, and both panes stay mounted once visited, so scope them to `presentations-studio`. Like Documents, focusing the form re-reads the desk, so a file saved in Chat after the pane mounted shows up the next time the form is used (a read within 4 s of the last one is skipped).
- Regen opens a panel; it does not POST until `presentations-regen-submit`. Stub is HTTP 503.
- Do not POST `/api/v1/presentations` as a substitute for Create on a live proof. On a stub desk the default Create button is the Open Slide route, not that 503.
- `presentations-download` has no gateway gate. A PPTX is not evidence of a working key.
- A closed gate (403 `gateway_blocked`) reads differently by product. On the hosted build the studio shows `presentations-needs-key` and hides the banner. On Personal the flat error body is unreadable: Create and the Nultron Create both run through the job stream, so the banner shows the stream's own fallback, "Request failed", with no Settings link (Slide rewrite, save and download still go through the studio's `errorMessage()`).
- A failed generate clears the deck on screen (`openDeck` or `outline` is set to `null` before the error is shown), as it does in Documents. A stream that ends in `job.error` shows the same banner (`presentations-error`) through `job.error`.
- Clicking the middle of an Open Slide canvas selects whichever block is under the pointer. Assert the block whose text you edited, not whichever block is selected after a later click.
- Create already applies the length, source, notes, and design checks. A stub deck with no source still has 4 pages on Short. Pasting source in More changes the lines on the pages. It does not add a button. The design check rejects too many bullets, a title that does not fit, and a wall of text. On a stub desk that repair does not open a socket. A Nultron slide rewrite (`presentations-regen-submit`) runs the source/notes repair and the layout fit on that one slide, not the four checks.
- Nudge is keyboard-only. There is no nudge button.
- Cancel now reaches the model call (the request's abort signal goes to the runtime) and a cancelled generate saves nothing. The Presentation UI has no cancel control, so it is not driven here.
- **Feature ids that are not testids:** `presentations-header`, `-shell` (the root is `presentations-studio`), `-rail`, `-ask`, `-harness`, `-gallery`, `-edit`, `-shapes` and `-save` in the sub-feature list name features, not DOM elements. Handles the list omits: `presentations-open-slide-deck-list` and `-deck-open` (reopen Open Slide decks), `presentations-deck-list`, `presentations-download-note`; on the Open Slide stage `presentations-open-slide` (wrapper), `-accent`, `-add-text`, `-duplicate`, `-notes`, `-block` (`data-kind`, `data-x`, `data-y`, `data-selected`) and each page's `data-role` and `data-layout`; on the Nultron stage `data-layout` on `presentations-filmstrip-slide`, `presentations-slide` and `-slide-title` (PR #137, `@agentforge/core/slide-design`, `presentation-preview.tsx:6`, `:518`, `:534`, `:563`; the host's layout, else assigned locally; kinds `title`, `section`, `split`, `quote`, `figure`), `presentations-add-<rectangle|rounded|ellipse|triangle|line|arrow|star|callout|text>`, `presentations-shape-remove` (the Delete button), `-stroke`, `-shape-text`, `-shape-resize`, `-edit-notes`; `presentations-enhance-revert` and `-error` (Enhance is paid on a keyed desk). There is no route to delete a deck (`router.ts:385-388` is GET and POST for both deck kinds), so the Save-deck step of the shapes recipe is not reversible on a shared desk.
- **Driven 2026-10-05 on `:3000` (keyed; maintain3), no Create, no regen submit, no save, no enhance.** `expected-inputs` "A few slides you can change, then download."; 6 `example-card` in `presentations-studio`; `presentations-prompt` a TEXTAREA; `presentations-studio-empty` 1, `presentations-download` 0, `presentations-hint` 0; `presentations-open-slide-choices` present and `presentations-choices` 0; a card filled the prompt (no request); More showed the engine `open-slide`, 2 `presentations-starter`, and `presentations-slide-count` appeared for the Nultron engine where 16 set `aria-invalid="true"`; a starter opened the editor with 7 filmstrip slides whose `data-layout` read `title, section, split, split, split, split, split`; `presentations-download` produced a `.pptx` from the ungated `POST /api/v1/presentations/pptx` (no model); `presentations-add-ellipse` added a shape. The Open Slide stub draft (4 laid-out pages) and the Nultron refusal banner are stub-only and were not driven here; `/presentations/open-slide/stream` and `/presentations/stream` were never called.
