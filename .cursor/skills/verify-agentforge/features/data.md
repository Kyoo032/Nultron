# Data

Data is a table analyst job: upload or paste a table → it is parsed, profiled and loaded into a private SQLite → the host picks the cuts the columns allow (comparison, over time, a count, blanks) and runs those SELECTs → the model names what the results say through a capped read-only `run_sql` tool (plus `calculator`, and `run_code` for exploration that is never evidence), and the host re-runs its SQL in code to build the evidence tables and charts → a sentence that states a number the queries did not return is rewritten once (`job.round` 1 of 1), then dropped. A follow-up stays on the same sheet and the cuts are chosen again. It is not Research and does not call `web_search`. Parsing, profiling and previewing work without a key; analysis needs one. On a stub desk the generate button still stops at the gateway error before any cut runs. Map: [`docs/internal/maps/data-analysis.md`](../../../../docs/internal/maps/data-analysis.md).

Product: both · Instance: main :3000

## Sub-features

- `data-rail` (a feature id, not a testid: `[data-rail]` is a real attribute on the rail container, `app-rail.tsx:243`) reaches `/data` from `agent-data` on Default (and any workspace that includes Data).
- `data-shell` (a feature id, not a testid: `html[data-shell]` is the motion switch, `lib/shell-motion.ts`; the studio's own root is `data-studio`) shows `data-studio`: the header is the title plus one outcome line, `expected-inputs` = "You get: a saved analysis — findings, evidence, and the SQL behind every number." (when the header is 60rem wide or more it also draws `buddy-stage-header`, with its button `buddy-stage-header-tap`, in an art column at the end: `apps/web/components/mode-header.tsx:66-73`, container query in `app/globals.css`); a closed `data-how` disclosure ("How this works"); a `data-source` panel (`data-upload`, which fires the hidden `data-file-input`; the closed `data-paste` disclosure "Or paste a table" holding `data-csv` + `data-use-pasted`; and `data-saved`, a `<select>` that exists only once a dataset is saved) beside a `data-starters` list; the `data-studio-prompt-bar` (`data-enhance`, `data-studio-model`, `data-prompt`, `data-generate`) sits under that grid in normal flow (not a sticky dock). Since 0.15.0 `data-csv` is **not visible** until `data-paste` is opened. While nothing is loaded, `data-studio-empty` (`StudioEmptyDesk`, `apps/web/components/data-studio.tsx:408`; attributes `data-mode` and `data-tier` = `full` | `mascot` | `none`, plus `data-staged="true"` only while the header stage is on screen, absent at 1024 and 390 px) sits below the prompt bar. It draws nothing while `buddy-stage-header` is on screen (`data-staged="true"`); otherwise it draws the flat scene or the mascot, by the room left in the window. It goes away once a dataset, a result or a job exists.
- `data-upload` posts the file to `POST /api/v1/datasets` (multipart, field `file`); `data-use-pasted` posts `{name, text}` to the same route. Both return a dataset with a profile and a 100-row preview.
- `data-dataset` shows the adopted table: `data-dataset-name`, a row/col/size line, `data-profile` (per-column type, nulls, distinct, min/max/mean, top values) and `data-preview-toggle` → `data-preview`. All of this works with no gateway key.
- `data-saved` is a `<select>` with one option per stored dataset (`data-studio.tsx:237-253`); choosing one reopens it via `GET /api/v1/datasets/:id`. It is rendered only when at least one dataset is saved, so with none the element is absent (count 0), not empty.
- `data-starter` pre-fills `data-prompt` (3 starters).
- `data-studio-model` is the generate-bar chat-catalog dropdown, a `select-field min-w-0 max-w-md flex-1 basis-48` (`apps/web/components/data-studio.tsx:367-374`). It shares a wrapping line with `data-enhance` above the prompt row, so it does not overflow the form: at a 390px viewport it is 224px wide and ends at x 341 of a pane that ends at 382.
- `data-prompt` and the `data-cancel` / `data-generate` group are one `PROMPT_ROW` (`apps/web/lib/prompt-row.ts`, used at `data-studio.tsx:381-405`); the group (`PROMPT_ACTIONS`) takes its own line at 40rem of row width or less, each button half of it. Measured on `:3000` (2026-10-01): at a 390px viewport `data-prompt` is 224px and `data-generate` is 224px on the line below; at 768px 438px and 438px; at 1280px one line (prompt about 859px, `data-generate` about 83px). `data-enhance` sits outside that row, so it keeps its word at every width (148px at 390px). `data-prompt` is still a plain `.input` (`:385`), not the 32px `text-field` the other desks' prompts use.
- Generate POSTs `/api/v1/data/stream` with `{datasetId, prompt, model, history}` — the table itself is never in the body. Progress renders as `data-progress`; a finished analysis renders as `data-analysis` (+ `data-summary`, `data-finding`, `data-evidence`, `data-evidence-sql`, `data-evidence-table`, `data-charts`, `data-chart`; `data-tables` and `data-table` never render, because `tables` is always `[]`, `data-analysis-build.ts:184`, `data-harness.ts:236`) with `data-actions` / `data-download` above it. `data-history` marks a follow-up question.
- Generating with no adopted dataset is refused in the browser (`data-error`, no network call). An unparseable upload or paste is refused by `POST /api/v1/datasets` with 400/413 and lands in the same `data-error`.
- `data-download` saves the analysis Markdown. `data-cancel` aborts a running job silently.
- `data-tools` (2026-10-03, no testid): the job binds three tools: `run_sql` (at most 8 queries), `calculator` and `run_code` (a Python or JavaScript sandbox, at most 4 runs; it cannot see the attached table, only desk files, and what it returns is a lead, never evidence). The job's instruction is `DATA_SYSTEM` (`packages/host/src/data-generate.ts:42`). A `run_sql` query is a `job.step` labelled with its SQL (`onQuery`, `:305-311`, emitted at `:310`). A `run_code` run is a `job.step` too, labelled "Ran a Python computation" or "Ran a JavaScript computation" and, when the run did not finish, with the detail "<language> computation failed: <reason>" (`codeRunStep`, `:121`, emitted from `onRuntimeEvent`, `:315-328`); the program, its output and its files stay out of the list, and the phase count keeps showing the SQL count. `JobProgressList` draws a step only as the trailing text of the **active** phase (`apps/web/components/job-progress.tsx:72`), with no testid, so a finished analysis leaves no trace of it, only a file under `out/` in the Files section if the program saved one. Needs a live key. On the hosted server `run_code` is withheld unless `AGENTFORGE_CODE_RUNS=on` ([code.md](./code.md), `code-switch`); `run_sql` and `calculator` are unaffected.
- `data-meta` (2026-10-03, no testid): a saved analysis keeps `question`, `model`, `datasetId`, `datasetName`, `queries` and `skills` in its artifact meta, and `queries` is the list of SQL the host executed for the model's `run_sql` calls, failed attempts included, each cut at 2000 characters (the host's own cut queries are not in it; they are the findings' evidence). Read it from `GET /api/v1/artifacts/:id` (`meta.queries` is an array of strings, never a number). The evidence re-runs after the model finished are not in it. Deleting the dataset through the API deletes the analyses whose meta names it. An analysis saved before 2026-10-03 has `{}` as its meta and stays.
- Stub/no-key generate refuses on `/api/v1/data/stream` with HTTP **200** carrying a `job.error` frame (status 503) — assert `data-error`, never the status; see SKILL.md “Harness-wide gotchas” G2. The message names Toko Token and Settings. On a keyed desk the same press is a PAID analysis.
- `data-needs-key` (hosted only) is the shared `NeedsKeyNote` under the prompt bar (`data-studio.tsx:406`). While it shows, `data-generate` is `disabled` (`:399`). The gate is `useHostedNeedsKey` (`data-studio.tsx:70`), false off the hosted build, so it is count 0 on Personal and on webdev.

## How to get to it (user POV)

- Choose the Data agent on the left rail (`agent-data`), then `agent-open-studio`. A desk that already has it shows the tab. A fresh first-run desk starts with Research, Images, Videos and Presentation only, so hire it first (`/workspaces`, `agent-hire`).
- Open `http://127.0.0.1:3000/data` when the tab is unlocked.
- Legal / Marketing / Students presets do not add this tab unless the owner checks it.

## Driving it with the Nultron harness

Preconditions:

- Doctor exits 0.
- `agent-data` is visible on an existing Default (every desk made before 2026-09-29, and the hosted first desk). A fresh Personal first desk is also named Default but has only Chat, Research, Images, Videos and Presentation (`FIRST_RUN_MODES`), so turn Data on in Workspaces first; the General and Organisation presets include it (`templates/library.ts:678-688`).
- Stub proof: upload (or paste) a table, confirm `data-profile`, press a starter, generate. Expect `data-error` carrying the gateway hint on an HTTP 200 from `/api/v1/data/stream` (G2). Live generate only if the operator asked and doctor reports `runtime: "ai"` and `hasOpenai: true`. The generate-without-a-key step holds only on a keyless or stub desk: on a keyed desk (the operator's `:3000`) `data-generate` is a PAID analysis, so upload, paste, preview and starters are the steps to drive there.

- **Open Data.** Click `agent-data`, then `agent-open-studio` (or go to `/data`). URL matches `/data`. `data-studio`, `data-upload` and `expected-inputs` are visible; `data-how` and `data-paste` are closed `<details>` and `data-csv` is hidden until `data-paste` is opened.
- **Upload.** Set `data-file-input` to a small CSV. `data-dataset`, `data-dataset-name` and `data-profile` appear; `POST /api/v1/datasets` is 201. No key needed.
- **Preview.** Click `data-preview-toggle`. `data-preview` lists the first rows. An empty cell in a pasted CSV renders blank (`textContent ""`, driven 2026-10-05 with `East,` in the paste), as the Paste step below says. The em dash is for a `null` cell (`cellText`, `apps/web/components/data-grid.tsx:19-22`), and `data-profile` uses it for a statistic the column does not have (MIN, MAX and MEAN of a text column; `dataset-profile.tsx:16-18`).
- **Paste.** Click the `data-paste` summary ("Or paste a table") first, then type a table into `data-csv` and click `data-use-pasted`. Driven 2026-09-23: 3-row CSV → `POST /api/v1/datasets` 201, `data-dataset-name` "Pasted table", empty cell shown as a blank in `data-preview`; cleaned up with `DELETE /api/v1/datasets/:id` → 200. `GET /api/v1/datasets` answers `{"items":[…]}`. A second dataset is adopted and `data-csv` clears. `data-saved` now has an option for each.
- **Unparseable paste.** Put a single line with no data row in `data-csv`, click `data-use-pasted`. `POST /api/v1/datasets` is 400 and `data-error` reads "Could not find a header row plus at least one data row" (English on every desk — see Gotchas).
- **No table.** With no dataset adopted, fill `data-prompt` and click `data-generate`. `data-error` is the local "upload or paste first" string and **no** API call is made.
- **Starter.** Click a `data-starter`. `data-prompt` fills.
- **Generate without a key (keyless or stub desk only; PAID on a keyed desk).** With a dataset adopted, click `data-generate`. `data-error` mentions gateway / Settings / Toko Token. No search call.
- **Generate with a key (live only).** Only after doctor reports `runtime: "ai"` and the owner has allowed one billed analysis. Adopt a small CSV (for example `region,amount` with six rows), ask "Which region has the highest total amount? Show the query." and press `data-generate`. `data-progress` draws one `data-progress-phase` row per phase (`profiling`, `cutting`, `analyzing`, `verifying`, `saving`); a step's text shows only under the **active** phase and as `last.detail ?? last.label` (`job-progress.tsx:72-73`), so a `run_sql` step reads "N rows" in the DOM and its SQL travels only in the SSE `job.step` frame, then in `meta.queries` and the evidence SQL. Visible labels (en): "Profiling the dataset", "Choosing the cuts", "Querying with SQL 1/8", "Checking sentences against the queries", "Saving analysis" (the first and last are hard-coded English, `data-generate.ts:310`, `:377`; the others are `data-copy.ts:9-13`). Assert the labels and `data-progress-round`, not SQL text in the DOM. If a sentence stated a number no query returned, a `job.round` 1 of 1 shows as `data-progress-round` ("Round 1 of 1 · Repairing the findings") before the second `analyzing` phase. Then `data-analysis` shows `data-finding` rows; a finding that cites a query has `data-evidence` holding `data-evidence-sql` (the SQL) and `data-evidence-table`. Every figure in an evidence table or chart is a query result, so compare one against the CSV by hand. Then read `GET /api/v1/artifacts?mode=data` for the newest id and `GET /api/v1/artifacts/<id>`: `meta.question` is your prompt, `meta.datasetId` is the adopted dataset's id and `meta.queries` is an array of strings, each a `SELECT` over `data` the model ran (empty when the host's cuts answered the question; the cuts' own SQL is in each finding's evidence), and `meta.skills` is the list of Data harness skills that ran (`read-sheet`, `pick-cuts`, `run-cuts`, optionally `next-question`, then `hold-sentence`). The `:3000` host must be one started after 2026-10-03 (a host that predates the change saved `meta` as `{}` for every analysis, so check the array before blaming the studio). `run_code` is not expected in this run; if the model used it, say so in the evidence. Do not drive this on a keyed `:3000` without the owner's say-so.
- **Clean up.** Every dataset you create persists. There is no delete control in the UI — remove yours with `DELETE /api/v1/datasets/:id` and confirm `GET /api/v1/datasets` is empty (and that `data-saved` disappears on reload).
- **Locale (id).** With the desk on `id` (see [locale.md](./locale.md)), this view reads `Unggah CSV / XLSX` on `data-upload`, and the `data-prompt` placeholder reads `Tambahkan tabel dulu…` before a table is adopted and `Ajukan pertanyaan tentang tabel…` after (`data.promptNoTable` / `data.promptWithTable`, `apps/web/components/data-studio.tsx:386`). `Ajukan pertanyaan tentang tabel ini.` and `Unggah atau tempel tabel, lalu ajukan pertanyaan.` (`data.emptyAsk`, `data.emptyUpload`) are in the catalog but no component reads them, so neither is ever on the page (driven 2026-10-01: only `Unggah CSV / XLSX` rendered). `data-profile` headers read `KOLOM / TIPE / KOSONG / UNIK / MIN / MAKS / RATA-RATA / NILAI TERATAS`. Testids are locale-invariant. Two strings are **not** localized and that is the expected (buggy) state: every host `ApiError` from the dataset store is English, and the gateway hint says "Settings", not "Pengaturan". Do not record either as a locale regression.
- **Cloud live.** Only after doctor `ai`: one table analysis. Do not screenshot the key.

## Gotchas

- An existing Default desk unlocks Data; a fresh Personal first desk does not (see the precondition). Seeded Legal / Marketing / Students desks do not.
- This is not `/api/v1/research`. A network call to Tavily/Brave is a fail.
- Do not POST `/api/v1/data` or `/api/v1/data/stream` as a substitute for the prompt bar on a live proof. `/api/v1/data` is not the UI's route at all — the studio uses `/api/v1/data/stream`.
- A failed analysis on `/api/v1/data/stream` is HTTP 200 — assert `data-error`; see SKILL.md “Harness-wide gotchas” G2.
- **Every dataset you upload or paste is persisted and there is no UI delete.** `data-saved` gains an option for each and the raw files sit under `<data dir>/datasets/<workspaceId>/`. Clean up with `DELETE /api/v1/datasets/:id` and prove it with `GET /api/v1/datasets` plus a reload (`data-saved` count 0).
- **Host error text is English on every desk.** The `id` catalog has `data.errors.noHeader` and friends, but nothing reads them — the message on screen comes straight from the host.
- `data-studio` stays mounted after one visit — SKILL.md “Harness-wide gotchas” G3; here it means an adopted dataset and a shown `data-analysis` survive switching to Chat and back, so reload to get a clean studio.
- **Id desk: more stays English, and the profile headers are CSS-uppercased.** `textContent` of the `data-profile` headers is "Kolom / Tipe / Kosong / Unik / Min / Maks / Rata-rata / Nilai teratas" (`id/data.json:55-65`, uppercased by `dataset-profile.tsx:11`). Also English on an `id` desk: the analysis card chrome "Data analysis" and "Evidence" (`data-analysis-view.tsx:59`, `:20`), `DataGrid`'s "No rows" and "Showing N of M rows" (`data-grid.tsx:74`, `:82`) and the two hard-coded phase labels above; the catalog keys `data.analysisKicker`, `data.evidence` and `data.job.*` have no reader.
- Controls the recipe does not name: `data-enhance` (a `POST /api/v1/prompts/enhance` call: free stub text on a stub desk, after which the testid becomes `data-enhance-revert`, and a **paid** model call on a keyed desk; `data-enhance-error` is an sr-only alert), `data-cancel` (only while a job runs), `data-history` ("Follow-up {n} on this dataset", only after a completed analysis), `data-send-kb`, `data-make-document`, `data-make-presentation` and `data-actions-note` (after an analysis, `artifact-actions.tsx:91-114`), `data-needs-key-settings` (hosted link), the client-side refusal "That file is over the 25 MB cap" (no request, `data-client.ts:54`), `data-saved` (at most 100 options, text `{name} ({rows} rows)`, placeholder "Saved datasets…") and the toggle labels "Show first rows" / "Hide rows". `data-generate` is `type="submit"` in a real form (`data-studio-prompt-bar`), so G1 applies, and `data-studio-model` is empty and disabled until `useJobModel` settles. A desk (workspace) switch remounts the pane and drops the adopted dataset.
- `README.md` and this file used to say a keyless generate is a 503. On the studio's stream route it is HTTP 200 with a `job.error` frame (`runtime_stub`, status 503): see G2.
- **Driven 2026-10-05 on `:3000` (keyed; maintain3), no generate.** Empty desk counts (no `data-dataset`, no `data-saved`, 3 `data-starter`, `data-generate` disabled), a 6-row CSV with a blank cell adopted through `data-file-input` (`m3-data.csv`, 201), `data-profile`, `data-preview` showing the blank cell as empty text, a pasted table adopted as "Pasted table", a one-line paste refused with "Could not find a header row plus at least one data row", then both datasets deleted (`GET /api/v1/datasets` back to `[]`). `data-generate`, `data-enhance` and the live analysis were **not driven (paid)**. The stub half (generate -> `data-error` "Data analysis needs a live gateway. Paste a Toko Token API key in Settings, then try again.") was not repeated: it needs a stub desk.
