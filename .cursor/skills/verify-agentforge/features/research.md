# Research

Research is a job: claims pulled from the question and any pasted text → search on the sources Research already uses → fetched pages → a comparison built in code → a cited dossier as Markdown. A claim with no passage kept from a page is dropped. The model writes the reading and does not invent a source or a quote. A finding may cite only a source that was read and kept a verbatim passage; when the draft does not, those findings are rewritten once and any cite that still does not resolve is dropped. It is not a citation manager and it has no offline output. Live generate needs a gateway key. Search uses a saved Tavily or Brave key when the desk has one, and otherwise Wikipedia, OpenAlex, arXiv, and Crossref. It does not ask for a second key. After the last model call the host checks the findings (every citation resolves, every finding is cited, no section is empty) and sends them back once if they fail. The empty shell, the template prefill and the refused generate (no gateway key) are the stub proof. The comparison and the passage-cite check are proven by `packages/host/src/research-dossier.test.ts` (the stub desk refuses before search). Map: [`docs/internal/maps/research-dossier.md`](../../../../docs/internal/maps/research-dossier.md).

## Gotchas

- **Since 2026-10-19 (QA report BUG-06/07).** `research-progress` shows `<m:ss> elapsed` (`common.jobProgress.elapsed`), counted from when the list mounts, so a reload mid-run restarts it at 0:00. The keyless search asks arXiv and Crossref only for a scholarly question and drops any hit that shares no meaningful word with the query (Chat `web_search` uses the same gate). Reading moves past an unreachable page to the next candidate, up to five extra, so the Reading total can grow while it runs.
- **Since 2026-10-19 (Research bot fix).** A long page (a Wikipedia article over 1.5 MB) is read, not listed as unreachable, and the model sees the paragraphs that match the question rather than the page's first 8,000 characters. In Chat, the Research bot's turn no longer ends on one gateway 503 after `research_dossier` returns: the next step is sent again up to twice. A drive that wants a cited answer asks about something Wikipedia covers in a long article, for example "What is Bank Indonesia's inflation target band?". Map: `docs/internal/maps/research-dossier.md` § 5 step 3 and Failure modes.
- **Every search query passes the outbound guard (2026-10-13).** It is PII-masked and refused past 300 characters or when it holds a credential or an encoded blob; the error frame is `job.error` with `code: "outbound_refused"`, status 400. The question that leads the query list is cut at a word to 300 characters first, so a long question still searches. Since the review fixes the Research screen opens its own guard with the question as the person's text and nothing private, so only those shape rules apply there. A refused query is skipped: the others still run and it is left out of the searched steps and of `dossier.queries`. The run ends `outbound_refused` only on a "stopped" refusal or when every query was refused.

- Default desk unlocks Research. A Legal desk also has it. Do not open Studio to unlock the tab.
- `research-error` shows an "Open Settings" link only when the error matches the hint and does not say "Settings" (`apps/web/components/research-studio.tsx:139`, hint helper `:53-54`). The two stock gateway refusals say it, so they show no link. A failing Tavily or Brave search does not say it (`packages/core/src/tools/platform/web-search.ts:31`, `:56` and `:88` match the hint), so the link shows for those. Assert the banner text, and drive a Tavily or Brave failure to check the link.
- Search does not need its own key. A missing Tavily / Brave key does not refuse Research, unless that backend was chosen in Settings (`web-search.ts:78-83`). The keyless path is `packages/core/src/tools/platform/keyless-search.ts` (pinned Wikipedia, OpenAlex, arXiv, Crossref). Stub desks still refuse on the gateway, before any search. Which route answers a real 503 is in SKILL.md "Harness-wide gotchas" G2; read it before asserting a status.
