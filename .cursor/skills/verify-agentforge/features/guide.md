# Guide

The first-run tour and the first desk it points at. After first-run setup a short guided tour is offered once: five coach marks on the real shell (the rail and its tools, Workspaces, the Chat composer, the Knowledge Base, Settings), each with Next, Back (not on the first), a visible Skip and a close button. Esc closes it and a click outside does nothing. A fresh **Personal** desk starts with Research, Images, Videos and Presentation plus Chat only; the tour's second stop is where the rest are switched on. How it works, file by file: [`docs/internal/maps/first-run-desk-and-guide.md`](../../../../docs/internal/maps/first-run-desk-and-guide.md). The tour is shared by Personal and Enterprise; the first-desk rule is Personal's.

## Sub-features

- `guide-offer` is the welcome card: `guide-card` with `data-guide-mode="offer"`, `guide-next` ("Show me around"), `guide-skip`, `guide-close`. No `guide-back`, no `guide-progress`, no `guide-dots`. Centred.
- `guide-steps` is the five stops, `data-guide-step` = `modes`, `workspaces`, `chat`, `knowledge`, `settings` and `data-guide-index` 0 to 4. `guide-progress` reads "Step n of 5"; `guide-dots` is decoration (`aria-hidden`). `guide-back` is absent on the first stop. The last stop's `guide-next` reads "Done".
- `guide-anchor` is `guide-spotlight`, the ring on the element being pointed at. It follows the anchor; a missing anchor has no ring and the card is centred (`data-guide-placement="center"`), a window with no room beside it gets `sheet` (a sheet with the anchor still ringed; it sits along the top instead when that covers less of the anchor, `guide-placement.ts:123-131`, which a window around 320 px wide can hit). `data-guide-placement` is one of six values, `GuidePlacement` = `right | left | top | bottom | center | sheet` (`apps/web/lib/guide-placement.ts:11`). The card goes on the stop's preferred side when it fits inside the window, then tries the other sides in a fixed fallback order (`placeGuideCard`, `:71-133`), so one stop reads `right` at 1280 and `bottom` at 375 (driven 2026-10-05: stop two got `bottom` at 375). Assert the card is inside the window and that the attribute is one of the six, not that it is `right`.
- `guide-modal` is what open does to the page: `#root` has `inert`, `guide-backdrop` swallows every click, focus is on `guide-card` (`role="dialog"`, `aria-modal="true"`, `aria-label`, `aria-describedby`), and `guide-live` carries the step text for a screen reader. `guide-overlay` is the wrapper around `guide-backdrop`, `guide-spotlight`, `guide-card` and `guide-live` (`data-guide-overlay`, `apps/web/components/guide-tour.tsx:271`); inside the card `guide-title` is the heading (`apps/web/components/guide-card.tsx:112`) and `guide-body` the text (`:130`), the ids `aria-describedby` names: the offer names those two, and a step names three, `guide-progress guide-title guide-body` (`guide-card.tsx:89`; driven 2026-10-05). While the tour is open the desk buddy (`desk-buddy`, `desk-buddy-chip` or a page's `buddy-stage-*`) shows `presenting`: `DeskBuddyReactions` claims it (`apps/web/components/desk-buddy-reactions.tsx`, `BUDDY_PRIORITY.guide`) for as long as the tour is open, and a flash (a tap, a wave) speaks over it for a moment. The card's own 36px mascot is separate: `wave` on the offer, `presenting` on a stop. Where no buddy is drawn (a collapsed rail, or over the empty Chat's hero, which is a full body of its own) only the card's mascot shows.
- `guide-dismiss` is the way out, by testid `guide-skip` (outcome `skipped`), `guide-close` or Esc (outcome `closed`), and `guide-next` on the last stop, Done (outcome `finished`). Each is written to the host (`POST /api/v1/settings/guide`) and the tour never opens on its own again.
- `guide-replay` is `settings-guide` on Settings with `settings-guide-replay` ("Replay the guide"): opens step one on the page the person is on. It does not navigate. Closing a replay writes the outcome like any other exit (`POST /api/v1/settings/guide`, `handlePostGuide`, `packages/host/src/handlers/guide.ts`), which also sets `seen: true`.
- `guide-first-desk` is the rail of a fresh Personal desk: `mode-chat`, `mode-research`, `mode-images`, `mode-videos`, `mode-presentations`, `mode-knowledge`, and counts of 0 for `mode-documents`, `mode-finance`, `mode-data`, `mode-market`, `mode-legal`, `mode-meeting`, `mode-music`, `mode-edit`, `mode-education`. This list is Personal's. A hosted tenant's first desk has every work mode (`HOSTED_FIRST_DESK_MODES`, `packages/core/src/agents/product-modes.ts:69`), so on the hosted app those counts are not 0, and stop two names no missing tools.
- `guide-tour-hint` is `onboarding-tour-hint` under `onboarding-start`: "A quick tour comes next. You can skip it." It is absent once the host says the guide was seen.

## How to get to it (user POV)

- Install Nultron on a machine that has never run it, paste a key, and press Start in Chat. The welcome card is over Chat. Show me around, then Next through the five stops, or Skip, or press Esc.
- Later, Settings → Guide → Replay the guide.
- To see the narrow desk, that same first launch is the only way: the first desk is written once, on a fresh data dir or by Start over ("all").

## Driving it with the Nultron harness

Preconditions:

- **Never press Start over on `:3000`, and never write to the operator's desk.** The tour opens only after first-run setup, which `:3000` (a keyed desk with every mode) never shows, so drive it with the host's answers **faked in the browser**: a scratch Playwright script that answers `GET /api/v1/settings` from `route.fetch()` with `gateway` replaced by a `needs_key` gate and `guide` set to `{ seen: false }`, answers `GET /api/v1/workspaces` with a desk whose `productModes` are `chat, research, images, videos, presentations`, records `POST /api/v1/settings/guide` and returns `{ guide: { seen: true } }`, and answers every other write on `/api/v1/settings*` and `/api/v1/workspaces*` itself so nothing reaches the host. Type only a dummy key. The 2026-09-29 script is the model; keep it in the run's scratch directory, not in `scripts/`.
- The host half (the record, and Start over erasing it) is proven by `packages/host/src/first-run-modes.test.ts` and `packages/host/src/handlers/guide.test.ts`, which use a real empty `AGENTFORGE_DATA_DIR`. `POST /api/v1/settings/guide` is routed in the tree (`packages/host/src/router.ts:295`, `handlePostGuide`) and `GET /api/v1/settings` carries a `guide` field (`packages/host/src/handlers/settings.ts:108`). A `:3000` process started before that route landed answers 404 for the POST and has no `guide` field; in that case say "restart :3000" in the report and drive on the fake. Read `GET /api/v1/settings` for the `guide` field first, so you do not probe the route with a write.
- Hot updates: Vite serves a module under a `?t=` query after an edit, so `import("/lib/guide-store.ts")` from the page is a second copy of the store. Get the URL from `performance.getEntriesByType("resource")`.

Drive:

- **Offer.** Onboarding: Continue, dummy key, Check this key, Start in Chat. `guide-card` has `data-guide-mode="offer"`, is centred, `document.activeElement` is the card, `#root` has `inert`, and the rail behind it shows exactly the first-desk testids above.
- **Steps.** Show me around. Each stop: `data-guide-step` and `data-guide-index`, `guide-progress`, a `guide-spotlight` ring whose box matches the anchor's, the card fully inside the window, `guide-back` present from stop two, Skip and close on every stop. Stop one names the desk's tools (Research, Images, Videos, and Presentation); stop two names up to three tools the desk does not have yet (Documents, Finance, and Data), and on a desk that has every tool says so instead (`guide.steps.workspaces.bodyAll`, `apps/web/locales/en/guide.json:25`: "Every tool is already on this desk. To have fewer, open Workspaces, choose Edit on your desk, and switch some off. …"; driven on `:3000` 2026-10-05); stop three is anchored on `composer` from Chat. A held Enter or arrow key advances one stop, not all of them.
- **Outside click.** Click a corner of the dimmed desk on the offer and on a step: the tour is still open, on the same stop.
- **Keyboard only.** From Settings, focus `settings-guide-replay` and press Enter: the tour opens on stop one (no offer), focus on the card. Enter on the card, or ArrowRight, is Next; ArrowLeft is Back; Tab and Shift+Tab visit close, Skip, Back, Next and wrap without leaving the card; Space on a focused Next advances; Esc closes and focus returns to `settings-guide-replay`. Five Enters from the card walk the whole tour to Done when it was started from Replay (which begins on stop 1); from the first-run offer it takes six, the first Enter leaving the offer.
- **Persistence.** Skip, close and Esc each POST `skipped`, `closed`, `closed`; Done posts `finished`. After each, reload with the fake host now saying `seen: true`: nothing opens. Send the fake back to `needs_key` and finish first-run setup again: still nothing, and `onboarding-tour-hint` is absent.
- **Fallback.** Hide `workspaces-link` (`style.display = "none"`) on stop two: within 400 ms the ring is gone and `data-guide-placement` is `center`; restore it and the ring returns. On Settings, stop three has no composer, so the card is centred with `guide-spotlight` absent (driven on a Replay from `:3000`, 2026-10-05).
- **Widths and themes.** 1280, 683 and 375 wide, light and dark, English and Indonesian (`GET /api/v1/settings` fake `locale: "id"`): every card inside the window, no horizontal scroll, and at 375 the rail stays visible above a bottom sheet. Screenshots of the offer and each stop under `evidence/guide/<run-id>/`.
- **Buddy.** On Settings (no hero, no page stage; the rail buddy is `desk-buddy` or `desk-buddy-chip`) press `settings-guide-replay`: the buddy's `data-state` is `presenting` for as long as the tour is open and returns to its resting state (`idle`) after Esc. It is not drawn over the empty Chat's hero or on a collapsed rail, so the offer over a fresh Chat shows only the card's own mascot. Driven 2026-10-01 on `:3000` with the fake host: on Settings the buddy read `idle` before the Replay, `presenting` while the tour was open and `idle` again after Esc; over the Chat offer the rail buddy's dock was `none` and only the card's 36px mascot showed (`wave`).
- **Motion.** The tour adds no looping animation of its own. `document.getAnimations()` still lists infinite ones while it is open, because the desk's decoration loops (`nx-grid-drift`, `nx-bob`, `nx-turn`; smooth on webdev and stepped only under `html[data-shell="desktop"]` since 2026-10-05, PR #138) run as on any page (driven 2026-10-01, before the shell change, so re-count: 7 over the offer on Chat, the shapes' `nx-bob` and `nx-turn`; 1 on Settings during a Replay, the dot grid). So assert that none of them belongs to `guide-card`, `guide-spotlight` or `guide-backdrop` (`getAnimations({ subtree: true })` on `guide-overlay`), not that the document has none.

## Gotchas

- **It never opens on `:3000`.** No onboarding, no offer. Replay is the way in, and it proves everything except the offer.
- **`seen: true` is not proof that anyone walked the first-run tour.** Every exit, a Replay included, posts an outcome, and the host records it with `seen: true`. On 2026-10-05 a `:3000` desk that had never shown the tour read `guide: {"seen":false,"outcome":null,"at":null}` before a Replay and `{"seen":true,"outcome":"closed","at":…}` after Esc. Only Start over clears it, so a Replay on a shared desk cannot be undone from the UI. Read `guide` first, and say in the evidence that the drive flipped it.
- **Focus falls to `app-main-panel`** after the offer, because the onboarding button that held focus is gone by then. That includes Esc on the first-run offer (driven 2026-10-05). After a Replay it goes back to `settings-guide-replay`.
- **The rail's first frames are Chat and a skeleton (`rail-modes-skeleton-row` x4), or the remembered desk, never every mode** (2026-09-29; it used to flash all fourteen tabs). `guide-card` waits for the workspaces answer, so a screenshot taken after it appears shows the real desk. See [rail.md](./rail.md), `rail-first-paint`.
- **Do not match the copy by string on an `id` desk.** Match the testids and `data-guide-*` attributes.
- **A first desk cannot be seen on `:3000`.** Its desk was written before the rule and keeps every mode; that is the rule working. Use the test, or the fake.
- Also true: every way of ending first-run setup offers the tour, not only `onboarding-start`: an `onboarding-example` tile and the hosted `onboarding-later` button end through `finish()` / `onDone` too (`onboarding-screen.tsx:220-236`, `:402`). The overlay is portaled to `document.body`, so query `guide-overlay` from `document`, not from `#root` (which is `inert`). `guide-backdrop` has no background while a spotlight is shown (the ring's 100vmax box-shadow dims the desk) and takes the scrim colour only when there is no ring (`guide-tour.tsx:278`). The offer card has no `data-guide-step` or `data-guide-index` (both undefined); `guide-dots` `li` carries `data-current="true"`; `guide-close` has `aria-label` "Close the guide" and the card's label is "A quick tour of <productName>". If focus leaves the card (Back on stop 1 removes the focused button) it is pulled back in, and a held ArrowLeft, ArrowRight, Enter or Space is swallowed (`guide-tour.tsx:220`). The map's "every settings read hydrates the store" is wrong: only the gate read in `App.tsx:279` calls `hydrateGuide`.
- **Driven 2026-10-05 on `:3000` (keyed; maintain3), host faked in the page, nothing written.** `GET /api/v1/settings` was faked to `needs_key` with `guide.seen: false`, `POST /api/v1/settings` to an allowed answer (a dummy string, never a key) and `POST /api/v1/settings/guide` fulfilled by the page and recorded: onboarding reached `onboarding-try` with `onboarding-tour-hint`, Start opened `/chat`, and `guide-card` appeared as the offer (`data-guide-mode="offer"`, placement `center`, `role="dialog"`, `aria-modal="true"`, `#root` inert, `guide-back`, `guide-progress`, `guide-dots` and `guide-spotlight` all count 0, `guide-next` "Show me around"). Five stops in order `modes` (right), `workspaces` (right), `chat` (top), `knowledge` (right), `settings` (right) with "Step n of 5", a spotlight on each, `guide-back` from stop 2 and "Done" on the last; Done closed the tour and posted `{"outcome":"finished"}` (to the fake). The rail behind it showed all 14 work modes, because `:3000`'s existing Default has every mode, so the stop-1 and stop-2 bodies differ from the first-desk wording above; the real `guide` record on the host stayed `closed`. Esc and Skip, the 375 px sheet, Replay and the Indonesian locale were not repeated this pass.
