# Meeting

Meeting turns a recording or a pasted transcript into a transcript, structured minutes, and the same minutes in the other language. Rail tab `mode-meeting` (an existing Default has it, a fresh Personal first desk does not; the `id` rail row reads "Rapat"; the row reads `Meeting` with no `New` badge since 0.15.0), route `/meeting`, studio `meeting-studio`. The header is the title plus one outcome line, `expected-inputs` = "You get a transcript, structured minutes, and the same minutes in the other language — from a recording or a pasted transcript." Create, upload, paste and the recorder's controls need no key; only `meeting-run` reaches the gateway. On a live run the minutes call passes four host checks (valid minutes JSON, action owners the transcript names, no invented dates or times, a non-empty summary) with one repair round. Minutes that still fail are kept and shown with `meeting-checks-note`; the translation is not checked. A model you pick in `meeting-model` is held for the whole run. Full mechanism map: [`docs/internal/maps/meeting-minutes.md`](../../../../docs/internal/maps/meeting-minutes.md).

## How to get to it (user POV)

- Rail → `mode-meeting`, or open `http://127.0.0.1:3000/meeting`.
- Type a title, pick the language spoken, press Create; then record, upload a file, or open "Or paste a transcript".
- A desk that hides Meeting redirects `/meeting` to its first visible mode, assert the rail testid, not the studio (SKILL.md G3).

## Gotchas

- **A picked model is pinned, a seeded one is not.** The model select seeds the studio's default and sends only `model`, so the host may still swap it after a transport-class failure. Change the select and the request also carries `modelPinned: true`, and the host holds the minutes, the repair and the translation to that model. The artifact's `meta.model` and the minutes record name the model that answered, which is the picked one only in the pinned case.
- **A failed check does not fail the run.** Minutes that still fail after the repair are saved and shown, with `meeting-checks-note` above them and the verdicts in `minutes.checks` and `meta.checks`. A set that passed shows no note, with or without a repair, and the Translation tab never shows one. Only minutes that never parse are an error (HTTP 200 event-stream carrying `job.error` `invalid_minutes` or `generation_failed`, 502).
- **The paste box is behind a disclosure.** `meeting-paste` has count 1 but is not visible until `meeting-how` is opened; a recipe that fills it directly fails on visibility, not on the product.
- **25 MB per recording**, because the HTTP adapter refuses a body over 26 MB. Over that is a 413, not a truncated upload. A longer meeting is a pasted transcript. **The browser recorder cannot produce one**: it records opus at 24 kbps (about 10.8 MB an hour) and auto-stops 512 KB short of the cap, keeping everything captured so far and saying so in `meeting-record-capped`.
- **Recording needs the hosted `Permissions-Policy` to allow two features.** `microphone=(self)` and `display-capture=(self)` in **both** `packages/host/src/security-headers.ts` and `webapp-deploy/Caddyfile`. Without them the browser refuses before any product code runs, so the Record button does nothing and there is no error worth reading. Fixed in the tree, never sent to a browser, [SR-14](../../../../docs/internal/security-register.md#sr-14). Webdev sends no such header, so a green drive on `:3000` says nothing about the deploy.
- **A `.webm` recording is stored as `recording/source.weba`.** `EXT_BY_MIME` maps `audio/webm` to `weba`. Cosmetic: ffmpeg reads by content. Do not go looking for a `.webm` on disk.
- **Replacing a recording now deletes the old file.** Re-uploading over an existing recording removes every other `source.<ext>` in that meeting's `recording/` and drops the derived `audio/` chunks ([SR-13](../../../../docs/internal/security-register.md#sr-13)). Never driven through the UI, if you do it, record what you saw.
- **A failed translation no longer loses the minutes (2026-09-23).** The minutes are saved on the meeting before the translation starts, so a `translating` failure leaves `meeting-tab-minutes` with content and `meeting-tab-translation` empty. A failed transcription part-way through is still metered for the chunks that answered.
- **A date or a figure the transcript never said does not stay in the minutes (2026-09-28).** `heldOn` and a due date are cleared unless that phrase is in the transcript. A number that is not its own number in the transcript (so `12` is not found inside `120`) becomes the marker `[figure not said]`, in both languages. The marker is not a new control. This runs in code after the minutes call's checks and its one repair round, so a decision that quotes a date the transcript never says is first sent back through the `quoted-dates` check; when the repair does not fix it, the number is stamped as the marker and `meta.checks` still says `quoted-dates` failed. A first answer that is not the sheet is asked once more (the `minutes-shape` check's repair, with no second retry on top); a gateway failure is not. A translation that changes the counts, owners, dates, provisional marks, or figures is asked once more, and if it still disagrees the minutes stay and the translation is not saved (`translation_disagreed`, the message follows the desk language). Stub still answers `runtime_stub` before any of that.
- **A dropped attendee is the guard working, not a bug.** `meeting-unverified` says how many names the transcript never said were removed. Check the transcript before reporting it as data loss.
- **Meetings are folders**, under `localDataDir()/meetings/<workspaceId>/<meetingId>/`. There is no table and no migration. Deleting a workspace's directory is how you reset the mode.
- **The transcription wire is `/chat/completions` with base64 `input_audio`**, not `/audio/transcriptions`, for every id except a Whisper-style one. If you see a request to `/audio/transcriptions` from Meeting, the model id is Whisper-shaped, that is by design.
- **Delete is two steps since 2026-09-23** (0.15.0 verify finding 7). `meeting-delete-<id>` opens the confirm; only `meeting-delete-confirm` removes the meeting and its folder, recording included, and since 2026-10-02 its transcript and minutes artifacts and the minutes' Knowledge card, in one transaction (`DELETE /api/v1/meetings/<id>` 200). `meeting-delete-confirm` and `meeting-delete-cancel` carry no id, only one row is armed at a time.
