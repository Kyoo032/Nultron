# Legal

Legal is a matter job: .docx files in, position-aware review, verified deliverables out (issues memorandum, tracked-changes redline, deviation report, red-flags Markdown). v1 accepts .docx only. Live runs need a gateway key; matter intake, uploads, and role editing work without one. Map: [`docs/internal/maps/legal-matter-run.md`](../../../../docs/internal/maps/legal-matter-run.md).

## Sub-features

- `legal-rail` reaches `/legal` from `mode-legal` on Home and on the Legal preset.
- `legal-shell` shows `legal-studio` with the matter panel, the matter map, "What will happen", and previous matters. Its `ModeHeader` draws `buddy-stage-header` in the art column when the header is 60rem wide or more; while that stage is on screen the empty-desk mascot on screen 1 (`MascotSlot`, `apps/web/components/legal-studio.tsx:399`) draws nothing, and below 60rem it is drawn.
- `legal-file-input` accepts only .docx; a .txt or .pdf shows the message "Only .docx files are accepted in v1. Convert PDF or other formats to .docx first."
- Upload is disabled until both `legal-side-party` and `legal-side-counterparty` are filled; `legal-upload-hint` says so. The first accepted upload creates the matter lazily; a refused file (not `.docx`, over 25 MB) is refused before the matter exists. Each accepted file appears with a role tag that cycles through the roles on click; the click sends `PATCH /api/v1/legal/matters/:matterId` with a `roles` array, not a per-file route.
- `legal-side` and `legal-work-type` are segmented controls that wrap instead of clipping (`SIDE_SEG`, `WORK_SEG`, `WORK_OPT`, `apps/web/components/legal-matter-panel.tsx:40-44`; Work splits two and two when its card is 24rem or less); `legal-deliverable-<kind>` are checkboxes; `legal-run` stays disabled until a file is uploaded and both the client party and the counterparty are set.
- `legal-progress` streams phases classify → diff → review n/m → missing → interactions → draft → verify (with "Round r of 3") → edit → package; `legal-cancel` stops it.
- Result tabs `legal-tab-adverse`, `legal-tab-missing`, `legal-tab-unmarked`, `legal-tab-verification`, `legal-tab-redline`, `legal-tab-memo`, `legal-tab-audit`; findings rows are `legal-finding-row`; the verification panel is `legal-verify`.
- `legal-download-<kind>` fetches `/api/v1/artifacts/:id/file` (native save on desktop).
- Stub/no-key run shows `legal-error`. The studio posts `/api/v1/legal/matters/:id/run/stream`, so the response is **HTTP 200 `text/event-stream`** and the failure arrives as the stream's single `job.error` frame, `{ code: "runtime_stub", status: 503 }` — see SKILL.md **Harness-wide gotchas** G2. Do not assert a 503 on the response.
- Matter form fields beyond the party: `legal-matter-title`, `legal-side-counterparty`, `legal-side-role-other` (only when the side is "other"), `legal-playbook`, `legal-author`, `legal-addressee`, `legal-firm`, `legal-instructions`. The panel itself is `legal-matter-panel`. `legal-side-counterparty` and `legal-side-role-other` sit in an auto-fit grid (`apps/web/components/legal-matter-panel.tsx:116`, `minmax(min(16rem,100%),1fr)`), so they share a line when the card has room and stack to one column when it is narrow; `legal-side-party` is `min-w-[14rem] flex-1` (`:109`) beside the side buttons. Placeholders: `legal-side-party` "Client name as printed" (`id`: "Nama klien di dokumen"), `legal-side-counterparty` "Counterparty, e.g. Lenders", `legal-matter-title` "Title, e.g. Meridian credit" (`apps/web/locales/{en,id}/legal.json:45-53`).
- `legal-deliverable-executive-summary` renders but is **disabled** (`available: false`, `apps/web/lib/legal-view.ts:83-94`; the `id` label reads "belum tersedia pada versi ini"). The four selectable kinds are `issues-memo`, `redline`, `deviation-report`, `red-flags`.
- File rows carry `legal-file-role-<docId>` (cycle) and `legal-file-remove-<docId>` (remove); the drop target is `legal-drop-zone`, the list is `legal-file-list` and each row is `legal-file-row`.
- The right column is three panels: `legal-matter-map` (rows `legal-matter-map-row`), `legal-plan` ("what will happen"), and `legal-previous` (rows `legal-previous-row`, each with `legal-open-<matterId>`). Model pickers are `legal-studio-model` and `legal-studio-verifier-model`: two `<select class="select-field …">` (`MODEL_SELECT`, `apps/web/components/legal-matter-map.tsx:78`, used at `:148` and `:159`), each in a full-width label that drops the select under its label text when 12rem of select does not fit beside it. Screen 1's two columns are one column below `lg` (`apps/web/components/legal-studio.tsx:397`).
- `legal-reopen` is a `<select>` that renders only when at least one matter exists.
- The running screen adds `legal-round`, `legal-documents` and the `JobProgressList` internals `legal-progress-round` / `legal-progress-phase` / `legal-progress-sources`.
- The result screen adds `legal-result-headline`, `legal-new-matter`, `legal-next-turn`, `legal-findings`, `legal-findings-stream`, `legal-memo`, `legal-memo-text`, `legal-redline`, `legal-redline-row`, `legal-audit`, `legal-handoff`, the per-row `legal-verify-<key>`, and the shared `ArtifactActions` set (`legal-actions`, `legal-download`, `legal-send-kb`, `legal-make-document`, `legal-make-presentation`, `legal-actions-note`).
- `legal-studio` carries `data-screen` = `new` | `running` | `result` (`apps/web/components/legal-studio.tsx:301`, the `screen` constant at `:293`) — the cheapest assertion for which screen is up.
- `legal-needs-key` (hosted only) is the shared `NeedsKeyNote` above `legal-error` (`apps/web/components/legal-studio.tsx:359`). While it shows, `legal-run` is `disabled` (`:337`). The gate is `useHostedNeedsKey` (`:85`), false off the hosted build, so it is count 0 on Personal and on webdev. Intake, upload and role editing stay open either way.
- Matter deletion is `DELETE /api/v1/legal/matters/:matterId`. **There is no UI control and no testid for it** — see [Gotchas](#gotchas). Use it to clean up after a drive.

## How to get to it (user POV)

- Choose Legal on the left rail (`mode-legal`). Home has the tab; the Legal preset seeds it.
- Open `http://127.0.0.1:3000/legal` when the tab is unlocked.
- Marketing / Students presets do not add this tab unless the owner checks it.

## Driving it with the Nultron harness

Preconditions:

- Doctor exits 0.
- `mode-legal` is visible on Home or on the Legal preset. If count is 0, you are on a desk that hid Legal — not a missing agent.
- Stub proof stops at intake, upload, role editing, and the refused run. Live run only if the operator asked and doctor reports `ai`. The refused run holds only on a keyless or stub desk; on a keyed desk the same press runs the model.
- Nine of the ten legal routes never reach the gateway (`packages/host/src/handlers/legal.ts:114`). Intake, upload, role editing, delete and playbooks are fully driveable on a keyless desk; only `run/stream` needs a key.
- Packaged proof repeats the same steps in the installed app, not only on `:3000`.

- **Shell.** Rail shows Legal. `/legal` renders `legal-studio` empty, with the matter panel, the matter map, “What will happen”, and previous matters.
- **Narrow layout (2026-10-01).** Set the viewport to 390 x 844 and open `/legal`. The pane scroller (the visible `overflow-y: auto` ancestor of `legal-studio`) has `scrollWidth` equal to `clientWidth`, and `legal-matter-panel`, `legal-side-party`, `legal-side-counterparty`, `legal-matter-title`, `legal-work-type`, `legal-side` and both model selects each have a right edge inside the panel's (`getBoundingClientRect().right <= legal-matter-panel.right - 16`). Measured on `:3000` on 2026-10-01 with the `en` catalog: the panel's content is 224 px, `legal-work-type` is 224 x 74 px, two rows (`legal-work-type-review` and `-markup` on the first, `-draft` and `-analyze` on the second), `legal-side` is 224 x 74 px (Borrower and Lender, then Other…), and both model selects are 224 px wide on a line of their own under "Model" / "Verifier". At 768 px `legal-work-type` is one row (438 x 38), at 1024 px two rows again (320 x 74, the card is under 24rem) and at 1440 px one row (492 x 38), with the two columns side by side from 1024 px. The matter-title placeholder reads "Title, e.g. Meridian credit" (`id`: "Judul, mis. kredit Meridian") and the counterparty one "Counterparty, e.g. Lenders" (`id`: "Pihak lawan, mis. Kreditur"); neither is cut off at 390 px. Known gap, not fixed: the `legal-playbook` select shows "No playbook · generic review" cut off at 390 px.
- **Fill the sides first.** Type the client into `legal-side-party` **and** the other side into `legal-side-counterparty` before the first upload. The first upload creates the matter (`ensureMatter`, `apps/web/components/legal-studio.tsx:121-128`), and `POST /api/v1/legal/matters` refuses an empty party or counterparty with `400 invalid_request` (`sideSchema`, `packages/host/src/legal/input.ts:26`). Since the 2026-09-23 fix the renderer asks for both first: with either empty, `legal-drop-zone` and `legal-file-input` are disabled and `legal-upload-hint` reads "Enter the client name and the counterparty before you upload."; nothing is POSTed. A host `invalid_request` that still gets through is shown as `legal.errors.*` copy, never as `side.party is required`.
- **Upload.** Upload `packages/core/src/docx/fixtures/lender-initial-aca-draft.docx` and `depositary-bank-round-1-redline.docx` through `legal-file-input`. With both sides filled: `POST /api/v1/legal/matters` then `POST …/files`, one `legal-file-row` per file, and `legal-run` enables (driven 2026-09-23 with the first fixture). Both appear with counters. Click each role tag to cycle it (PATCH roles): the redline to counterparty draft, the draft to prior turn.
- **Wrong format.** Upload a .txt with both sides filled, before or after a matter exists: the studio refuses it before `POST /api/v1/legal/matters` (`refusedUpload`, `apps/web/components/legal-studio.tsx:71`, called from `onFiles` at `:138`), so no empty matter is left behind. The exact message “Only .docx files are accepted in v1. Convert PDF or other formats to .docx first.” appears in `legal-error`, `legal-file-row` stays at its previous count, and **no `POST /files` reaches the host** — the check is client-side (`apps/web/lib/legal-client.ts:336-338`). The studio's pre-check (`refusedUpload`) takes the sentence from `legal.errors.docxOnly`, so it is localized whether or not a matter exists yet; see [Gotchas](#gotchas).
- **Cleanup (mandatory on a shared desk).** The drive leaves a matter behind, and a refused upload leaves one too. Read the id from `GET /api/v1/legal/matters`, then `DELETE /api/v1/legal/matters/:matterId` (expect `200 {"ok":true}`), reload `/legal` and confirm `legal-reopen` and `legal-previous-row` are back to count 0 and `<dataDir>/legal/<workspaceId>/<matterId>/` is gone.
- **Run without a key (keyless or stub desk only; PAID on a keyed desk).** On a keyed desk (the operator's `:3000`, `runtime: "ai"`) `legal-run` starts a live multi-phase review that bills, so stop after the upload and role steps there. Click `legal-run`. The wire shows `PATCH /api/v1/legal/matters/:id` (save-before-run) then `POST /api/v1/legal/matters/:id/run/stream` → **200**, and `legal-error` carries the stub copy. `legal-progress` and `legal-cancel` stay at count 0 and `legal-studio` keeps `data-screen="new"` — the run never reaches the running screen.
- **Live run.** Only after doctor `ai`: `legal-progress` streams classify → diff → review n/m → missing → interactions → draft → verify (at least one “Round r of 3”) → edit → package, then lands on the results screen with a non-empty `legal-tab-adverse` (`legal-finding-row`). `legal-cancel` stops a run mid-phase.
- **Redline.** Download the redline (`legal-download-<kind>`) and open it in Word. Tracked changes are authored as the configured author with margin comments; Accept All produces the proposed language.
- **Deviation report.** Download the deviation report (`legal-download-<kind>`). It opens in Excel with a Deviations and a Summary sheet.
- **Handoff.** Send to Knowledge Base creates a `Memo` source. Open in Documents prefills the Documents studio.
- **Reopen.** Reopen the matter from Previous matters; the last run's results load.
- **Locale (id).** With the desk on `id` (see [locale.md](./locale.md)), the empty `/legal` reads `Jalankan perkara` (`legal-run`); the rail entry reads `Hukum`. Do not look for the uppercase `PERKARA` any more (a case-sensitive check for it failed on 2026-10-01): the panel label is the mixed-case `Perkara` (`legal.matter.panel`, drawn through `.panel-label`, which is `text-transform: none`, `apps/web/app/globals.css:551-558`), so `Jalankan perkara` is the proof string. `Perkara baru` appears only once a matter exists (screen 1 button, no testid) or on the result screen (`legal-new-matter`), and `Perkara sebelumnya` is the previous-matters panel heading. The `.docx` refusal is localized: the studio pre-check shows `t("legal.errors.docxOnly")` (`apps/web/components/legal-studio.tsx:74`), so an `id` desk reads `Hanya berkas .docx yang diterima pada v1. Ubah PDF atau format lain ke .docx terlebih dahulu.` (`apps/web/locales/id/legal.json:31`) and it can serve as a locale proof. The English sentence survives only behind that check: `LEGAL_DOCX_ONLY_MESSAGE` (`apps/web/lib/legal-client.ts:17`, the client library's own guard) and the host's refusal copy (`packages/core/src/legal/output-copy.ts:66`, `id` text at `:160`). Testids are locale-invariant.

## Gotchas

- v1 accepts .docx only. A .txt or .pdf is refused with the exact sentence above — a refusal, not a crash, and nothing joins the matter. The studio's pre-check shows the localized `legal.errors.docxOnly` (`apps/web/components/legal-studio.tsx:74`); the hardcoded English `LEGAL_DOCX_ONLY_MESSAGE` (`apps/web/lib/legal-client.ts:17-18`) is now only the client library's own guard behind it.
- A refusal by the **host** (a renamed `.docx` that fails the zip-magic sniff, `packages/host/src/legal/store-files.ts:163-165`) is a different path: HTTP 400 `unsupported_content_type` with the localized `unsupportedFile` copy (`packages/core/src/legal/output-copy.ts:66`, id at `:160`).
- The matter is created **lazily** on the first accepted upload (`ensureMatter`, after `refusedUpload`). There is no matter row to assert before a file is dropped; a refused `.txt` no longer leaves an empty matter (fixed 2026-09-23). Clean it up with `DELETE /api/v1/legal/matters/:matterId` — there is no UI control for it.
- **Clean up your matter with the route, not the UI.** `deleteLegalMatter` exists (`apps/web/lib/legal-client.ts:322-325`) but no component calls it; the only references are in its own test. `DELETE /api/v1/legal/matters/:matterId` returns `{ ok: true }` and `rmSync`s the matter folder (`packages/host/src/legal/store.ts:173`) — but it leaves `<dataDir>/legal/<workspaceId>/` behind as an empty directory, so check for the *matter* folder, not the workspace one.
- **Role cycling is a whole-matter PATCH.** There is no `/files/:docId` role route. The tag sends `PATCH /api/v1/legal/matters/:matterId` with `{ roles: [{ id, role }] }` (`apps/web/components/legal-studio.tsx:177-180`). From the `context` default the first click lands on `counterparty-draft`, then `our-draft`, `prior-turn`, `executed`, `instruction`, `playbook`, `figures`, `precedent`, back to `context` (`nextDocRole`, `apps/web/lib/legal-view.ts:155-158`) — so "the draft to prior turn" is three clicks, not one.
- **`legal-cancel` is a client-side abort**, not a route (`apps/web/lib/use-job-stream.ts:58-61`). There is no cancel endpoint to poke.
- **The per-file cap is 25 MB**, tighter than the 40 MB in `LEGAL_CAPS` because it matches the desktop IPC envelope (`packages/host/src/legal/store-files.ts:24`). Matter total is 100 MB and 60 files. A second upload of the same bytes is HTTP 409 `conflict` (sha256 match, `packages/host/src/legal/store.ts:186-192`).
- **A run needs both parties, not a title.** `canRun` is `docs > 0 && partiesReady(draft) && !uploading` (`apps/web/lib/legal-view.ts:114-116`), matching the host's `sideSchema`; an untitled matter is saved as `legal.studio.untitled`.
- `legal-run` stays disabled until a file is uploaded **and** both the client party and the counterparty are set. A disabled Run is that gate, not a hang.
- A stub / no-key run is never a silent no-op, but it is **not an HTTP 503** — `/api/v1/legal/matters/:id/run/stream` answers 200 and `runtime_stub` / `status: 503` ride inside the single `job.error` frame (SKILL.md **Harness-wide gotchas** G2). Two different gates can stop a run: a saved-but-disallowed key trips `requireGatewayAllowedFor(tenant)` first and returns a real HTTP 403 `gateway_blocked` with no stream at all (`packages/host/src/handlers/legal.ts:114`); no key at all reaches `requireLive` inside the job (defined at `packages/host/src/legal-generate.ts:62`, called at `:241`).
- There is no separate Settings link on `legal-error`: `SettingsLinkHint` is appended only when the message does not already match `/settings/i` (guard at `apps/web/components/legal-studio.tsx:363`, `SettingsLinkHint` at `:366`), and both `stubError` catalogs name Settings in the sentence itself (`packages/core/src/legal/output-copy.ts:65`, id at `:159`), so the guard is always false. Assert the copy, never a hint link.
- `legal-download-<kind>` fetches `/api/v1/artifacts/:id/file`. On desktop that is a native save, so no browser download event fires — assert the file on disk.
- `legal-side` and `legal-work-type` are segmented controls, `legal-deliverable-<kind>` are checkboxes. Do not look for a select for either of them; the selects on this page are `legal-playbook`, `legal-studio-model`, `legal-studio-verifier-model` and `legal-reopen`.
- `studio.title` stays **Legal** in `id`. Do not use it as a locale proof string — on the empty screen use `Jalankan perkara` (`legal-run`); the panel label is the mixed-case `Perkara`, not the old uppercase `PERKARA`. `Perkara baru` is not on the empty screen; it needs a matter (screen 1) or the result screen (`legal-new-matter`).
