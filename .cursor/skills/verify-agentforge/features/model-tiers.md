# Model tiers

Since PR #157 (2026-10-12) Chat offers three choices instead of a model list: **Daily** (the default), **Fastest** and **Reasoning**. In the chat-first shell the choice is a chip in the agent's header beside its name (`chat-header`), and the composer is only `+`, the message box and Send; before that shell the same control sat in the composer toolbar. The trigger `tier-picker` shows the current choice's label and nothing else, and its panel `tier-picker-panel` lists the three as `tier-option-daily`, `tier-option-fast` and `tier-option-reasoning`, each with a line on what it is for. A send carries `{ content, tier }` and never a model, a Thinking flag or a reasoning level; the host turns the tier into a model and the renderer is never told which. The reasoning-effort select is gone, because the tier sets Thinking (Fastest is Off, Reasoning is Deep, Daily is the model's default). **The steps in [models.md](./models.md) that drive `model-picker`, `model-group-recommended`, `model-best-for` and `reasoning-effort` do not apply to the chat-first shell on `:3000`**; they apply only to the `"modes"` fallback layout, where those controls still exist. Spec: [`docs/internal/model-tiers-spec.md`](../../../../docs/internal/model-tiers-spec.md). The host half (the catalog, the walk, the mask test) is its own track; this file covers what the person sees and what the browser posts.

Product: both · Instance: main :3000 + HYP AI :3301

## Sub-features

- `tiers-picker` is `tier-picker`, the trigger in `chat-header`, beside `agent-name` (the header passes it as `tier`, `chat-session.tsx:424`, and `AgentChatHeader` draws it in `agent-chat-tier`, `agent-chat-controls.tsx:67`). The composer draws none: it gets no `onTierChange` in this shell (`chat-session.tsx:525`), so `composer` holds no `tier-picker`, and `composer-toolbar` and `composer-controls` are no longer rendered at all (only their dead rules remain in `globals.css`). If a pane ever passes `onTierChange` to the composer, the picker is a row under `composer-plus`, not in a toolbar (`chat-composer.tsx:672-680`). Its visible text is exactly `Daily`, `Fastest` or `Reasoning` (`Harian`, `Tercepat`, `Penalaran` in `id`), with a decorative chevron; its `aria-label` is `Answer style: <label>` (`Gaya jawaban: <label>`). It carries `aria-haspopup="listbox"` and `aria-expanded`. It wears the old picker's `model-picker` and `model-picker-trigger` classes; they are layout hooks left from the toolbar (in the header, `.agent-chat-tier .model-picker` makes it only as wide as its word, `agent-chat.css:47-55`), not a model picker. It is disabled while a send is running, and while the host has listed no tiers.
- `tiers-panel` is `tier-picker-panel`, portalled to `document.body` and placed by `placePickerPanel` (`apps/web/lib/picker-panel.ts`), holding one `[role="option"]` per tier with its `tier-option-<id>` testid, `aria-selected` on the current one, and `aria-disabled="true"` on one the host reports unavailable, which also shows `Unavailable` (`Tidak tersedia`). There is no search box, no group and no check for a model name.
- `tiers-keyboard` Enter or Space on the trigger opens it (an arrow key does too); focus moves to the list. ArrowUp and ArrowDown move the highlight and wrap, Home and End jump, Enter or Space chooses the highlighted tier unless it is unavailable, Escape closes and returns focus to the trigger, Tab closes and returns focus to the trigger, and a click outside closes without moving focus. Choosing a tier closes the panel and returns focus to the control that has a place for it: in the composer's old form (the picker under `+`, which passes `returnFocusRef`) that is `composer-text`; in the header, which passes none, it is the `tier-picker` trigger (`tier-picker.tsx:169`, from `focusAfterClose`, `model-picker.tsx:73-80`). Expect the trigger.
- `tiers-default` a person who never opens the picker is on Daily. A new thread starts on the last tier the person chose (`localStorage["agentforge-chat-tier"]`); an existing thread restores the tier it last sent with (`localStorage["agentforge-chat-thread-tiers"]`, a map of thread id to tier, at most 80 threads). A stored value that is not a tier id, or a tier the host now reports unavailable, is skipped.
- `tiers-body` the run request. `POST /api/v1/threads/:id/runs/text` (and `runs/image`, `runs/video` for an attachment) has the body `{ "content": ..., "tier": "daily" | "fast" | "reasoning" }` and no other key. The enhance-prompt request carries no `model`. Code: `apps/web/lib/chat-tier-body.ts`.
- `tiers-thinking-row` the reply's Thinking row follows the tier: it shows for Daily and Reasoning and not for Fastest (`tierThinkingEnabled`, `apps/web/lib/chat-tier-pref.ts`).
- `tiers-context` the context chip's window and the attachment types the composer accepts come from the chosen tier's `contextLength` and `inputModalities` in the catalog the host sent, not from a model.
- `tiers-unavailable-error` a refused send with `503 { error: { code: "tier_unavailable" } }` shows `composer-error` with the catalog's sentence (`That choice is not available right now. Pick another one and send again.`; `Pilihan itu sedang tidak tersedia. Pilih yang lain lalu kirim lagi.`), never the host's own message, which can name a model.

## How to get to it (user POV)

- Open `http://127.0.0.1:3000/chat`.
- The agent's header (`chat-header`) shows a chip reading `Daily` beside its name. Click it to see the three choices, pick one, then type in the message box. No `+` click is needed.
- Nothing about it is in Settings. There is no model name anywhere in Chat.

## Driving it with the Nultron harness

Preconditions:

- Doctor exits 0 on `:3000`.
- `GET /api/v1/chat` answers `tiers` (three entries, each `{ id, available, inputModalities, contextLength }`) and `defaultTier: "daily"`. Until the host's tier catalog is in, `tier-picker` renders disabled and a send still names `daily`; that is a host gap, not a renderer fail.
- Read `localStorage["agentforge-chat-tier"]` and `["agentforge-chat-thread-tiers"]` before touching the picker and restore both at the end. A throwaway Playwright profile starts empty.

- **Present, and the old controls absent.** On `/chat`, `tier-picker` is inside `chat-header` and visible, and its visible text is `Daily`. It is not inside `composer` (count 0 there). `model-picker`, `model-picker-prefix` and `reasoning-effort` have count 0. `composer-toolbar` and `composer-controls` have count 0. `composer-enhance` is still in the DOM, but inside `composer-plus-menu`, which is `hidden` until `composer-plus` is clicked. The same chip is in the header of `/chat?agent=research`.
- **Open with the mouse.** Click `tier-picker`. `tier-picker-panel` appears, `tier-picker` has `aria-expanded="true"`, `document.activeElement` is the list (`[role="listbox"]`), and three `[role="option"]` rows exist with `tier-option-daily` selected. Press Escape: the panel is gone, `aria-expanded` is `false`, and focus is on `tier-picker`.
- **Open with the keyboard.** Focus `tier-picker` with Tab and press Enter (then, in a second pass, Space, then ArrowDown). The panel opens with focus in the list. ArrowDown twice lands on `tier-option-reasoning`; Enter chooses it. The panel closes, the trigger reads `Reasoning`, and focus is on `tier-picker` (the header passes no composer to return to; on the old composer form it was `composer-text`). Open again and press Tab: the panel closes and focus is on `tier-picker`.
- **Outside click.** Open the panel, click empty page space. The panel closes and focus is wherever the click put it.
- **What a send posts.** Capture requests (Playwright `page.on("request")` filtered to `/runs/text`, or the network log). With nothing picked, the body parses to exactly `{ content: "<the text>", tier: "daily" }`. Pick Fastest and send: `tier` is `fast`. Pick Reasoning and send: `tier` is `reasoning`. In every case `Object.keys(body)` is `["content","tier"]`: no `model`, no `thinking`, no `reasoningEffort`. Attach an image (when the tier's `inputModalities` includes it) and send: the `/runs/image` body has the same two keys.
- **Memory.** After sending a thread on Fastest, click `new-chat-link` in the header: the trigger reads `Fastest` (the last choice seeds the next thread). Open the first thread again from the Conversations popover (click `agent-history-toggle`, then its `thread-item`; the rail has no session list in this shell): it reads `Fastest`; pick Reasoning there, go to another thread and back: it reads `Reasoning`.
- **Thinking row.** Send a prompt on Fastest: the live reply shows no Thinking row. Send one on Reasoning: it shows one.
- **Unavailable tier.** Route the catalog request in the browser (`GET /api/v1/chat` for the generalist; a Research pane reads its tiers from `GET /api/v1/models`, `chat-session.tsx:263-275`) (Playwright `page.route`) to answer `reasoning` with `available: false`. Open the panel: `tier-option-reasoning` has `aria-disabled="true"` and reads `Unavailable`; clicking it, or highlighting it and pressing Enter, chooses nothing and the panel stays open. Route the run to `503 { error: { code: "tier_unavailable", message: "x" } }` and send on Daily: `composer-error` shows the catalog sentence, not `x`.
- **Languages.** In Settings choose Bahasa Indonesia, restart as the banner says, and read the trigger (`Harian`), the three options (`Harian`, `Tercepat`, `Penalaran`) and the hints. Restore English.
- **Widths.** At 1280, 600, 470 and 375 px the chip sits in the header beside the agent's name without clipping and without overlapping the name or the three header controls (the quiet chips beside them hide under 52rem of header width; the tier chip does not, `agent-chat.css:78-84`). At 375 the panel stays inside the window (its left edge is at least 8 px, its right edge at most `innerWidth - 8`), every row is at least 44 px tall, and the hint wraps instead of clipping. Check light and dark.
- **Evidence.** Screenshots of the closed trigger, the open panel (light and dark), the 375 px panel and the network capture of one body per tier, under `evidence/model-tiers/<run-id>/`.

Status: driven on `:3000` on 2026-10-12 (`evidence/model-tiers/2026-10-12-maintain/`). Options `tier-option-daily` (selected), `-fast`, `-reasoning`; `aria-label` `Answer style: Daily`; Escape returns focus to `tier-picker`; request bodies were `{content, tier}` only (`daily`, `reasoning` aborted before any model call, `fast` sent for real: "pong" in 7.7 s, no Thinking row); a new chat seeds the last choice. ## Gotchas

- The tier picker is not `model-picker`. The published code's model recipes ([models.md](./models.md), `chat-model-switch` in [chat.md](./chat.md)) are not valid on `:3000`, and a drive that clicks `model-picker` there will time out.
- `SHELL_LAYOUT` `modes` is the only layout with the model picker and the Thinking select; `:3000` is `chat-first`.
- The wrapper's class is `tier-picker model-picker` on purpose. `.model-picker` in `globals.css` was the composer toolbar grid's slot for the choice control, and a selector for `.model-picker` still matches the tier picker here, now in the header. Use the testids.
- The header chip is `disabled` while a turn runs (`chat-session.tsx:424`, `disabled={running}`), so a script that changes tier mid-run finds it inert.
- Do not look for a model name. The host never sends one, so a drive that wants to prove "which model answered" has no renderer-side evidence; the mask test the spec names is `packages/host/src/model-mask.test.ts` (the host track's), and the host's logs are where an operator reads the id.
- The stream watchdog names the tier ("No first token from Reasoning after 240s"), and Daily and Reasoning get the long budget (240 s first token, 180 s idle) because the renderer cannot tell whether the model behind them thinks quietly. Fastest keeps the short one.
- `chat.tiers.*` keys are built at run time (`chat.tiers.${id}.label`), so the literal-key scan cannot see them; `apps/web/lib/chat-tier-locale.test.ts` holds both catalogs to the registry instead.
- The Thinking CSS (`.composer-thinking*`) is still in `globals.css` and unused by the composer. A selector for it matches nothing.
- Playwright is not run locally in this repo. `apps/web/tests/e2e/foundation.spec.ts` was edited for the tier picker and has not been run.
