## 2026-09-21 — Meeting: the pipeline actually runs, driven against the live gateway

- **The bug the owner saw.** Meeting produced no minutes and no translation. Both legs were real code; neither was ever reached, because the run died at the first phase. The fault was arithmetic, not the gateway: `timeoutForMedia` turns a probed duration into milliseconds (`2 * 65.556063 * 1000 + 30_000` = `161112.126`), and `child_process.execFile` refuses a non-integer `timeout` with `ERR_OUT_OF_RANGE` **before spawning anything**. The catch-all in `packages/host/src/edit/ffmpeg/run.ts` reported that as `ffmpeg_failed` / "ffmpeg recipe failed", so every recording whose audio was not a whole number of seconds long — i.e. every real recording — failed at `extracting` with an error blaming ffmpeg for a request ffmpeg never received. `runFfmpeg` now rounds the budget up once, for every caller, and the failure message carries the exit code and the tail of stderr. **`packages/host/src/edit/ffmpeg/recipes.ts` had the same arithmetic**, so Edit's probe, extract and render recipes were broken the same way for any clip of fractional length.
- **Second root cause: the model the picker chose cannot transcribe on this gateway.** `mimo-v2.5-asr` is not in the live catalog (139 ids, 2026-09-21), so `pickTranscriptionModel` fell through to `qwen3-livetranslate-flash`, which answers `503 get_channel_failed` — "Supply pool unavailable" — as do `qwen3.5-omni-flash` and `qwen3.5-omni-plus`. `gpt-audio` answers `200` with a refusal sentence. So even with ffmpeg fixed, transcription could not have succeeded.
- **What works, proven with one short chunk each:** `gemini-3.5-flash` (verbatim, and the only id that labels speakers), `gpt-audio-mini` (verbatim, fastest), `gpt-audio-1.5` (verbatim when streaming; non-streaming wraps the text in a JSON object), `qwen3-omni-flash-2025-12-01` (verbatim, and only with a data URI). `TRANSCRIPTION_PREF` is now that order, pinned by `packages/core/src/meeting/asr-model.test.ts` against a catalog snapshot.
- **The request shape is per model family, which cost a live 400 each to learn.** The OpenAI audio family takes bare base64 in `input_audio.data` and answers `400 invalid_value` to a data URI; the DashScope-backed qwen/omni family takes a `data:` URI and answers `400 InvalidParameter` ("The provided URL does not appear to be valid") to bare base64, and is asked to stream. `transcriptionShapeFor` (core) returns wire + encoding + stream; the new `packages/host/src/meeting/transcribe-request.ts` builds the call and accumulates SSE deltas.
- **One dead model no longer kills a run.** Transcription walks a chain: a model that refuses, times out or answers with nothing is dropped and the next is asked, and the first that answers is preferred for every remaining chunk. A pinned `AGENTFORGE_MEETING_ASR_MODEL` still means exactly one model. A `200` with no text counts as a refusal, which is how `gpt-audio`-style soft refusals are caught.
- **Three review findings from PR #66 closed.** `isTranscriptionModelId` now refuses every `*-realtime` id (WebSocket only), TTS ids, and anything whose `mediaKind` is image, video or other — the `usable[0]` fallback that could hand a meeting to a video model is gone (finding 2); the omni family sends `stream: true` (finding 3); a caller's abort signal is now *composed* with the 300 s per-request budget instead of replacing it, so a hung gateway call no longer waits for the browser to disconnect (finding 7). Gateway refusals now reach the SSE `job.error` frame naming the model and repeating the gateway's own message.

## 2026-09-21 — Portal fix pass X: sign-out that signs you out, and mail that is not in the clear

Eight findings from the Phase 9 review round, each a failing test first. Register rows
[SR-21](security-register.md#sr-21), [SR-33](security-register.md#sr-33) and the new

- **Signing out now signs you out.** The portal kept a 30-day browser session of its own that nothing
  could end, so after signing out of the app, pressing **Sign in** signed the same person straight
  back in with no address and no code — and on a shared browser, signed in the *next* person as the
  last one. Three halves: a portal `GET`/`POST /logout` that clears the cookie on every answer and
  redirects only to a URI on the client's registered origin; a per-user version counter
  (`web_session_versions`, migration 0009) carried in the cookie, so `POST /auth/logout` with

  sending the browser through that portal logout and back to `/sign-in`. Both paths audit
  `web_session.revoked`. **Everyone signed in at deploy time signs in once more:** a cookie minted
  before the version field existed is refused rather than trusted.
- **Mail is never sent in the clear.** The SMTP transport passed `ignoreTLS` whenever
  `PORTAL_SMTP_SECURE` was off, which means "never attempt STARTTLS" rather than "TLS if offered" —
  so a real provider on 587 would have received the sign-in code and the SMTP AUTH user and password
  on a plain socket. STARTTLS is now **required** for any host off loopback, `ignoreTLS` survives
  only for the Mailpit sandbox, and production refuses to start on a cleartext mail host.
- **`GET /tenant/config` stopped being a tenant-name oracle.** It had no rate limiter and answered
  400 for an unknown slug and 403 for a suspended tenant, so a wordlist enumerated the portal's
  whitelabel partners. One refusal for both now, and a per-IP limiter on both branches.
- **`PORTAL_PUBLIC_URL` and `PORTAL_TRUST_PROXY` are validated at boot**, in `loadConfig` with every
  other variable. The public URL must be a bare origin — https anywhere, http on loopback only — and
  is **required in production**, because the access token's `iss` is built from it. A typo in the
  trust-proxy flag is a boot error instead of a silent "off".
- **Smaller ones.** `pnpm portal:seed --redirect` refuses anything but https, or http on loopback
  (it used to accept `javascript:` and `data:` into the allowlist `/authorize` redirects to with a
  code). A request body over the 64 KB ceiling answers `413` with the standard error body rather than
  `500`. The dead `state_mismatch` branch on authorization codes is gone — the host's `__Host-`
  cookie is the real `state` control and always was — with the `state_hash` still stored for audit.
  `scripts/review-instance.ps1` no longer seeds the literal Postgres password `portal`; it keeps what
  `review.env` holds, generates one for a fresh review root, and stops with an instruction when the
  volume already exists (harness, never ships).

## 2026-09-21 — deploy note: the hosted server cannot be restarted on this code until six variables are set

**Read this before the next restart of the hosted deployment.** `assertHostedEnvComplete`
(`packages/host/src/hosted-env.ts`) runs at boot, before `server.listen`, and **throws** when the
hosted environment is incomplete. A container started with `AGENTFORGE_SERVER=1` and any of the
following missing does not serve a degraded app — it does not start, `GET /healthz` never answers,
and Caddy's active check keeps the previous container in place while the log carries the only
explanation.

Required in hosted mode:

- `AGENTFORGE_PORTAL_URL` — https, judged by `assertAllowedEndpointUrl`.
- `AGENTFORGE_PORTAL_CLIENT_ID` and `AGENTFORGE_PORTAL_CLIENT_SECRET` — the app's confidential
  OAuth client at that portal. The portal prints the secret once.
- `AGENTFORGE_SECRETS_KEY` — the wrap key, 32 bytes of entropy; there is no `.master-key` fallback
  in server mode.
- At least one **https** entry in `AGENTFORGE_TRUSTED_ORIGINS` that survives the allowlist. Server
  mode drops cleartext and anything that is not an origin, and an empty list means every mutating
  `/api` call 403s.
- On `NODE_ENV=production` only: `AGENTFORGE_BILLING_WEBHOOK_SECRET`. Off production its absence is
  a startup warning rather than a refusal.

`webapp-deploy/.env.example` said until today that the three portal variables could be left empty
because that "changes nothing today". It has been rewritten: that sentence predated the boot check
and was false from the moment it landed. Security register [SR-46](security-register.md#sr-46).

- **One declared harness per mode.** Every product mode has a spec (loop, tools, budget, repair rounds) in `packages/core/src/harness/modes/`, indexed by `MODE_HARNESS_SPECS` (`specs.ts:19`). Chat gets 12 steps and 40 tool calls, with caps of 20 `write_file`, 20 `edit_file`, 10 `delete_file`, 8 `web_fetch` and 6 `run_code`. Data keeps 6 steps and 60 calls, with `run_sql` at 8 and `run_code` at 4. Every other mode keeps the old 6 steps and 60 calls. A call past a tool's cap returns a budget refusal to the model instead of running (`runtime/tool-budget.ts`, `invokeToolGuarded`).
- **Check gates.** `runChecked` (`packages/host/src/harness/run-checked.ts`) runs a mode's checks and hands the failures back as an ERROR / WHY / FIX note, at most `repairRounds` times. Documents (structure, grounding), Presentation (slide count, content, duplicate titles, fit), Research synthesis (every finding cites a given source, no empty section) and Meeting minutes each get one repair round. Finance and Legal keep their own loops. Edit gets a budget and cancel only. Images, Videos, Music and Education have no model loop.
- **Cancel reaches the model call.** The job runner, Chat and the Edit agent now pass the caller's signal to the runtime, so a cancel aborts the request in flight and no later call starts. Two single calls still ignore a cancel: prompt enhance (`handlers/enhance-prompt.ts:63`) and the Knowledge map (`knowledge-map.ts:133`, `:155`). Details in the SR-75 update.
- **File tools.** `list_files`, `read_file`, `write_file`, `edit_file`, `search_files` and `delete_file`, each with a `root` argument that defaults to `desk`, bound to Chat. Caps: 2 MB a file, 2,000 live files a desk, 2,000 lines a read, 500 list entries. `edit_file` is compare-and-set, so two parallel edits give one `saved` and one `conflict` (SR-125).
- **Desk files.** Versioned, sealed text files per desk: tables `desk_files` and `desk_file_versions` (migration `0022_desk_files.sql`), bodies stored through the tenant object store so the quota counts them, routes under `/api/v1/files` (list, read, versions, save, revert, soft delete), a Files section in the Knowledge Base page. History only grows, a revert writes a new version, and deleting a desk purges its files. Version count is not capped (SR-118).
- **`knowledge_search`.** Chat only. Returns up to 4 excerpts of at most 1,200 characters (8 at most), and is refused when the key gate is closed (`packages/host/src/knowledge-search-tool.ts`).
- **`run_code`.** Python (pandas, numpy) or JavaScript in a WASM sandbox, bound to Chat and Data: one hardened child process per sandbox, no network, 30 s wall clock, 512 MB for Python and 256 MB for JavaScript, text files in by desk path and out through `/workspace/out`, saved as agent versions. Data treats the output as a lead and re-runs its own SQL for every figure. Network containment is not an OS rule (SR-111).
- **Documents and Presentation read desk files.** Up to five desk files join the pasted source, read by the host and not by the model, under the same injection guard and 120,000-character ceiling (`packages/host/src/desk-sources.ts`, `MAX_SOURCE_FILES`). Documents, Presentation and Open Slide use it, through `apps/web/components/desk-source-picker.tsx`.
- **Data provenance fix.** A Data artifact saved `queries` as a count where the schema wants a list, and the store dropped the whole metadata object (question, model, dataset). `knownField` now drops only the wrong field (`packages/core/src/artifacts/artifact-meta.ts`), and Data saves the SQL it ran, each statement cut at 2,000 characters (`data-generate.ts:74`, `:200`, `:321`). Artifacts saved before this fix may have empty metadata and are not repaired.

### Personal only

- **Folder root, picker and approvals.** Chat can open one real folder per desk. The folder button calls `agentforge:pick-folder` (`apps/desktop/main.cjs:584`), the mount is accepted over IPC only, and the file tools take `root: "folder"`. Reads are contained by real path and refuse `.env*`, key files, `.git`, `.ssh` and similar names. A write or delete is a proposal the owner approves from a diff card, refused as `stale` if the file changed since, at most 50 pending. Routes are under `/api/v1/folder`. Open register rows: SR-114, SR-115, SR-116 and SR-127. Fixed on the way: a deleted desk's proposals are purged (SR-126).

### Enterprise only

- **Hosted caps.** `run_code` allows 2 runs at once, 1 per tenant and 2 warm children in all; `AGENTFORGE_MAX_CODE_RUNS` and `AGENTFORGE_MAX_CODE_RUNS_PER_TENANT` raise the first two (`packages/host/src/code-runner/limits.ts:50-59`). Desk files count toward the tenant quota. Regex `search_files` is refused in server mode because it blocks the one event loop (SR-117). The folder root is unavailable.
- **The sandbox in the image.** The build stage runs `scripts/build-sandbox-runtime.mjs` into `/opt/sandbox-runtime`, the runtime stage copies it root-owned and read-only to `/app/sandbox`, and the image sets `AGENTFORGE_SANDBOX_DIR=/app/sandbox` (`webapp-deploy/Dockerfile`). The five Python wheels are the only download, pinned by sha256 in `scripts/sandbox-runtime.lock.json`. No egress deny exists for the child yet (SR-111, SR-97), and the child's memory is not sized against the pod limit (SR-123).

## Findings from the verify-skill maintenance pass, 2026-10-05 (product bugs, not fixed)

Found while driving every recipe on `:3000` (host started from this tree), on a throwaway no-key instance and on the Phase 0 pilot compose stack (images built 2026-10-02). Evidence: `.cursor/skills/verify-agentforge/evidence/<feature>/2026-10-05-maintain/`. None of these is a security flag.

- **A non-`ok` gate verdict never heals (both products, highest impact).** `needsGatewayRefresh` re-checks in the background only an `ok` verdict past its TTL (`packages/host/src/gateway-gate.ts:559-567`). An `unreachable` or `error` verdict stays on disk, and once `lastOkAt` is older than the 7-day grace, `deriveGatewayGate` closes the desk (`:327-330`). On `:3000`, one timeout on 2026-10-03 closed the whole desk for two days while the gateway answered normally. The screen said "We couldn't reach Toko Token" until a manual Re-check. A packaged Personal app hits the same path after one blip, and so would a hosted tenant.
- **Settings Save with a blank key field forgets the key (Personal and webdev).** The form posts `openaiApiKey` on every save (`apps/web/components/settings-page.tsx:284-289`). Off server mode a blank is forwarded (`keyFieldValue`, `packages/host/src/handlers/settings.ts:226-234`), and `mergeSecrets` deletes the key (`packages/core/src/secrets.ts:137-139`). So changing only the Edit turn cap, or pressing Enter in it, signs the desk out of the gateway. The code comment calls this intended ("clearing the field still means forget my key"), but the field is empty whenever a key is saved. Traced in source; not driven, because it would wipe the operator's key.
- **Finance loses 1 px of scroll per rail detour.** `/finance` at 1440x560: set the pane's `scrollTop` to 60, then switch to another mode and back; it reads 59, 58, 57. Legal keeps its value exactly. Cause not found.
- **Finance shows a vague error, or none, on a closed gate.** The code-only parses (cash flow, budget, appraisal, ratios) call no model, but the route is gated first (`packages/host/src/handlers/finance.ts:52`). Under a 403 the renderer shows only "Could not read those figures", and for budget nothing in `finance-error`. On Personal a closed gate replaces the app with onboarding, so this matters on hosted "Add it later".
- **Empty box above the key form after a component install.** The panel hides 4 s after it finishes (`apps/web/components/component-setup.tsx:58-66`). Its wrapper `onboarding-setup-check` stays (`apps/web/components/onboarding-screen.tsx:293`) because `visible` is `component !== null` (`apps/web/lib/use-component-setup.ts:126`). That leaves a bordered heading with no body. Driven with the host's answers faked; it only appears where the bundled reader fails and a real download runs, such as a packed mac build.
- **Model label casing.** `gpt-oss-120b` shows as "GPT Oss 120B" because `ACRONYMS` has no `oss` (`packages/core/src/models/curation.ts:28`).
- **Portal: "we already sent a code" after a send that failed.** After `code_mail_failed`, "Send a new code" within 60 s answers 429 "We already sent a sign-in code…", though nothing was delivered. The cooldown reads the failed attempt's time (`newestSentAt`, `apps/portal/src/otp/send.ts:119-122`). Driven on the pilot with its Mailpit down.
- **Portal: a mail outage holds every send for about 8 s before the 503** (invite redeem, invite resend, member code). Driven on the pilot.
- **Pilot rehearsal: Mailpit does not come back after a Docker restart.** It is the only long-running pilot service with `restart: "no"` (`webapp-deploy/compose.local.yml:82`); the other `"no"` belongs to the one-shot `portal-prepare` step (`webapp-deploy/compose.yml:303`). After the Docker engine restarted it stayed `Exited`, and every sign-in failed with `mail_send_failed … ENOTFOUND mailpit`. This affects the rehearsal stack only.
- **Dead locale key.** `auth.account.tenant` ("Account", `apps/web/locales/en/auth.json:34`) is never rendered.
- **Observation, not a bug.** On the live key, a Chat work card read "Saved. Live embeddings timed out, so this source is on a l…". That is the `embed_local` fallback (a 4 s timeout, then 5 minutes of local vectors, `packages/host/src/knowledge-embed.ts:30-37`), and the card is still searchable by keyword.
