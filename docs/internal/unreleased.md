## Chat can make a PowerPoint deck, and desk files can be downloaded, 2026-10-06 (both products; uncommitted, worktree `agentforge-deck`)

Branch `feat/chat-deck-tool` from `main` at `6105c5c`. Both changes reach Personal and Enterprise through the shared renderer and host. Not committed, not packed, not driven in a browser or on a live model. Maps: [`agent-tools-and-files.md`](maps/agent-tools-and-files.md) § 13, § 8 and § 11, and [`presentations.md`](maps/presentations.md) § 10. Recipes: `features/chat.md` (`chat-deck`, tool-row step 3b) and `features/files.md` (`file-download`).

- **New: `build_deck` for Chat** (`packages/host/src/deck/`). The model writes the outline (title, up to 14 slides with a heading, bullets, an aside and speaker notes); the tool validates it with `parsePresentationOutlineBody`, runs `presentationChecks`, builds the file with `buildPresentationPptx` and saves it as a `presentations / draft` artifact, then answers `{ ok, artifactId, filename, slideCount }`. No model call inside the tool. A failed check answers `{ ok: false, reason: "checks", message }` with the ERROR, WHY and FIX note, so the model repairs and calls again (4 calls a turn). The prompt names it in one sentence and says to write in the language of the conversation.
- **New: PPTX is an artifact type.** `PPTX_MIME` joins the catalog and the binary set (`packages/core/src/artifacts/artifact-meta.ts`), so the existing `GET /api/v1/artifacts/:id/file` route serves a deck with the right type, an attachment name and the inert headers.
- **New: the deck card under the answer** (`apps/web/components/chat-deck-card.tsx`). Title, slide count, file name, the first four headings, **Open** (the Presentation mode's read-only preview in place, no second renderer) and **Download** (`downloadArtifactFile`, which opens the native save dialog in the packaged app). It sits outside the Thinking disclosure and is rebuilt from the saved tool call, so a reopened thread shows it. The Thinking row stays one line.
- **New: `GET /api/v1/files/download?path=`** (`packages/host/src/desk-files/routes.ts:122`). The newest version of one desk file as an attachment, with the same desk, tenant and path checks as `/content`, `nosniff`, `Content-Security-Policy: sandbox`, `Cache-Control: no-store` and a plain-text type (`.html` and `.xml` go out as `application/octet-stream`). Security register SR-140.
- **New: Download controls for desk files.** `file-download` in the Files viewer (newest version only) and `tool-row-file-download` beside the chip of a saved write and beside each file a `run_code` row saved.
- **Changed: the saved-result picker hides Office files** (`textArtifacts`). It fills a text box, and a Word, Excel or PowerPoint artifact is base64. Legal's Word and Excel artifacts were offered there before.
- **Limits that apply to a deck.** The artifact body cap (4 MB of base64, about 3 MB of file), 14 slides, the per-field text ceilings (enforced by the host and explained to the model, not by the tool's schema; see the review fixes below), and on the hosted server the tenant storage ceiling, which now counts saved artifacts.
- **Tests.** Host: `deck/build-deck.test.ts`, `deck/build-deck-tool.test.ts`, `desk-files/routes.test.ts` (download cases, server mode and off it), `download-wire.test.ts` (a real socket, the hosted router with its session gate, and the header composition) and a new row in `tenancy-harness.test.ts`. Renderer: `lib/download-clients.test.ts` (the two client calls on the web and over the IPC bridge), `lib/deck-card.test.tsx`, `lib/tool-rows.test.tsx`, `lib/files-render.test.tsx`, and `server/deck-download.test.ts`, which runs both client functions against the real host over a real socket and over the shell's IPC conversion.
- **Not proven.** No click in a browser, no live model calling `build_deck`, no packed app: the shell's `host:save-bytes` half (the dialog and the write) was read, not run. A hosted drive behind the proxy is owed: the release Caddyfile may replace the route's `Content-Security-Policy` (SR-132).

### Review fixes, 2026-10-07 (same branch, still uncommitted)

A review said "ship after named fixes". The High and the three Medium findings are fixed, test first; the two Low findings are open. Security register SR-140 carries the evidence. Nothing here was driven in a browser, on the hosted box, on a packed app or against a live model; the tests are host and renderer unit tests, one of them through the real AI SDK with a replaced `fetch`.

- **Fixed (High): a model that overruns a limit no longer ends the turn.** The SDK checks a tool call's arguments against the tool's schema before `execute`, and a failure there became `run.failed`. `buildDeckInputSchema` (`packages/host/src/deck/deck-schema.ts`) now keeps only the shape (a title, a list of slides, a heading on each; a slide kind it does not know reads as `bullets`) and says each limit in words in the field descriptions. `buildDeckForTenant` enforces the limits through `deck-limits.ts` and answers `{ ok: false, reason: "limits", message }`: every overrun in one message (`slides[1].notes is 2100 characters; the limit is 2000`), ten at most, then "and N more". Text is measured after trimming and cleaning, and a bullet that is only blank is dropped. `DeckRefusal` gains `limits`; the renderer reads no reason, so nothing changed there. Proof: `deck/build-deck-run.test.ts` (a model overruns, is refused, calls again and gets the deck; first seen red with "Invalid arguments for tool build_deck") and `deck/build-deck-limits.test.ts`. The old "answers too_large" test could no longer reach that branch with real input, so it became `deck/build-deck-too-large.test.ts` with a stubbed exporter.
- **Fixed (Medium): a deck or a Presentation export is never written with a character XML cannot hold.** A form feed from a PDF, a NUL or an escape code went into the slide XML and PowerPoint said the file needed repair while the tool said `ok`. `stripXmlIllegalChars` (`packages/host/src/xml-text.ts`) removes them (form feed and vertical tab become a space) and runs in the deck path and in the Presentation outline schema (`presentation-outline.ts`), which every path to the exporter parses through. Proof: `xml-text.test.ts` (all 65,536 code units), `presentation-outline.test.ts`, `presentation-pptx.test.ts` and `build-deck-limits.test.ts`, which open the zip and read every XML part. Not checked: the docx and xlsx exporters for the same flaw.
- **Fixed (Medium): saved artifacts count toward a hosted tenant's storage.** `tenantStorageReport`, `assertStorageAdmits` and the budget `putTenantObject` reserves against now include `SUM(size_bytes)` of the tenant's artifacts (new report field `artifactBytes`); `build_deck` asks about the stored size, the base64 text, not the file inside it. **Server mode only**: a desk's number is unchanged and its report never reads the table. No quota number changed.
  - **Effect on existing hosted desks.** On the first request after deploy, `usedBytes` rises by what the tenant's artifacts already hold (dossiers, briefs, drafts, decks), with no migration and no recompute, and the Settings storage card moves with it. A tenant that was within that much of the ceiling is refused its next upload or deck until it deletes something; reads, deletes and every other route are unaffected. Artifacts written before `size_bytes` existed hold 0 and count as 0. Text results are kilobytes each, so for most desks the change is small; a desk full of decks is the case it was made for. I did not read any real desk's artifact sizes. To see what it will do before deploying, run `SELECT o.tenant_id, SUM(a.size_bytes) FROM artifacts a JOIN workspaces w ON w.id = a.workspace_id JOIN organizations o ON o.id = w.organization_id GROUP BY o.tenant_id` on the box.
  - **A new index, created on open, on a hosted server only.** `size_bytes` follows the body in each row, so summing it from rows with megabyte bodies walked every overflow page: about 2 seconds for 100 decks, in a synchronous call that stops the host (measured in a scratch database). `artifacts_ws_size_idx (workspace_id, size_bytes)` is created by `ensureArtifactTables` (`packages/db/src/ensure-schema.ts`) on every open when `AGENTFORGE_SERVER` is on, `IF NOT EXISTS`, and the sum drops under a millisecond. A desk never gets it (nothing reads the sum there), so Personal's schema and its first open after an update are unchanged (`ensure-schema.test.ts`, "leaves a desk's artifacts table as it was"). It is not a numbered migration on purpose (no row changes, safe to repeat, no slot in a journal other branches are adding to) and is not declared in `schema.ts`, so `drizzle-kit generate` would not emit it. The first hosted open after deploy builds it, which reads every artifact row once. The plan is pinned by `tenant-artifact-use.test.ts` and `ensure-schema.test.ts`.
  - **Still not gated.** The other artifact writers (research, documents, finance, legal, meeting, open slide, presentation, data) do not call `assertStorageAdmits`, so a tenant at the ceiling can still save a text result there; two builds in flight can overshoot by their own size; the counted size is the plain text and the sealed row is larger; and Settings' "largest" list shows media only, so decks are deleted from the Presentation page.
- **Fixed (Medium): a failed save in the packaged app is no longer silent.** `saveDesktopBytes` returns the shell's `{ ok, reason }`; `apiFetch` throws a `DesktopSaveError` (`apps/web/lib/desktop-save.ts`) when `ok` is false and the reason is not `canceled`. The deck card shows the sentence (`common.saveFailed.*`), the files viewer shows `files.errors.saveFailed`, and the studios that print an error message print it, all in English and Indonesian. A closed dialog stays silent; a shell that answers nothing (older) reads as saved. `apps/desktop/main.cjs` was not changed. Proof: `lib/desktop-save.test.ts`, `lib/desktop-bridge.test.ts`, `lib/download-clients.test.ts` (first seen red with the wiring line disabled). The shell's real write was not run.
- [ ] **Open (Low): the hosted Caddyfile replaces the download routes' `Content-Security-Policy`** (SR-132, SR-140). `attachment` and `nosniff` still stop a browser rendering the file, but the `sandbox` these routes set never arrives. Fix: a path-matched `header` in the Caddyfile for `/api/v1/files/download` and `/api/v1/artifacts/*/file`, and a line in `check-app.sh` that reads it back. Both live outside this repo.
- [ ] **Open (Low): the deck's title-slide kicker follows the desk language, not the conversation's** (`presentationKicker` through `presentationLocale()` in `packages/host/src/presentation-pptx.ts`). Pass a locale from the tool in a later change.
- [ ] **Open question for Rizky: `build_deck` works on a desk that does not have Presentation switched on**, so the deck lands in a list that desk has no screen for.
