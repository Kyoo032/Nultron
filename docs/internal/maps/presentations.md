## Overview

Presentation is a job. A topic goes in the prompt bar, the model returns one JSON outline, and the renderer paints the current slide large, with a filmstrip and a properties panel. A second route turns the same outline into a `.pptx`. The owner edits the title, heading, and bullets on the slide, and inserts rectangle, rounded rectangle, ellipse, triangle, line, arrow, star, callout, and text. Those boxes are dragged and resized, then written into the PPTX by `addOwnerShapes` (`packages/host/src/presentation-pptx.ts:35`). There is no pen, table, chart, or slide master.

The outline still starts in React state (`apps/web/components/presentations-studio.tsx:74`). Save writes it to `presentation-decks/<workspaceId>/deck_*.json` (`packages/host/src/presentation-decks.ts:37`, `POST /api/v1/presentations/decks` at `packages/host/src/router.ts:369`). Reload clears the open deck until `presentations-deck-open` reads it back. A starter still produces a PPTX with no gateway key.

The first screen is a topic box, length and style chips, and Create (`presentations-studio.tsx:490-515`). Everything else sits in More (`presentations-more`, `:520`), including which builder makes the slides (`presentations-engine`, `:542`). The default builder is Open Slide (`engine` starts as `"open-slide"`, `:77`), so Create drafts a deck on a stub desk. Nultron is the previous stage and is what a starter in More still opens. Open Slide is a port of the MIT open-slide authoring rules (`packages/core/src/open-slide/THIRD-PARTY-NOTICES.md`): a 1920×1080 JSON deck, not React source. Education does not show the Presentation builder. Its lesson uses the same simple stage (`variant="simple"` at `apps/web/components/education-studio.tsx:423`) and keeps its own More (`education-more`).

The two builders differ in what the host does after the model answers. A **Nultron** outline is done when it reads as an outline and passes four pure checks, with one repair round if it does not; a repair call that fails keeps the first outline, and an outline that still fails a check ships with a note. It then goes through the design pass (§ 3c): a note where one is blank, a bullet or figure the source did not give replaced, a layout for every slide, and one more ask for only the crowded slides. An **Open Slide** deck has no structure checks, because its pages are free-placed blocks with no heading or bullets to look at (`packages/host/src/presentation-checks.ts:9-11`); it gets the length, source and notes skills and the same design pass (§ 9). Both builders accept the pasted source and up to five desk files as sources, and both Create calls stream their phases (`presentations-progress`).

### 3. Generate: prompt bar to `POST /api/v1/presentations/stream` to one JSON outline

`onGenerate` (`presentations-studio.tsx:226`) clears `checks` and branches on `engine`. Both builders run through `job.run` on `useJobStream` (`:66`), so the host's phases reach the screen. Nultron posts `{ prompt, model?, modelPinned?, sourceText?, sourceFiles?, slideCount? }` to `/api/v1/presentations/stream` (`:254-277`) and Open Slide posts to `/api/v1/presentations/open-slide/stream` (`:237-243`), both through `apiFetch`, so webdev and the packaged app share one call. The plain JSON routes `POST /api/v1/presentations` and `POST /api/v1/presentations/open-slide` stay for a direct caller and call the same functions. While the stream runs, `JobProgressList` draws `presentations-progress` (`:704`): the phase list and, after a failed check, a `Round 1 of 1` line. A stream that ends in `job.error` shows through `shownError` (`:373`) in `presentations-error` (`:469`), and a result lands through `landOutline` (`:100`, `:281`) with its `checks`. The prompt is the topic plus a localized "Keep it {length} and {style}." line built from the two chip rows (`presentation.shapeNote`, `:255-270`). The chips do not set `slideCount`. `slideCount` comes from `presentations-slide-count`, a text field in More that is shown only for Nultron (`:547-569`) and parsed by `readSlideCountInput` (`apps/web/lib/presentation-checks.ts:86`): empty is no count, a whole number from 2 to 15 is sent, anything else is not sent and the field is marked invalid (`presentations-slide-count-hint` turns red), so a typo never becomes a 400.

`handlePostPresentationsStream` (`packages/host/src/handlers/jobs.ts:236`) and `handlePostPresentations` (`:223`) both resolve the tenant and call `requireGatewayAllowedFor(tenant)` (`:238`, `:227`) **before** anything else. A closed gate is a flat `403 gateway_blocked` here, never a failed model call, and on the stream route it is that JSON refusal, not an SSE event. The stream handler wraps the job in `streamJob` and hands it `emit` and the abort signal (`:239-242`); the plain one calls `generatePresentationOutline(tenant, body, undefined, request.abortSignal)` (`:228`). Both functions take `(tenant, body, emit, abortSignal)`, the order Research, Data and Finance use.

`generatePresentationOutline` (`packages/host/src/presentation-generate.ts:356`) then:

1. `readPrompt` (`:80`): a missing or blank `prompt` is a 400.
2. `readSlideCount` (`:103`): absent is `null`. A value that is not a whole number from `MIN_REQUESTED_SLIDES = 2` to `MAX_REQUESTED_SLIDES = 15` (`presentation-checks.ts:26-27`) is a 400 `invalid_request`. The number counts the title slide. `withSlideCount` (`:122`) tells the model so in words: "N slides in total, counting the title slide, so "slides" holds exactly N-1 items".
3. `requireLivePresentationRuntime` (`:173`): `resolveRuntimeMode({settingsHasKey: hasLiveProvider(settings), envRuntime})`. Stub throws `ApiError("runtime_stub", presentationGatewayMessage(locale), 503)`. **This is the state on an unkeyed desk** and the one the harness proves.
4. `assembleDeskSource` (`packages/host/src/desk-sources.ts:175`, shared with Documents, see [`documents.md`](documents.md) § 3a): the pasted `sourceText` (trimmed, capped at 120,000 characters with a visible `[source material truncated at cap]` marker, run through the injection guard unless `settings.injectionGuardBypass` is on) plus up to five `sourceFiles` under headers, within the same ceiling.
5. `resolvePresentationModel` (`:185`): body `model` wins, then `settings.presentationGenModel`, then `defaults.presentations`. `readModelPinned` (`packages/host/src/job-regen.ts:49`) says whether the person picked it; a picked model is never swapped by the fallback.
6. `runChecked` (`:379`) runs the outline call and the checks, see § 3a. The `OUTLINE_SYSTEM` prompt (`:63`, `{languageRule}` substituted by `outlineSystem`, `:128`) asks for the requested count and otherwise 8 to 12 content slides (max 14), a heading of 6 to 14 words, 3 to 5 bullets of 10 to 22 words, and notes of 40 to 90 words. If no attempt ever read as an outline, the held attempt's own `invalid_outline` 502 is thrown here (`:424-426`). Each repair round is announced as `job.round` (`onRound`, `:417-419`, labelled by `presentationRepairLabel`, `presentation-locale.ts:38`).
7. `designOutline` (`:309`, called at `:429`) runs the design pass on what `runChecked` returned, see § 3c. The model is not asked again unless a slide is crowded.
8. The result is rendered as markdown by `presentationOutlineMarkdown` (`packages/host/src/work-cards.ts:217`) and saved as an artifact (`persistOutline`, `:196`, `mode: "presentations"`, `kind: "draft"`) whose `meta` holds `question`, `model` (the model that answered), `slides`, `sourceFiles` (when any), `repairRounds` (when a repair was spent) and `failedChecks` (the codes still failing, `:442-449`). It is then ingested as a `Presentation` work card (`upsertWorkSource` and `artifactWorkCard`, `:450-455`). **Both are best-effort:** `persistOutline` swallows its own error and logs `presentation_outline_not_saved`, and no artifact means no ingest, but the outline is still returned.
9. The return is the plain outline when every check passed, else `{ ...outline, checks: notes }`, read off the outline the design pass returned (`presentationCheckNotes`, `:439`; `:456`, type `PresentationOutlineResult`, `:251`).

Every model call goes through `collectJobAssistantRun` (`job-regen.ts:252`) with `jobMode: "presentations"` (`presentation-generate.ts:166`), which is what applies the mode's job knob from the model policy (`jobThinkingExtras`, `packages/core/src/models/job-thinking.ts:30`). **This is the opposite of Chat, which deliberately sets no `jobMode`** (see [`chat-send.md`](chat-send.md#4-runtime--probe-stream-coerce) and [`model-policy.md`](model-policy.md)). A `run.failed` event becomes a `502 generation_failed` (`job-regen.ts:224-226`).

#### 3a. The checks and the repair round

`runChecked` (`packages/host/src/harness/run-checked.ts:71`) is the generic gate: `produce` makes the output, every check looks at it, and a failure goes back to `produce` as an `ERROR` / `WHY` / `FIX` note for at most `repairRounds` more tries. Presentation takes `repairRounds` from `harnessSpecFor("presentations")` (`presentation-generate.ts:372`), which is **1** (`packages/core/src/harness/modes/presentations.ts:15`).

`produce` (`presentation-generate.ts:380-414`) makes one call per round, and keeps `held` outside the loop: the last reply that read as an outline, or else the last reply there was (`:377`), plus `lastText`, the raw text a repair quotes back (`:378`). `readAttempt` (`:254`) reads each reply with `parsePresentationOutline` (`packages/host/src/presentation-outline.ts:133`) into an `Attempt` (`:245`) that holds either the `outline` or the `failure`, an `invalid_outline` `ApiError`. It does not throw for an unreadable reply. Per call:

1. On a repair, `repairPrompt` (`:151`) appends the previous reply and the note to the same user prompt. The reply is quoted whole, with no length cap.
2. A call that throws ends in the `catch` (`:393-401`). `throwIfJobAborted` (`:395`) rethrows a cancel as the job's 499. Any other failure, with a reply already held, logs `presentation_repair_failed` and returns `held`. Only the first call can fail the request this way.
3. `throwIfJobAborted` (`:403`) stops a cancelled request before it is saved.
4. An empty reply returns `held`, or throws `generation_failed` 502 if there is none (`:404-409`). An empty first reply gets no repair.
5. `held` becomes the new attempt when it read as an outline or when nothing held did (`:412`). A repair that comes back unreadable therefore replaces `held` only if there was no outline to lose.

An unreadable first reply is repaired like any other failure. `READABLE_CHECK` (`:266`, id `readable`) fails an attempt that has a `failure`, and its note quotes the parse error and the JSON shape to return. `outlineChecks` (`:281`) puts it first and wraps the four structure checks so they pass while there is no outline to look at. The repair round that follows gets the first reply back in its prompt. If the repair is unreadable too, or the repair call fails or comes back empty, no attempt ever read as an outline and `final.failure` is thrown (`:424-426`): the repair reply's `invalid_outline` 502 in the first case, the first reply's in the other two. Nothing is saved, so the studio never sees half an outline. The unit tests pin each branch (`presentation-generate.test.ts:405`, `:413`, `:420`, `:477`, `:502`, `:510`, `:519`).

The four checks (`presentationChecks`, `packages/host/src/presentation-checks.ts:262`, in the order the repair note lists them) are pure functions of the outline:

| Check code | Fails when | Source |
|---|---|---|
| `slide_count` | The request set a count and `slides.length` differs from `slideCount - 1`; or no count was set and there are more than `MAX_OUTLINE_SLIDES = 14` content slides | `countIssue`, `:132` |
| `slide_content` | A slide has no heading, or no bullet, subhead or aside | `contentIssue`, `:140`; `hasBody`, `:113` |
| `duplicate_title` | Two slides share a heading once case and punctuation are stripped | `duplicateIssue`, `:156`; `titleKey`, `:117` |
| `slide_fit` | Text would run past its box in the exported slide | `fitIssue`, `:177`; `overflowingParts`, `:95` |

`slide_fit` is an **estimate**, not a render. It assumes 0.5 em per character (0.55 bold) and a 1.2 line height, and compares the line count against the box sizes `addContentSlide` uses (`presentation-checks.ts:47-60`, which must be changed together with `packages/host/src/presentation-pptx.ts:189` when a box moves). It runs on the layout the export draws (`resolvePresentationSlideLayout`, `:181`), not on the raw model output.

What the person sees. When a check still fails after the repair, the response carries `checks`, an array of `{ check, slides, expected?, found? }` (`presentationCheckNotes`, `:201`): codes and 1-based positions in `outline.slides`, never English. The studio reads it with `readOutlineChecks` (`apps/web/lib/presentation-checks.ts:35`), drops anything unreadable, and `landOutline` stores it (`presentations-studio.tsx:100`). `PresentationChecksNote` (`apps/web/components/presentation-checks-note.tsx:8`) renders `presentations-checks` above the preview (`presentations-studio.tsx:724`), with one `presentations-checks-<code>` item per note. `presentationCheckLine` (`presentation-checks.ts:63`) writes each sentence in the desk's language and adds one to every slide number, because the filmstrip counts the title slide and `outline.slides` does not. The note clears when the person edits a slide, rewrites one, opens a starter or a saved deck (`:95`, `:138`, `:321`, `:733`). A pass after a repair shows nothing; only the artifact `meta.repairRounds` records it. An outline kept after a failed repair call looks like any other flagged outline: the note shows, and only the host log (`presentation_repair_failed`) and `meta.repairRounds` say a repair was tried.

#### 3b. Cancel and budget

The request's `abortSignal` (`packages/host/src/types.ts:55`, set from the client disconnect at `packages/host/src/http-adapter.ts:694`) goes into every outline call (`presentation-generate.ts:391`) and every slide rewrite (`:529`). A cancel that lands during a repair call is still the 499, not a kept outline (`:395`; test `still cancels with 499 when the person leaves during the repair call`, `presentation-generate.test.ts:440`). `collectJobAssistantRun` checks it before each model call and after a failed one (`job-regen.ts:255`, `:274`), then hands it to the runtime as `signal` (`:210`), where `linkCallerAbort` aborts the request in flight (`packages/core/src/runtime/ai-sdk-runtime.ts:146`). A cancelled job is the job's own `499 aborted` (`throwIfJobAborted`, `packages/host/src/job-stream.ts:19`), thrown past the model fallback, and nothing is saved. Each run also receives the mode spec's budget (`job-regen.ts:184`, `:207`). For Presentation that is `DEFAULT_RUN_BUDGET` (6 steps, 60 tool calls, `packages/core/src/harness/defaults.ts`) and the mode binds no tools (`tools: []`), so it bounds nothing today.

#### 3c. The design pass and what the stream shows

`designOutline` (`presentation-generate.ts:309`) runs after the checks, on the outline `runChecked` returned. It first puts back what the person did not give: `repairNultronOutline` (`packages/host/src/presentation-harness.ts:218`) fills a blank speaker note with the line from `presentationSkillCopy` (`presentation-locale.ts:43`), replaces a bullet or aside that the pasted source and desk files do not support with a sentence from that source, and replaces a bullet or aside that holds a digit with "No figure supplied" when the topic, the title and the source have none. It emits `job.phase` `designing` (`:313`). `inspectNultronDesign` (`presentation-harness.ts:109`) gives each slide one layout from `title`, `section`, `split`, `quote`, `figure` (`SLIDE_LAYOUTS`, `packages/core/src/presentation/slide-design.ts:7`) and lists the crowded ones: too many bullets, a title that does not fit, or a wall of text (`slideCrowdReasons`, `:89`; limits in `SLIDE_DESIGN_LIMITS`, `:14`: a title layout is 42 characters or 8 words, any other heading 72 characters or 14 words, a wall 220 characters or 40 words, and 2 supporting lines on title, section, quote and figure against 5 on split). If any slide is crowded the pass emits `repairing` and asks once more for only those slides (`designRetryPrompt`, `:218`, `versionId: "presentation-design"`). `mergeNultronDesignRetry` (`presentation-harness.ts:164`) keeps a replacement only when every digit run was already on that slide, in the topic or in the source (`textKeepsDigitRuns`, `slide-design.ts:156`). That ask is one call and its failure is swallowed: a crowded slide is still cut in code. A cancel is not swallowed (`throwIfJobAborted` in the `catch`, so nothing is saved). Last, `repairNultronDesign` (`presentation-harness.ts:140`) writes each slide's `layout` (the optional `layout` field, `presentation-outline.ts:36-46`) and cuts what still does not fit (`fitDesignPage`). The slide count never changes.

Because the design pass runs last, the `checks` note is read off its result: a cut that leaves a slide empty or two headings equal is reported, and a check the repair round fixed is not shown again. The pass is not a fifth check, so a crowded slide the model repaired in the ask is simply not crowded any more.

What the stream shows, in order: nothing until the first reply is read; `job.round` 1 of 1 labelled `Repairing the outline` when a check failed and the repair call starts; `job.phase` `designing`, and `repairing` when a slide is crowded (`presentationDesignLabel`, `presentation-locale.ts:30`); then `job.done` with the outline and, when a check still fails, `checks`. All labels are host copy in `en` and `id`.

### 4. Preview: one stage, a slim filmstrip

Layout is not taken at face value. `resolvePresentationSlideLayout` (`apps/web/lib/presentation-outline.ts:82`) repairs decks where the model returned only `bullets` kinds: the last slide becomes `close`, the middle slide becomes `split` if it has 3 or more bullets, a `section` with 3 or more bullets is demoted to `bullets`, and a `split` with no `aside` either takes its last bullet as one (`takeAside`, `:68`) or falls back to `bullets`. The **same function also exists host-side** (`packages/host/src/presentation-outline.ts:78`) and is what the PPTX builder and the `slide_fit` check call. That is the only reason preview and export agree.

### 5. Regenerate one slide

`presentations-regen` toggles `regenOpen` (`apps/web/components/presentation-preview.tsx:215`) and mounts the shared `JobRegenPanel`, which is where `presentations-regen-panel` / `-prompt` / `-model` / `-file` / `-attach` / `-submit` come from (`apps/web/components/job-regen-panel.tsx:118`, `:135`, `:143`, `:156`, `:186`, `:202`). Opening the panel makes **no** request. In the studio the button lives in More, on the current content slide only. Education does not pass `onRegenerate`, so the lesson has no rewrite button.

Submit uploads any held image through `POST /api/v1/media`, inlines any held `.txt` into the instruction, then `onRegenerate` (`presentations-studio.tsx:293`) POSTs the **whole outline** plus `slideIndex`, the studio prompt, the instruction, the model pick, attachments, `sourceText` and `sourceFiles` to `/api/v1/presentations/regenerate` (`:301-314`, route `packages/host/src/router.ts:361`). The response replaces the outline and clears `checks` (`:320-321`).

`regeneratePresentationSlide` (`packages/host/src/presentation-generate.ts:481`) re-validates the posted outline with `parsePresentationOutlineBody` (400 if malformed), range-checks `slideIndex` (`readSlideIndex`, `:470`, 400), gates on live runtime (503), assembles the same source (`:502`), builds a prompt carrying the deck title, the other slides' headings, and the current slide's full body, appends the user instruction (`appendRegenInstruction`, `job-regen.ts:57`), runs `SLIDE_SYSTEM` (`:459`), parses one slide (`parsePresentationSlide`, `presentation-outline.ts:147`) and returns `mergePresentationSlide(outline, index, slide)` (`:169`), a new outline object, immutably replaced in renderer state. **It runs none of the four checks and no repair round**, so a rewritten slide can repeat another slide's heading or overflow its box without any note. It does get the source and layout work for that one slide: `repairNultronOutline` with `onlyIndex` (`:535-544`) fills a blank note and replaces a bullet the source does not support, then `repairNultronDesign` gives the slide a layout and cuts what does not fit (`:545-551`), and only that slide of the result is taken. It makes no second ask.

### 6. Download: the same outline, server-rendered to PPTX

`onDownload` (`presentations-studio.tsx:329`) POSTs the raw outline (or the Open Slide deck) to `/api/v1/presentations/pptx` (or `/open-slide/pptx`), reads the blob, takes the filename from `Content-Disposition`, and clicks a synthetic `<a download>`. The button is `presentations-download` (`:456`), the only primary control once a deck is open.

`handlePostPresentationsPptx` (`packages/host/src/handlers/jobs.ts:278`) is the odd one out: **no `getTenant`, no `requireGatewayAllowedFor`, no runtime check.** It validates the body and builds bytes. Nothing here reaches the gateway, but a desk with a closed gate can still export a deck it is holding.

`buildPresentationPptx` (`packages/host/src/presentation-pptx.ts:292`) defines a 13.333 × 7.5 in layout, stamps `author` and `title` from `resolvedProductName()` and the outline title, adds the title slide (`addTitleSlide`, `:131`), then one content slide per outline slide (`addContentSlide`, `:189`) through the *same* `resolvePresentationSlideLayout` the preview used. `addOwnerShapes` (`:35`) maps each kind to an Office preset and writes fill and stroke. Speaker notes become real PPTX notes (`addNotes`, `:125`). Colors are the quiet-tool tokens as Office hex (`COLORS`, `:13`). The filename is `safeFilename` (`:80`): strip non-word characters, spaces to hyphens, cut at 60 characters, fall back to `presentation.pptx`.

### 7. Locale: slide copy follows the frozen boot locale, not a picker

There is no language control in the studio. `presentationLocale()` is `localeForRun()` (`packages/host/src/presentation-locale.ts:7-9`), the app locale frozen at boot (see [`locale-boot-and-run-harness.md`](locale-boot-and-run-harness.md)). It drives three things: the `{languageRule}` line spliced into `OUTLINE_SYSTEM` and `SLIDE_SYSTEM` (`presentation-locale.ts:11-16`, applied at `presentation-generate.ts:128-134`), the 503 copy (`:22-26`), and the PPTX title-slide kicker `PRESENTATION` / `PRESENTASI` (`:18-20`). The repair note is fixed English; the language rule in the prompt carries the output language. Renderer chrome is separate: `apps/web/locales/{en,id}/presentation.json`, namespace `presentation` (singular) while the rail key stays `presentations`. The check sentences (`presentation.checks.*`), and the slide-count field (`presentation.slideCount.*`) live there. The desk-file picker is shared with Documents, so its strings are `files.deskSources.*` in `apps/web/locales/{en,id}/files.json`.

### 8. Handoff in: Research / Finance / Data / Market / Legal to Presentation

Presentation is a **handoff target**, never a source. `HANDOFF_TARGETS = ["documents", "presentations"]` (`apps/web/lib/mode-handoff.ts:11`). ### 9. Open Slide: harness, stage, PPTX

Create defaults to Open Slide. Length and style are chips on the empty screen (`presentations-open-slide-pages`, `presentations-open-slide-density`, `presentations-studio.tsx:377`, `:402`). Movement and the builder stay in More (`presentations-open-slide-motion`, `:579`; `presentations-engine`, `:542`). Those choices are the product form of open-slide's scoping questions. The aesthetic stays in the deck JSON and is not drawn on the stage.

Generate posts `{ prompt, brief: { pageCount, density, motion }, model?, modelPinned?, sourceText?, sourceFiles? }` to `POST /api/v1/presentations/open-slide/stream` (`presentations-studio.tsx:237-243`, route `packages/host/src/router.ts:364`, handler `handlePostOpenSlideStream`, `packages/host/src/handlers/open-slide.ts:35`); the plain `POST /api/v1/presentations/open-slide` (`router.ts:363`) answers the same deck as JSON. There is no `slideCount` for Open Slide: the page count is the three-way length chip. `generateOpenSlideDeck` (`packages/host/src/open-slide-generate.ts:210`) takes `(tenant, body, emit, abortSignal)`. Both handlers gate through `requireGatewayAllowedFor` first (`handlers/open-slide.ts:27`, `:38`) and pass the request's abort signal. It assembles the source first (`assembleDeskSource`, `:220`), so a bad `sourceFiles` entry is a 400 even on a stub desk, which then drafts without using the source: `draftOpenSlideDeck` (`:228`, `packages/core/src/open-slide/draft.ts:333`) opens no socket. A live runtime sends `OPEN_SLIDE_SYSTEM` (`packages/core/src/open-slide/harness.ts:6`) through `withOutputLanguage(..., "presentations", locale)` (`open-slide-generate.ts:141`, rule at `packages/core/src/output-language.ts:64`) and `collectJobAssistantRun` with `jobMode: "presentations"` and the abort signal (`collectDeck`, `:129-154`). There is **no `runChecked`**: an empty reply is `generation_failed` 502 (`:246-248`), an unreadable one is `invalid_outline` 502 (`:249-254`), and the only further calls are the length ask and the design ask below. A deck the person cancelled is not saved (`:245`, `:311`). The deck is saved as an artifact and a work card (`persistDeck`, `:174-204`) with `engine: "open-slide"`, `pages`, `model` and `sourceFiles` in its `meta`. The language is `localeForRun()`.

After the draft, `applyOpenSlideSkills` (`packages/core/src/open-slide/skills.ts`) runs before the deck is returned. It trims pages that sit above the length bracket (short 3–5, medium 6–10, long 11–12), fills an empty speaker note from `presentationSkillCopy` (`packages/host/src/presentation-locale.ts`), and, when source text is set, replaces a line the source does not support. A digit is cleared when neither the topic nor the source contains one. A live deck that is still under the bracket minimum is asked once more (`open-slide-generate.ts:256`); a second short deck is returned as-is. The stub path never opens a socket for that ask. Nultron runs the same notes and source repairs in `repairNultronOutline` (`packages/host/src/presentation-harness.ts:218`), after its checks. Its length is the request's `slideCount`, held by the `slide_count` check (§ 3a), not this bracket.

The design pass runs after those skills, with the layouts and limits of § 3c. `inspectOpenSlideDesign` (`packages/core/src/open-slide/design.ts:52`) assigns each page one layout and lists the crowded ones. Open Slide also keeps the style chip: split is capped at 1 / 3 / 5 / 5 supporting lines for minimal, light, standard, and dense (`OPEN_SLIDE_DENSITY_CAP`, `design.ts:20`). The length chip still wins: the pass never adds a page. A live desk with a crowded page emits `job.phase` `repairing` and asks once, for only those page ids (`designRetryPrompt`, `open-slide-generate.ts:55`; the ask is `:285`), and `mergeOpenSlideDesignRetry` (`design.ts:115`) keeps a replacement only when every digit run was already in the topic or the source. A stub desk emits `designing`, and `repairing` only when the draft is crowded, then `repairOpenSlideDesign` (`design.ts:63`) shortens the failing pages in code (`designDeck`, `open-slide-generate.ts:164`); it opens no socket. Code repair always runs last, so a returned deck has a layout on every page.

The stage is `OpenSlideStage` (`apps/web/components/open-slide-stage.tsx:45`). A slim filmstrip (`presentations-open-slide-filmstrip`, `:136`) sits above the canvas (`presentations-open-slide-stage`, `:163`). Pages are `presentations-open-slide-page` (`:144`). Each page and the stage carry `data-layout` from the assigned layout (`pageLayout`, `:30`; `:146`, `:165`). Blocks are `presentations-open-slide-block` (`:266`) with pixel `data-x` / `data-y` on a 1920×1080 canvas. The Nultron filmstrip and stage carry the same `data-layout` (`apps/web/components/presentation-preview.tsx:518`, `:534`, `:563`), and Education, which uses that preview, only gains the attribute. Clicking a text block edits it in place (`presentations-open-slide-text`, `:279`). Arrow keys call `nudgeOpenSlideBlock` (`packages/core/src/open-slide/deck.ts:255`), 8px, or 40px with Shift, when focus is not in the text. Color, duplicate, add text, and notes appear on `presentations-open-slide-toolbar` (`:181`) only while a block is selected. Movement is stored on the brief and not played.

Download posts that JSON to `POST /api/v1/presentations/open-slide/pptx` (`packages/host/src/router.ts:365`). `buildOpenSlidePptx` (`packages/host/src/open-slide-pptx.ts:73`) maps each page to one Office slide and writes speaker notes (`:87`). Like the Nultron PPTX route, this handler does not call the gateway (`handlePostOpenSlidePptx`, `handlers/open-slide.ts:48`). Save uses `open-slide-decks/` via `POST /api/v1/presentations/open-slide/decks` (`router.ts:367`), a different folder from Nultron outlines so a Nultron parser never reads an Open Slide file.

Not in this cut: Babel source edits, present mode, stepped motion, PDF, static HTML, remote fonts, and `svgl.app`. The harness text names no URL. A font value that contains a URL is replaced with `system-ui`.

### 10. Chat can make a deck, with no Presentation mode

Since 2026-10-06 (uncommitted, worktree `agentforge-deck`) Chat has a `build_deck` tool that borrows the host half of this mode. The model writes the outline in the chat turn, so no outline call is made here. The host first holds the call to its own limits (a title, headings, bullets, asides and notes of bounded length, at most 14 slides) and answers a readable refusal for any overrun, because the tool's schema sets none and an argument the SDK refuses would end the turn. The tool validates it with `parsePresentationOutlineBody` (§ 5), runs `presentationChecks(null)` through `runChecked` with no repair rounds (§ 3a), builds the file with `buildPresentationPptx` (§ 6) and saves it as a `presentations / draft` artifact with the PPTX type and a base64 body. A failed check goes back to the model as the ERROR, WHY and FIX note, and nothing is saved. It does not run the design pass (§ 3c): there is no source to check a bullet against and no model to ask again, so the layout is the one `resolvePresentationSlideLayout` picks at export. The tool, its limits, its answer and the card are in [`agent-tools-and-files.md`](agent-tools-and-files.md) § 14.

The card shows the deck in the transcript with `PresentationPreview` (§ 4) in its `simple` variant and no edit handlers: the same filmstrip and stage, read only. A Chat deck is not in the Presentation studio, has no saved-deck entry (`presentation-decks/`), and cannot be opened there to edit; it is a file to download. Its artifact shows in no studio list: the only reader of `listArtifacts` is the saved-result picker, which now hides Office files.

## Gotchas

- **`presentation-outline.ts` exists twice, nearly identical.** `apps/web/lib/presentation-outline.ts` and `packages/host/src/presentation-outline.ts` differ in the `ApiError` import specifier (`@agentforge/core/errors` vs `@agentforge/core`) and in two exported types only the renderer needs (`PresentationShape` and `PresentationOutlineInput`, `apps/web/lib/presentation-outline.ts:55`, `:65`). The logic is the same except one thing, added 2026-10-07 in the host copy only: every text field goes through `stripXmlIllegalChars` (`slideText`, `packages/host/src/presentation-outline.ts:10`), so the PPTX writer, which escapes markup but not control characters, is never handed a form feed or a NUL that would make PowerPoint ask to repair the file. The renderer copy does not strip, because it only draws text. Their test files are duplicated the same way, except the strip cases, which live in the host file. `resolvePresentationSlideLayout` is what makes the HTML preview, the PPTX and the `slide_fit` check agree, so a one-sided edit silently desynchronizes what the user saw from what they downloaded.
- **`/api/v1/presentations/pptx` is ungated.** `packages/host/src/handlers/jobs.ts:278` calls neither `getTenant` nor `requireGatewayAllowedFor`, unlike its two siblings at `:223` and `:248`. Nothing leaks (the body is the outline the caller already holds and nothing reaches the gateway), but it is the one presentations route a closed gate does not stop. The Open Slide PPTX route is ungated the same way (`handlers/open-slide.ts:48`).
- **A kept outline after a failed repair looks like any other flagged outline.** When the repair call throws or answers with something unreadable, the first outline goes out with its failing `checks` and `presentations-checks` shows. Nothing on screen says a repair was tried and failed. The host log has `presentation_repair_failed` (`presentation-generate.ts:399`), and the artifact `meta.repairRounds` is 1.
- **Regenerate runs no checks.** `regeneratePresentationSlide` merges the one slide, then runs the source repair and the layout fit on it (`presentation-generate.ts:534-551`), but none of the four checks, so a rewritten slide can repeat another slide's heading or overflow its box with no note. The note from the original generate is cleared on a rewrite (`presentations-studio.tsx:321`), so a rewrite also hides a failure the deck still has.
- **The two streamed jobs take the emitter first.** `generatePresentationOutline` and `generateOpenSlideDeck` are `(tenant, body, emit, abortSignal)`, like `generateResearchNotes`, and the plain JSON handlers pass `undefined` for `emit` (`handlers/jobs.ts:228`, `handlers/open-slide.ts:28`). Calling either with an `AbortSignal` third passes a signal where an emitter goes, which `tsc` refuses; `job-cancel-paths.test.ts` passes `() => {}` for that reason. `regeneratePresentationSlide` still takes `(tenant, body, abortSignal)`.
- **The design pass can undo a repair.** It runs after the checks and cuts text, so a repair that got a slide to fit can be followed by a cut that leaves it short. The `checks` note is read off the cut outline, so it is accurate, but the saved artifact's `meta.repairRounds` still counts the round.
- **The fit check is an estimate.** It counts characters against fixed box sizes (`presentation-checks.ts:47-92`), not rendered text. It can pass text a font renders wider and flag text a font renders narrower. Treat `presentations-checks-slide_fit` as a hint to open the PPTX, not a measurement.
- **The slide count counts the title slide.** `slideCount: 6` means one title slide and 5 items in `slides`. The wire note's `expected` and `found` are content slides, and `presentationCheckLine` adds one back (`presentationCheckLine`, `apps/web/lib/presentation-checks.ts:63-69`). A "6-slide" starter has 7 filmstrip entries for the same reason (`total = outline.slides.length + 1`, `presentation-preview.tsx:216`).
- **The slide-count field exists only for Nultron.** It is hidden when `presentations-engine` is `open-slide` (`presentations-studio.tsx:547`), which is the default, and Open Slide has no exact count at all, only the length chip.
- **One desk-file picker, one refresh rule.** Presentation and Documents mount the same `DeskSourcePicker` with the same `desk-sources*` testids ([`documents.md`](documents.md) § 2). Both panes stay mounted once visited, so scope a testid to `presentations-studio`. Both re-read the desk on every form focus through `refreshKey` (§ 2). Both warn with `desk-sources-over` when the picked files and the pasted text pass 120k, and both cut or skip files quietly when a long pasted block fills the ceiling.
- **Open Slide ignores the source on stub, but still reads it.** `generateOpenSlideDeck` assembles the source before it checks the runtime (`open-slide-generate.ts:220`, `:226`), so a missing desk file or a flagged file is a 400 on a stub desk, and a valid source changes nothing in the drafted deck.
- **The model dropdown is empty and disabled for the first few hundred ms.** `useJobModel` starts at `models: []` (`apps/web/lib/use-job-model.ts:97-98`) and `ModelSelect` disables itself while the list is empty (`apps/web/components/model-select.tsx:63`). A drive that asserts `presentations-studio-model` *visible* passes instantly; one that reads its options must wait for them. Measured on the desk of 2026-09-29: 0 options at first paint, 101 after `/api/v1/models` resolved.
- **The "Open Settings" link is suppressed on an English desk, on purpose.** The condition at `presentations-studio.tsx:472` is `matches gateway|api key|settings|runtime_stub|live gateway` **and** `does not match settings`, and the English 503 copy already says "...in Settings" (`packages/host/src/presentation-locale.ts:26`). The Indonesian copy says "Pengaturan", so the link *does* render there. Same banner, different anatomy per locale.
- **Two error vocabularies for the same wall.** The host 503 string lives in `presentation-locale.ts:22-26`; the renderer also ships `presentation.gatewayError` with the identical sentence in both catalogs, with **zero references** anywhere in `apps/` or `packages/`. Same for `presentation.kicker` (the kicker is produced host-side by `presentationKicker`). Dead keys that look authoritative.
- **Regen posts the entire deck, every time.** `presentations-studio.tsx:301-314` sends the whole `outline` object plus `slideIndex`; the host re-validates it (`parsePresentationOutlineBody`) and returns a whole new outline. There is no per-slide id and no server-side deck state; the client is the source of truth between calls.
- **The regen panel survives its own failure.** After a 503 the panel stays open, the preview stays rendered, and `presentations-error` appears at the top of the studio, not inside the panel.
- **A failed generate clears the deck on screen.** The catch in `onGenerate` sets `openDeck` or `outline` to `null` (`presentations-studio.tsx:282-288`) before it sets the error, as Documents does.
- **The starter path writes nothing.** Starters are constants in `apps/web/lib/job-starters.ts`; loading one creates no artifact, no thread, no KB card. Only a *successful live generate* persists (`presentation-generate.ts:442-455`). A harness run on a stub desk therefore leaves the owner's data untouched even after a PPTX download.
- **The deck dies on reload, not on navigation.** `WorkModeKeepAlive` keeps the component mounted across rail switches, so the outline survives Chat to Presentation round trips; `F5` clears it because nothing is persisted client-side either.
- **Presentation sends `jobMode`, Chat does not.** `presentation-generate.ts:166` and `:525` pass `jobMode: "presentations"`, which turns on the job knob for quiet families (`packages/core/src/models/job-thinking.ts`). Chat deliberately leaves it unset. Do not "fix" one to match the other.
- **`sourceText` is guarded like a Chat attachment.** Pasted or handed-off material runs through `scanInjection` (`packages/host/src/job-source.ts:23-35`) unless the owner turned the guard off, so a hostile dossier pasted into the source box is a 400, not a prompt. A desk file passes the same guard.
- **`presentations-prompt` is a `<textarea>`.** `presentations-studio.tsx:428-438` (rows 2 or 3), unlike `documents-prompt`, `research-prompt`, `images-studio-prompt` and `videos-studio-prompt`, which are single-line inputs that drop newlines from a prefilled brief.
- **The generate path now has unit tests, the assembled system prompt still has none.** `presentation-checks.test.ts` pins the checks and `presentation-locale.test.ts` the language rule, but nothing asserts the whole `OUTLINE_SYSTEM` that reaches the model. This is blocker P13's Presentation half (`docs/internal/blockers-2026-09-15.md:21`).

## Why

**Why the mode accepts source material and a handoff at all.** `[Direct]` `docs/internal/0.14.22-changelog.md:9` scopes the change as "an optional source-material input on Documents and Presentation, a renderer handoff between modes", and `:11` records the host half: "`document-generate.ts` / `presentation-generate.ts` accept `sourceText` on generate and regenerate and add the 'use only supplied material' rule to the system prompt." `[Direct]` the plan item that drove it, `docs/internal/research-dossier-analyst-modes-plan.md:37` (A5), and the owner's stated priority at `:3`: "Research dossier as a portable Markdown artifact that feeds Knowledge Base, Presentation, and Documents." Confidence: high.

**Why the outline is also saved as an artifact and ingested.** `[Direct]` `docs/internal/0.14.23-changelog.md:15`: `document-generate.ts` and `presentation-generate.ts` "now also persist a `draft` artifact in mode `documents` / `presentations`, then ingest `artifact:<id>`; the returned draft / outline shape is unchanged." The "shape is unchanged" clause is why `persistOutline` is allowed to fail quietly. Confidence: high.

**Why Presentation names its `jobMode` while Chat does not.** `[Direct]` `docs/internal/0.14.26-changelog.md:135`: "Every studio names its mode at its `collectJobAssistantText` call (finance, documents, presentations, research, data, market, legal) ... Chat never sets it and its body is unchanged byte for byte." `[Supported]` `docs/internal/blockers-2026-09-15.md:231` closes P6 with the same list. The reasoning for the asymmetry is recorded in [`chat-send.md`](chat-send.md#why): Chat's effort is a visible user choice. Confidence: high.

**Why the slide locale is read from the i18n core rather than a per-job field.** `[Direct]` `docs/internal/0.14.26-changelog.md:21`: "Presentation reads the slide locale from the i18n core." `[Direct]` `:73` records the renderer half of the same sweep: `presentation-preview.tsx` title localized, "(also fixed its missing `useProductBrand` import, a runtime crash on HEAD)", and "Presentation example gallery (`presentation.json` gained `galleryTitle` / `galleryHint` / six `templates.*`)". That commit is why the gallery has locale copy at all. Confidence: high.

**Why the editor is a stage and still not a full canvas.** `[Direct]` `docs/product-modes.md` Presentation: the owner edits title, heading, and bullets on the slide and places nine shape kinds that are dragged, resized, and written into the PPTX.
