## Overview

This page answers one question for each kind of data on the box: where do its bytes sit, which docker volume holds them, does the backup take them, and what would a move to COS or a restore need. Read it before a new file, table or folder is written on the box.

Two facts shape everything below:

- The app container has one data volume, `hyp-ai-data`, mounted at `/data` with `AGENTFORGE_DATA_DIR=/data` (bundle `compose.yml:28, 42`). Nearly every row is a table in `/data/agentforge.sqlite` or a folder under `/data`.
- A backup is one encrypted tar of `/data`, minus `components`, `logs` and `.master-key` (bundle `backup.sh:62-65`), plus one encrypted `pg_dump` of the portal. Anything outside `/data` and the portal database is not in the backup unless its row says so.

Citations without a repo folder (`backup.sh`, `compose.yml`, `DEPLOY.md`, `install.sh`, `env.template`, `Caddyfile`, `server-setup/README.md`) are bundle files. The repo checker does not read them, so re-read them when the bundle changes.

The object-store layout is in [`tenant-object-storage.md`](tenant-object-storage.md), and the tenant directory layout is in [`tenant-storage.md`](tenant-storage.md). This page does not repeat them.

## Gaps found

- **G1. The archive holds the database twice.** `backup.sh` stages a snapshot at `/data/.backup-staging/agentforge.sqlite` (bundle `backup.sh:34, 53`), then tars all of `/data` (bundle `backup.sh:62-65`), so the archive holds the live `agentforge.sqlite` and the snapshot. Restore moves the snapshot over the live file (bundle `restore.sh:65-70`), so a restore reads the consistent copy. The staging folder is removed after the archive is written (bundle `backup.sh:74`). The cost is archive size, not consistency.
- **G2. Knowledge uploads stay on the box under both backends.** This is by design: readers find an upload by scanning the folder for a `<sourceId>-` prefix (`packages/host/src/knowledge.ts:588`), because the stored name is the mangled filename (`packages/host/src/knowledge.ts:632`) and cannot be rebuilt; the object store has no list-by-prefix call. The folder is a quota root instead (`tenantJobRoots`, `packages/host/src/tenant-storage.ts:349-371`). A COS move leaves them behind, so a restore from the bucket misses them.
- **G3. Edit scratch and renders are local paths, not object keys.** A finished render is returned as a disk path (`packages/host/src/edit/ffmpeg/recipes.ts:303`, `packages/host/src/edit/jobs.ts:244`) and served from disk (`packages/host/src/handlers/edit.ts:565-575`). `resolveGenerateAsset` (`packages/host/src/edit/jobs.ts:281-349`) may accept an absolute scratch path as an asset id. Not driven.
- **G4. Presentation and Open Slide decks are keyed by workspace id only.** `packages/host/src/presentation-decks.ts:22` and `packages/host/src/open-slide-decks.ts:22` use no tenant prefix. Neither is counted in quota (`packages/host/src/tenant-storage.ts:349-371`) or erased (`packages/host/src/tenant-reset.ts:172-181`). The deck routes (`packages/host/src/router.ts:407-410`, `packages/host/src/handlers/presentation-decks.ts`) have no server-mode gate; they call `getTenant` only. Erasing a tenant leaves these folders behind. It is not a cross-company read: `getTenant` resolves the workspace only among the signed-in company's desks (`packages/db/src/portal-owner.ts:319-325`). The security register has no row for it yet; the row belongs on main with the fix.
- **G5. `studio-meta.json` stays on disk under COS.** It is written with `writeFile` under the media root (`packages/host/src/studio-media-meta.ts:45-48`) and is an explicit exception in `packages/host/src/tenant-storage-writers.test.ts:108`. A COS box keeps its media in the bucket and its index on disk.
- **G6. Key custody, not location (downgraded).** The hosted boot refuses to start without `AGENTFORGE_SECRETS_KEY` (`apps/web/server/boot-order.test.ts:112-124`), so the box runs on the env var, not the fallback file (`packages/db/src/vault-key.ts:37-51` reads the env first). `.master-key` is still excluded from the archive (bundle `backup.sh:64`), and the key is not in any backup (bundle `DEPLOY.md:174`), so its only copy is the operator's (G7).
- **G7. Off-box copies depend on the operator.** The hourly cron is documented (bundle `DEPLOY.md:156-160`), but `install.sh` installs none (no cron line in it). The daily disk snapshot is not set up (bundle `server-setup/README.md:47`). The bucket copy runs only when `COS_BACKUP_BUCKET` is set (bundle `backup.sh:106-107`, `env.template:64`). Without it, both archives sit on the single disk (bundle `DEPLOY.md:156`). The keys are copied by hand (bundle `DEPLOY.md:68`).
- **G8. Caddy and components volumes are not backed up.** `backup.sh` takes `/data` and the portal dump only (bundle `backup.sh:62-65`). Components are excluded on purpose (bundle `backup.sh:63`) and are re-fetched. Caddy state is not kept.
- **G9. Customer text is plain in the database.** Knowledge chunks and vectors, edit tables, dataset rows and channel messages are not sealed (`docs/internal/security-register.md:1137, 1193`; `packages/db/src/schema.ts:610, 736-845`). The archive is protected only by `backup.key`.
- **G10. Tester-only tables are not on the box yet.** Board (`packages/db/src/board-schema.ts:26, 45-106`), projects (`packages/db/src/projects-schema.ts:20, 62-90`), `doc_versions` (`packages/db/src/doc-versions-schema.ts:7-10`) and `doc_proposals` (`packages/db/src/doc-proposals-schema.ts:7-10`) are on `tester/chat-first`, not on main. HYP AI imports from main (`hypey/intake/SYNC.md`, outside this repo), so the 14f05d5 image does not have them. They reach the box only after a promotion pull request to main and the next HYP AI import.

## Rules for new storage

1. **Tenant bytes go through `putTenantObject`** (`packages/host/src/tenant-storage.ts:597`) with a key from `tenantRelativePath` (`packages/host/src/tenant-paths.ts:75`). A write that joins `mediaRoot()` within six lines of a write call fails the writers test (`packages/host/src/tenant-storage-writers.test.ts:117-118`).
2. **Seal what a person wrote** with `sealPayload` or `encryptJson` and `getLocalVaultKey()` (`packages/host/src/artifacts.ts:131`, `packages/host/src/settings-store.ts:301`). If a column stays plain, say so in `docs/internal/security-register.md`, as SR-155 does.
3. **A new tenant-scoped folder under `/data`** is archived automatically. It must also be added to erase (`tenantPurgeSharedRoots`, `packages/host/src/tenant-reset.ts:172-181`) and, if it holds tenant bytes, to quota (`tenantJobRoots`, `packages/host/src/tenant-storage.ts:349-371`). Otherwise erasing a tenant leaves it behind, as G4 shows.
4. **A new SQLite table with tenant rows** goes in one of `CASCADED_TABLES` (`packages/db/src/tenant-purge.ts:61-95`), `WORKSPACE_SCOPED_TABLES` (`packages/db/src/tenant-purge.ts:105-125`), `TENANT_SCOPED_TABLES` (`packages/db/src/tenant-purge.ts:128-142`) or `KEPT` (`packages/db/src/tenant-purge.ts:150` onward).
5. **Nothing new goes in `/opt/agentforge/components` or `/data/logs`.** Both are excluded from the archive on purpose (bundle `backup.sh:63`).
6. **A new docker volume, mount or host folder gets a row in the table above** in the same change. A row with a blank cell is wrong; write "Not checked" instead.
7. **A new kind of backup target** (another volume, another database) needs an entry in `backup.sh` and a restore step, or a row here that says it is not backed up.

## Moving to COS later

1. **Switch the backend** with `AGENTFORGE_STORAGE=cos`, `COS_MEDIA_BUCKET` and `TENCENT_REGION` (`packages/host/src/tenant-storage-cos.ts:90-92`). The server refuses to start the backend without a bucket (`packages/host/src/tenant-storage-cos.ts:89-105`), so there is no silent fall back to disk.
2. **Keep the keys.** Objects use the same `tenants/<id>/...` key as on disk (`packages/host/src/tenant-paths.ts:75-84`, `packages/host/src/desk-files/file-store.ts:238`), so a one-off copy of `/data/media/tenants/` to the bucket keeps every reference valid. No mover exists (`docs/internal/maps/tenant-object-storage.md:206`); the copy is a step to write and prove, not an option to flip.
3. **Decide the rows that stay on disk.** Knowledge uploads, edit scratch and renders, datasets, meetings, legal, channels, both deck folders and `studio-meta.json` are not behind `tenant-storage.ts`. Each needs an answer before the switch.
