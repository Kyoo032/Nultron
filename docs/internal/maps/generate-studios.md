## Overview

Two sibling pages, `/images` and `/videos`, that turn a prompt plus a few knobs into a file in a local gallery. They are **generate studios, not editors**: there is no canvas, no layers, no timeline (that is `/edit`), and no chat thread. Each one is a single fetch-on-mount for its own list, a form, and a grid.

The thing to hold onto: **a studio never goes through the chat run pipeline.** It posts to its own route (`POST /api/v1/images` / `POST /api/v1/videos`), which calls the platform generate tool *directly* — no thread, no run row, no SSE. The `/runs/image` and `/runs/video` routes next door look related and are not: they are attach-and-analyse, and they demand an `image_url` / `video_url` content part rather than producing one.

The second thing: **whatever the gateway returns is mirrored before the user sees it.** The renderer only paints host-served media, so the studio's success path ends with a local `/api/v1/media/<id>/file` path, never the vendor's URL. That half of the story is [`renderer-media.md`](renderer-media.md); the price line above the button is [`media-cost-estimate.md`](media-cost-estimate.md). This page is the spine the two of them hang off.

## How it works

### 1. Getting there, and staying there

On the legacy shell, `mode-images` / `mode-videos` on the left rail are `mode-${href.slice(1)}` buttons (`apps/web/components/app-rail.tsx:312-325`, `testId` at `:321`). The chat-first shell renders `AgentRail` instead (`apps/web/components/app-shell.tsx:35-36`); its own buttons are the Chat agent and agent rows (`apps/web/components/agent-rail.tsx:130`), so a studio is reached by its route there. The route maps to a component in `WORK_MODE_COMPONENTS` (`apps/web/components/work-mode-keep-alive.tsx:21-36`): `/images` → `ImagesStudio`, `/videos` → `VideosStudio`.

`WorkModePanes` (`apps/web/components/work-mode-keep-alive.tsx:67-96`, mounted by `WorkModeKeepAlive` at `:50-65`) **keeps every visited work mode mounted** and hides the inactive ones with `hidden` plus a `hidden` class, so in-flight state survives a rail switch. The whole set remounts when the desk moves from one real workspace scope id to another (`key={next.key}`, `nextDeskKey` in `apps/web/lib/desk-pane-key.ts`, `work-mode-keep-alive.tsx:60-64`); the first id of a cold load is adopted without a remount (2026-10-02, it used to remount every pane once). Consequence for anyone driving the app: after visiting `/images` and then `/videos`, `images-studio` is still in the DOM (count 1, not visible) and any testid the two pages share — `example-gallery` is the one that bites — resolves to **two** elements.

### 2. Mount → `GET /api/v1/images` (or `/videos`)

`load()` (`apps/web/components/images-studio.tsx:70-91`, `apps/web/components/videos-studio.tsx:86-111`) runs once from an effect (`images-studio.tsx:93-95`, `videos-studio.tsx:113-115`) and is the only read. The Videos studio runs it once more when a hosted key is saved (`videos-studio.tsx:120-127`). It fills four pieces of state from one payload:

```
{ items: GalleryItem[], models: StudioModel[], defaultModel: string, ready: boolean }
```

On the host, `handleGetImages` (`packages/host/src/handlers/jobs.ts:41-67`) and `handleGetVideos` (`:83-111`) assemble it. Neither calls `requireGatewayAllowed` — **both GETs are ungated on purpose**, which is why the page renders fully with no key.

- `items` ← `listStudioGallery(tenant, "image"|"video")` (`packages/host/src/studio-generate.ts:690-717`): `media` rows for this organization, newest first (`listMediaByKind`, `packages/host/src/media.ts:44-50`), each joined against a sidecar `studio-meta.json` next to the media store (`packages/host/src/studio-media-meta.ts:28-30`) for prompt / aspect / model. The sidecar is best-effort; a missing entry just means a caption-less tile. A row whose file is gone from the store carries `fileMissing: true` (`studio-generate.ts:139`, set at `:713`): `missingTenantObjects` (`packages/host/src/tenant-storage.ts:672-694`) checks each row's storage path (`store.head`) in batches of 16 (`:656`) on the file backend (`objectStorageKind() !== "file"` returns nothing, `:674`), and reports nothing under COS, where each answer would be a network `HEAD`. The row stays listed, because it is the owner's data and nothing here deletes it. On the dev desk 36 of 72 video rows answered 404 on `/api/v1/media/<id>/file` and none was marked.
- `models` ← `listStudioImageModels()` / `listStudioVideoModels()` then `attachMediaPrices(...)` (`packages/host/src/handlers/jobs.ts:50-55`, `:90-95`). The price half is [`media-cost-estimate.md`](media-cost-estimate.md). Images still come from the merged catalog. Videos come only from `listProbedVideoModels` (`packages/host/src/selectable-models.ts:154-156`, over `listProbedModels`, `:141-152`): the four dialect arrays in the model cache (`models-cache.json` on a desk, the tenant's own `model_cache` row on the hosted server), `mediaKind(id) === "video"`, with no static `CHAT_MODELS` fill-in. A Seedance id the refresh did not return is not in the list and is not priced.
- `defaultModel` ← `resolveStudioGenerateDefault` (`packages/core/src/agents/generate-defaults.ts:96-119`), fed by `AgentService.listGenerateDefaultSources` (`packages/core/src/agents/service.ts:211`): the first agent, by `createdAt`, that unlocks this surface and carries an `imageGenModel` / `videoGenModel` pin; else the Settings pin; else the catalog preference. On Videos the pin is kept only when that id is in the probed list (`packages/host/src/handlers/jobs.ts:104-106`); otherwise the default is `defaultStudioVideoModel` (`packages/host/src/studio-generate.ts:181-183`), which is `availableVideoDefault` (`packages/core/src/models/key-models.ts:40`) over the probed list, so `""` when the refresh listed no video model. It does not invent `grok-imagine-video`.
- `ready` ← `studioRouteReady("image_gen"|"video_gen", workspaceId)` (`packages/host/src/studio-generate.ts:294-300`).

### 3. Where the model list comes from — `/v1/models`, cached, then bucketed

The picker is **not** fed by the app's own `/api/v1/models`. It is fed by the studio GET, which reads the same in-process catalog:

1. **Probe.** `refreshModelCache` (`packages/host/src/selectable-models.ts:363-456`) calls `detectCompatibleApi` against the pinned gateway, which is a `GET /v1/models` with the saved key. A desk with no key and no custom gateway **never calls out** (`:375-376`) — and on the way through it also clears any stale `openaiError` (`:392`) so a keyless desk does not keep showing "unreachable". On the hosted server a tenant that holds a key and has no cache row (it upgraded into per-tenant caches) would otherwise see **no image or video ids** until it saved Settings; the first catalogue read starts one background refresh for it (`warmHostedModelCache`, `selectable-models.ts:508`), and the studio list is live on the next load. A desk is untouched.
2. **Persist.** The result lands in `models-cache.json` under the desk's data dir (`packages/host/src/model-cache.ts:114`, written by `saveModelCache` at `:192-202`). **This file outlives the key.** Removing the key does not empty the picker — the owner's `:3000` desk is keyless and still lists 40 image ids and 22 video ids, from the last live probe.
3. **Merge.** `listCatalogModels()` (`packages/host/src/selectable-models.ts:79-118`, the merge in `memoizedCatalog` from `:87`) merges the four dialect caches and stamps context lengths from the models.dev registry, memoized on the two cache files' mtime+size. The registry this holds is a projection, one `context_length` per model that announces one (`projectContextRegistry`, `packages/host/src/models-dev-cache.ts:31`), read back from a cache file that is now ~0.4 MB instead of 8.7 MB; freshness comes from a `models-dev-cache.meta.json` sidecar, so deciding whether to re-download no longer parses the registry.
4. **Bucket.** `routeModelsByKind` (`packages/core/src/models/media-kind.ts:158-170`) puts every id in exactly one of `chat / image / video / audio / other` by running `mediaKind(id)`. `listImageModels()` / `listVideoModels()` are `routed.image` / `routed.video` (`packages/host/src/selectable-models.ts:132-138`). Images studio uses that merged list. Videos studio does not: `listStudioVideoModels` defaults to `listProbedVideoModels` (`packages/host/src/studio-generate.ts:173-175`), the probed rows only.
5. **Prefer.** `pickPreferredImageModel` / `pickPreferredVideoModel` (`packages/core/src/models/media-kind.ts:184-192`) walk `IMAGE_PREF` (`media-kind.ts:16`, `gpt-image-2` first) / `VIDEO_PREF` (`media-kind.ts:46-53`: `seedance-2.0`, its dated Doubao spelling, `seedance-2.5`, then Veo fast, Grok Imagine and Omni; the live catalogue of 2026-09-30 lists only the two Seedance ids) and, when nothing matches, fall back to `DEFAULT_GATEWAY_IMAGE_MODEL` / `DEFAULT_GATEWAY_VIDEO_MODEL`. The Videos studio default does not take that last step: `defaultStudioVideoModel` (`packages/host/src/studio-generate.ts:181-183`) calls `availableVideoDefault`, which returns `""` unless the chosen id is in the probed list.

`ModelSelect` (`apps/web/components/model-select.tsx:41-77`) renders it as a plain `<select>` with `<optgroup>`s from `pickerGroups` (`packages/core/src/models/preferred.ts:419-444`), which also applies the chat hide-list and drops dated snapshots. Core returns each group as `{ kind, label, models }` with `kind` one of `recommended | brand | other` (`:415-417`); the renderer turns the two groups that are words into the desk's language through `pickerGroupLabel` (`apps/web/lib/picker-group-label.ts`, catalog `chat.models.groups.*`: "Recommended" is "Disarankan" and "Other" is "Lainnya" in Bahasa Indonesia), leaves brand names alone, and names the flat embeddings list from `chat.models.groups.embeddings` (`model-select.tsx:55`). Until 2026-09-29 these headings were English literals in both locales. Each option label ends with the price hint the studio attached (`apps/web/components/model-select.tsx:32-38`), e.g. `gpt-image-2 · 272K · $0.03/gbr`.

### 4. The needs-key state

Videos renders its note from the route and, on the hosted build only, from the hosted key hook:

```tsx
{keyMissing || (!ready && !loading) ? (<p data-testid="videos-studio-needs-key">…</p>) : null}
```

(`apps/web/components/videos-studio.tsx:403-405`). `keyMissing` is `useHostedNeedsKey()` (`apps/web/lib/use-desk-needs-key.ts:73-75`), which is `useDeskNeedsKey({ hostedOnly: true })`: off the hosted build it is always `false` and makes no request, so on Personal and webdev the note is the route's `ready` alone. Submit is disabled on `!keyReady`, where `keyReady = ready && !keyMissing` (`videos-studio.tsx:128`, `:397`). When a hosted key is saved in Settings the studio reads the gallery again (`videos-studio.tsx:120-127`).

Images renders the same testid from the host gate, the same flag that disables submit:

```tsx
{needsKey && !loading ? (<p data-testid="images-studio-needs-key">…</p>) : null}
```

(`apps/web/components/images-studio.tsx:231`). `needsKey` is `useDeskNeedsKey()` (`apps/web/lib/use-desk-needs-key.ts:36-61`) → `hostWithholdsLiveModel` (`:14-17`), true only when `allowed === false`. On the hosted build the hook also reads the shared gate store, so a key saved in Settings clears the note without a reload.

**The empty-model card (2026-10-19, QA report BUG-03/04).** When the gallery read has succeeded (`listed`), loading has finished, the key is in place and `models` is empty, `studioPickerEmpty` (`apps/web/lib/studio-picker-empty.ts`) is true. Both studios then drop the `ModelSelect`, render `images-studio-no-models` / `videos-studio-no-models` (title `*.noModels.title`, body `*.noModels.body` through `SettingsLinkHint`), and disable Generate with the body sentence as its `title`. A failed read never sets `listed`, so it never claims the key lists nothing. Tests: `apps/web/lib/studio-picker-empty.test.ts`.

**Disabled Generate colour (BUG-14).** `.btn-primary:disabled` in `apps/web/app/globals.css` paints every disabled primary button as a grey pill (`--line` fill, `--text-3` text, opacity 1) in both themes. It sits after `@tailwind utilities` at the same specificity, so it also wins over `disabled:opacity-50`. Before, `.btn:disabled` dimmed the accent to 45%, which read as a pale wash on light and a live-looking navy on dark.

`SettingsLinkHint` (`apps/web/components/settings-link-hint.tsx:7-31`) splits the catalog string on a sentinel and drops a real `<a href="/settings">` in the gap, so the banner is always a working link and never hard-codes English.

`ready` walks back to `listToolRoutes` (`packages/core/src/tools/credentials.ts:375-388`) resolving the `image_gen` / `video_gen` capability. Both declare backends `gateway` → `fal` → (`openai` / `volcengine`) with an autodetect order of `["gateway", "fal"]` (`:86-110`, `:111-135`), and a backend is ready when its env var is populated from `secretMapFromSettings` (`:311-355`; the resolution is `resolveToolBackend`, `:255-299`). No `OPENAI_API_KEY` and no `FAL_KEY` means no ready backend means `ready: false`. Videos disables `videos-studio-submit` while `!keyReady`. Images does not: submit follows `allowed`, so a keyless stub desk can still generate.

### 5. Knob snapping — the model decides which controls exist

`packages/core/src/models/video-capabilities.ts` is the whole rule set, and the Videos studio re-derives it on every render (`apps/web/components/videos-studio.tsx:130-131`).

`videoCapabilities(model)` (`video-capabilities.ts:56-59`) picks one of two profiles and then overrides one field:

| | `ratio` | `resolution` | `seconds` | `still` |
|---|---|---|---|---|
| `SEEDANCE_ALL` (`:17-22`) | ✔ | ✔ | ✔ | ✔ |
| `OPENAI_LIKE` (`:24-29`) | ✘ | ✘ | ✔ | ✔ |

`usesSeedanceVideoWire` (`:32-34`) chooses between them, and its regex is `seedance|dreamina-seedance|doubao-seedance|veo_|kling|sora` — **"Seedance-class" includes Veo, Kling and Sora.** `imageToVideo` is a separate, honest gate (`imageToVideoForModel`, `:40-54`) that returns false for `mj_video` and `omni-fast-v2v` even though their profile's legacy `still` flag is true; the comment at `:36-39` says so out loud.

What the three knobs do with that:

- **`videos-studio-resolution`** is `disabled` when `!caps.resolution` (`apps/web/components/videos-studio.tsx:313`) and is dropped from the POST body entirely when the model is not Seedance-wire (`:189`). The live matrix proved why: `grok-imagine-video` answers `json: unknown field "ratio"`.
- **`videos-studio-seconds`** lists `allowedVideoSeconds(model)` (`packages/core/src/models/video-capabilities.ts:68-73`), which is `[4, 6, 8]` for any `veo[_-]` id and `[5, 8, 10]` for everything else. When the model changes, an effect re-snaps the current value through `snapVideoSeconds` (`:76-80`, called from `apps/web/components/videos-studio.tsx:133-135`) — nearest allowed length, ties to the shorter clip. Driven: 10 s on `seedance-2.0-fast`, switch to `veo_3_1-fast`, the select lands on 8.
- **`videos-studio-still`** is not rendered at all when `!caps.imageToVideo`; a muted "text to video only" line takes its place (`apps/web/components/videos-studio.tsx:322`, `:367`). The still box is a text field (`:335`, `inputMode="url"`, not `type="url"`, so the browser's URL check does not block a stored reference on submit). A second effect clears any typed URL and any picked picture when the capability goes away (`:137-142`), so a stale still cannot ride along after a model switch. Below the box, **Use a saved image** (`saved-picture-picker.tsx`, `videos-studio-saved-open`) opens a grid of `GET /api/v1/images`, the Images gallery's own list, which is read on each open and is already filtered to what the file route would open for the caller (`packages/host/src/media.ts:44-50`, `listMediaByKind`), with `fileMissing` rows left out (`apps/web/lib/saved-picture.ts:12-14`, `apps/web/components/saved-picture-picker.tsx:41`). A pick is held apart from the typed URL (typing clears the pick, a pick clears the box) and goes out as `/api/v1/media/<id>/file` through `stillSource` (`apps/web/lib/saved-picture.ts:16-28`), never as `mediaSrc(url)`, which is the desktop scheme on Personal. A 404 `not_found` on a pick is answered with its own sentence (`videos.savedPicture.unusable`, `videos-studio.tsx:211-212`), because a picture over 6 MB reads as not found.

Images has one knob, `images-studio-aspect` (`square` / `landscape` / `portrait`, `apps/web/components/images-studio.tsx:54`). Until that menu is touched, `chooseImageFrame` (`apps/web/components/images-studio.tsx:98`, `packages/core/src/images/harness.ts:65-78`) sets it from the sentence: a poster is portrait, a banner is landscape, and a clash or a plain sentence stays square. It is not model-dependent.

**The prompt row answers to its own width (2026-10-01).** In both studios the Enhance button, the prompt and the submit button are one `PROMPT_ROW` (`apps/web/lib/prompt-row.ts`; `apps/web/components/images-studio.tsx:199-236`, `apps/web/components/videos-studio.tsx:371-408`), the prompt is `PROMPT_INPUT` and the submit button starts with `PROMPT_SUBMIT`. The row is a size container: at 40rem of row width or less the submit takes its own line below the prompt, and at 26rem or less Enhance keeps its icon, `title` and accessible name but its word (`.enhance-btn-label`) is `sr-only`. Measured on `:3000` (2026-10-01): at a 390px viewport the row is about 232px, the prompt is 184px, `images-studio-submit` / `videos-studio-submit` is 232px wide on the line below, and Enhance is 40px wide; at 768px the row is 446px, so the submit is still on its own line but Enhance shows its word (148px); at 1280px it is one line (prompt about 700px, submit about 94px). The selects above it are `select-field` (aspect, seconds and resolution plain, the model select `min-w-[12rem] flex-1`; `apps/web/components/images-studio.tsx:163`, `:183`, `apps/web/components/videos-studio.tsx:271`, `:289`), not `.input`.

### 6. Submit → `POST /api/v1/images` or `/api/v1/videos`

`onSubmit` (`apps/web/components/images-studio.tsx:106-134`, `apps/web/components/videos-studio.tsx:172-226`) posts JSON through `apiFetch`, so the packaged app routes it over IPC exactly like Chat does. The video body carries `seconds` always and `resolution` only when the model is Seedance-wire (`:183-190`). On a 2xx it clears the prompt and re-runs `load()` — the new clip appears because the **gallery is re-fetched**, not because anything was pushed into local state. A Videos error that names a model the key does not list drops that model from the picker and selects the suggested one (`videos-studio.tsx:198-203`).

On the host, `handlePostImages` / `handlePostVideos` (`packages/host/src/handlers/jobs.ts:69-81`, `:113-125`) are straight-line calls in this order:

1. `getTenant(request.workspaceId)`
2. `requireGatewayAllowedFor(tenant)` — **this is the gate**, and it lives only on the POSTs. See [`settings-and-gateway-gate.md`](settings-and-gateway-gate.md).
3. `parseImageGenerateBody` / `parseVideoGenerateBody` (`packages/host/src/studio-generate.ts:211-228`) — zod, a 400 on the first issue. `imageUrl` takes an https URL as before, or a stored image's reference, `/api/v1/media/<id>/file` or the bare id, the chat tools' form (`studioImageSourceSchema`, `:74`). The video parser adds one semantic check before anything runs: an `imageUrl` on a model whose `imageToVideo` is false is `video_still_unsupported`, 400 (`:224-226`); the harness checks the resolved model again below. A reference is resolved after the parse, in `studioSourceImage` (`studio-generate.ts:306-317`), before the stub stand-in and before the harness, through `chatMediaReferenceResolver` (`packages/host/src/chat-media-resolver.ts:9-15`), so it sees only what the chat tools see. A reference the caller may not see and an id that is not there both answer 404 `not_found`, "Media not found" (`studio-generate.ts:314`); a malformed reference is the parser's 400. A reference is never fetched, and a URL reaches the tool unchanged. The resolver also answers null for a non-image row, for the caller's own image over 6 MB (`TOOL_IMAGE_MAX_BYTES`, `packages/core/src/tools/media-reference.ts:12`) and for a video id, so those are 404 too.
4. `generateStudioImage` / `generateStudioVideo`, each run under `withRunSlot` (`handlers/jobs.ts:74`, `:118`) and answered `201`.

### 7. The generate helper — no run, no thread, no stream

`generateStudioImage` (`packages/host/src/studio-generate.ts:319-407`) calls `runImageSkills` (`packages/core/src/images/harness.ts:109-114`):

1. Resolve the model: body → `settings.imageGenModel` → `defaultStudioImageModel(undefined, tenant)` (`studio-generate.ts:327`). 2. Write a brief: the masked sentence is the subject, plus one still, no collage, no invented text (`writeImageBrief`, `packages/core/src/images/harness.ts:51-59`). `withImageOutputLanguage` stamps the run locale on that brief (`studio-generate.ts:344`). The gallery stores the sentence they typed, not the brief.
3. Choose the frame with `chooseImageFrame` when `aspect` was omitted (`packages/core/src/images/harness.ts:65-78`, called at `:119`). The page sends the frame the menu is showing.
4. One `imageGenerateTool.execute` inside `runWithToolSecrets` (`studio-generate.ts:341-351`). On `AGENTFORGE_RUNTIME=stub`, and only when `workType` is not `Edit`, this step returns a 1×1 PNG and does not call the tool (`:330`, `:338-340`).
5. If the tool returns no URL and `imageMissMayRetry` (`packages/core/src/images/harness.ts:89`, patterns at `:47-48`) matches a connection that never left (`fetch failed`, `ECONNREFUSED`, `ENOTFOUND`), the same brief runs once more (`:124`). A timeout, an HTTP body, or a missing key is not retried.
6. `saveGeneratedImage` mirrors the URL (`studio-generate.ts:381-382`, `packages/host/src/media.ts:158`) → a local `/api/v1/media/<id>/file`. A live call records `recordImageUsage` first (`:378-380`); the stub stand-in does not.
7. Sidecar meta (`:385-392`) and a Knowledge work card (`:393-404`, `packages/host/src/work-cards.ts:99`) — a text card holding their sentence, the frame, the model, and a `media:<id>` pointer. **No bytes go to Knowledge.**

`generateStudioVideo` (`packages/host/src/studio-generate.ts:433-501`) is not a second copy of the image helper. It calls `runVideoHarness` (`packages/core/src/videos/harness.ts:164-250`), and `videoToolResult` (`studio-generate.ts:409-431`) turns the tool's output into the harness's `VideoRenderResult` (success, `model_not_on_key` with a suggestion, or `tool_failed` with its status):

1. **Write the shot.** A sentence that does not already name a camera and a motion becomes subject, one motion, and one camera (`composeVideoShot`, `packages/core/src/videos/harness.ts:84-95`). The owner's sentence has to remain in the shot (`shotKeepsAsk`, `:98-101`); a draft that drops it is repaired once (`acceptVideoShot`, `:106-120`). A prompt that already has both, or is already 400 characters, is sent as written. The outbound prompt is `withOutputLanguage(maskPii(shot), "videos", locale)` (`:190`).
2. **Fit the key.** `resolveVideoModelForKey` still refuses an id the refresh did not list (`packages/core/src/videos/harness.ts:173-184`). `snapVideoSeconds` still picks the length (`:189`). A still on a model whose `imageToVideo` is false throws `video_still_unsupported` before any render (`:186-188`). The studio's own readiness gate runs before the harness (`studio-generate.ts:438-440`).
3. **Render once more when the job dies before a video file.** A timeout, HTTP 502/503/504, a dropped connection, or a URL that is not a video is tried once (`videoRenderShouldRetry`, `packages/core/src/videos/harness.ts:129-134`, and the loop at `:205-227`). A missing key, a rejected key, a model the refresh did not list, a still the model cannot take, and a prepaid-price refusal are not retried.
4. **Keep the clip.** A video URL is the only success (`clipIsVideoUrl`, `packages/core/src/videos/harness.ts:139-157`). Usage (`studio-generate.ts:467-471`), the gallery sidecar (`:476-484`, prompt is the shot, `durationSeconds` is the snapped length), and the Knowledge card (`:485-498`) all record that snapped length. The JSON body still returns the owner's sentence as `prompt`.

The image path has no route-ready check. Videos still 400s with `gatewayRequiredMessage` when the route is not ready (`studio-generate.ts:438-440`), unless a test injects `renderVideo`. ### 8. The wire

Both tools resolve their backend first and return a **structured failure rather than throwing** when there is none (`packages/core/src/tools/platform/image-generate.ts:109-125`, `packages/core/src/tools/platform/video-generate.ts:122-138`) — which is exactly how a keyless submit becomes a 400 with a "add a key in Settings" message instead of a 403.

**Images**, gateway backend (`packages/core/src/tools/platform/gateway-media.ts:303-396`): `POST <base>/images/generations` with `{ model, prompt, size }`, plus `quality: "medium"` for any `gpt-image` id (`:311-313`), plus `image` when editing. `size` comes from `openaiImageSize` (`:145-153`): `1024x1024` / `1536x1024` / `1024x1536`. **Every gateway image model gets OpenAI pixel sizes**, not a ratio string. A 180 s `AbortSignal.timeout` guards both the create and each poll (`:323`, `:353`), and a timeout is reported with an explicit "may already have billed" warning (`:292-293`).

**Videos**, gateway backend (`:398-453`): `POST <base>/video/generations`, then poll `<base>/video/generations/<taskId>` up to 90 times (`maxPolls`, `:434`) at 2 s (`pollMs`, `:435`). `buildGatewayVideoPayload` (`:162-207`) is the fork:

- Seedance-wire (`:172-193`): `content[]`, `duration`, `resolution`, `ratio`, `generate_audio: false`, `watermark: false`, and a still attached twice — inside `content` as `role: "first_frame"` and at the top level as `image`, because Veo and Kling read the generic field.
- Everything else (`:197-206`): `{ model, prompt, duration, seconds: String(duration) }` and nothing more. The comment above it records why — grok rejected pixel `size`, then rejected `ratio`.

`clampVideoSeconds` (`packages/core/src/models/video-capabilities.ts:82-87`) squeezes duration into 2–12 one last time here, so there are **three** snap points on a video request: the UI effect, the harness (`packages/core/src/videos/harness.ts:189`), and the payload builder.

### 9. Gallery and serving

`items` render as a grid (`apps/web/components/images-studio.tsx:248-259`, `apps/web/components/videos-studio.tsx:421-448`), each `src` passed through `mediaSrc` (`apps/web/lib/api-client.ts:459` → `desktopMediaSrc`, `apps/web/lib/media-src.ts:12-23`), which rewrites `/api/v1/media/<id>/file` to `agentforge://media/<id>` inside the packaged shell and leaves it alone in the browser. Videos add a per-clip download anchor, `videos-studio-download` (`apps/web/components/videos-studio.tsx:435-444`), which a `fileMissing` row does not get. An empty list renders the studio's character landing, `<StudioEmptyDesk flush />` (`apps/web/components/images-studio.tsx:243-246`, `apps/web/components/videos-studio.tsx:416-419`; skipped while a generate is running), whose root is `images-studio-empty` / `videos-studio-empty` (`apps/web/components/studio-empty-desk.tsx:123`, the root's `data-testid`). Those two testids exist again as of 2026-10-01; before that an empty list rendered nothing.

**What a tile mounts** (`apps/web/components/gallery-media.tsx`, shared by Images, Videos and Music). The Videos page used to mount one bare `<video controls>` per row, with no `preload` and no error state: 72 rows plus the 6 bundled examples was 78 video elements on one page, and half the rows had no file. Now:

- A row the host marks `fileMissing`, or whose file fails to load (`onError`, `:106` / `:121` / `:137`), shows `MediaMissingTile` (`:64`, `data-testid="media-missing"` at `:70`, words in `common.mediaMissing.*` in both locales) at the player's size, and mounts no player, so it asks for nothing.
- `GalleryVideo` (`:80`) mounts its `<video>` only once its tile has been within 300 px of the viewport (`useNearViewport`, `:38`, an `IntersectionObserver`; it never un-mounts a tile that has been seen) and is `preload="none"` except the newest four (`GALLERY_METADATA_COUNT`, `:23`; `galleryPreload`, `:28-30`), which fetch `metadata` so the top of the gallery is not a wall of black. Driven headless at 1280 px on the dev desk: 6 `<video>` on first paint, all 6 bundled examples, and 0 media requests; scrolling the whole gallery mounted 68 of 72 rows with `preload="none"` and made 4 media requests (the newest four), not 72.
- `GalleryImage` (`:124-140`) is `loading="lazy"` (`:134`); `GalleryAudio` (`:114-121`) is `preload="none"`.
- **A hidden Browser pane mounts no gallery player.** `IntersectionObserver` does not fire while `document.visibilityState` is `"hidden"`, so a drive that counts `<video>` in the gallery from the IDE's Browser pane sees 0. Use a visible window or headless Chromium.

`GET /api/v1/media/:mediaId/file` → `handleGetMediaFile` (`packages/host/src/handlers/media.ts:25-51`), routed at `packages/host/src/router.ts:363`, ungated, scoped by `organizationId`. The bytes come from `readTenantObjectRange` (`handlers/media.ts:40`, `packages/host/src/tenant-storage.ts:635-641`), which on the file backend answers only the requested range (`readRange`, `tenant-storage.ts:203`, `parseByteRange`, `packages/host/src/byte-range.ts:12`), so scrubbing a clip reads only the requested bytes. The bundled example clips have their own pair of routes (`packages/host/src/router.ts:372-373`, `packages/host/src/handlers/video-examples.ts`).

## Gotchas

- **Every generate now leaves a usage row.** `recordImageUsage` (`packages/host/src/studio-generate.ts:378-380`)
  fires right after the image harness returns, and only for a live call: a stub Images stand-in never reached the
  gateway, so it leaves no row. `recordVideoUsage` (`:467`) fires after the harness
  has kept a video URL, and still before the file is stored, because the gateway has already
  charged by then. Images are metered in images, videos in the *snapped* seconds. See
  [`tenant-usage-ledger.md`](tenant-usage-ledger.md).

- **The picker outlives the key.** `models-cache.json` (`packages/host/src/model-cache.ts:114`, written by `saveModelCache` at `:192-202`) is written by the last successful probe and read unconditionally by `loadModelCache` (`:172`). A desk with `hasOpenai: false` still shows whatever that probe returned. Images also fill an empty provider from static `CHAT_MODELS`. Videos do not: an empty probe is an empty `videos-studio-model`, and a static Seedance row is not priced. A model the video route then refuses with "not available for this key" is dropped from the picker (`apps/web/components/videos-studio.tsx:198-203`) and the error names another probed id (`rewriteModelNotOnKey`, called from `videoToolResult`, `packages/host/src/studio-generate.ts:420`).
- **"Seedance-class" includes Veo, Kling and Sora.** `usesSeedanceVideoWire` (`packages/core/src/models/video-capabilities.ts:32-34`). Reading the name instead of the regex leads you to expect `videos-studio-resolution` to be disabled on the default model; it is enabled.
- **`videos-studio-seconds` is not a fixed set.** Veo ids get `[4, 6, 8]` (`:65`, `:68-73`), everything else `[5, 8, 10]`. Until 2026-09-30 `veo_3_1-fast` led `VIDEO_PREF`, so `4 / 6 / 8` was what a driver saw first. `seedance-2.0` leads it now (`packages/core/src/models/media-kind.ts:46`), so on a catalogue that lists it a driver sees `5 / 8 / 10` first and has to pick a Veo id by hand for `4 / 6 / 8` (not driven in a browser).
- **Three places snap the clip length**: the UI effect (`apps/web/components/videos-studio.tsx:133-135`), the harness (`packages/core/src/videos/harness.ts:189`), and the payload builder (`packages/core/src/tools/platform/gateway-media.ts:171`). Only the last one clamps to the 2–12 window; the first two snap to an allowed option.
- **`still` and `imageToVideo` are two different flags and the legacy one lies.** Both `SEEDANCE_ALL` and `OPENAI_LIKE` set `still: true` (`video-capabilities.ts:17-29`); only `imageToVideoForModel` (`:40-54`) is honest, and only it drives the field (`apps/web/components/videos-studio.tsx:322`). The harness refuses a still on a model that cannot take one (`packages/core/src/videos/harness.ts:186-188`), as the parser does for a body model. Driven: `videos-studio-still` count 0 on `mj_video` and `omni-fast-v2v`, 1 on `grok-imagine-video`.
- **Images note and submit share `allowed`.** `images-studio-needs-key` renders when `needsKey && !loading` (`images-studio.tsx:231`); `images-studio-submit` is `disabled` on `needsKey` (`:225`). Stub `allowed: true` hides the note and can generate. Videos disables submit on `!keyReady` and shows its note on `keyMissing || (!ready && !loading)` (`videos-studio.tsx:397`, `:403`).
- **`generateStudioVideo` re-checks readiness and `generateStudioImage` does not** (`packages/host/src/studio-generate.ts:438-440` for the video; `generateStudioImage`, `:319-407`, has none). The image path relies entirely on the tool's own backend check, which is why its keyless failure on a live runtime is a `tool_failed` 400 rather than an `invalid_request` 400. Same status, different code, different message. A stub Images desk saves a stand-in instead (`:330`, `:338-340`).
- **Every gateway image request carries OpenAI pixel sizes**, whatever the vendor (`packages/core/src/tools/platform/gateway-media.ts:145-153`, used unconditionally at `:309`). `quality: "medium"` is added only for `gpt-image` ids (`:311-313`) — which is also why the estimate line says "at medium quality" for exactly those models.
- **`gateway_blocked` reaches the studios as a string, and only the hosted build maps it.** The host answers a flat body whose `error` is a string (`packages/host/src/errors.ts:20-25`). Both studios pass the body through `messageUnlessBlocked` (`apps/web/components/images-studio.tsx:123`, `apps/web/components/videos-studio.tsx:213`), which answers the catalog sentence only when `hostedGatewayBlocked` reads the body as a hosted block (`apps/web/lib/gateway-blocked.ts:19-21`, `:42-44`). Off the hosted build the fallback `data.error?.message` is `undefined` for a string, so a closed gate shows the generic "generate failed" copy on Personal and webdev. The same finding is recorded for Chat in [`chat-send.md`](chat-send.md).
- **Visiting a studio leaves it mounted.** `WorkModeKeepAlive` (`apps/web/components/work-mode-keep-alive.tsx:50-96`, the panes in `WorkModePanes`) hides rather than unmounts, so `example-gallery` resolves to two elements once both studios have been visited, and `images-studio` has count 1 while the user is on `/videos`. Driven; it is a Playwright strict-mode violation on any shared testid.
- **The empty state is behind the loading state.** `loading` starts `true` and both the `*-studio-needs-key` box and `*-studio-empty` are suppressed until it flips. Snapshotting the page as soon as `images-studio` becomes visible reads `null` for both. Wait for `*-studio-model` to gain options instead.
- **A missing media file is a 404 on this tree, not a 500.** `handleGetMediaFile` reads through `readTenantObjectRange` (`packages/host/src/handlers/media.ts:40`); the file backend's `readRange` turns an ENOENT into `objectNotFound()` (`packages/host/src/tenant-storage.ts:203-214`, `packages/host/src/tenant-object-keys.ts:28-30`), a 404 `not_found` whose message is "That file is not available on this account", so no host path reaches the response. An earlier drive on `:3000` recorded a 500 with the absolute path from the older `readByteRange` route. That drive is not repeated here; the change is read from the tree only.
- **The gallery is org-scoped, not desk-scoped**, exactly like the rest of the media store — open finding `b9`, see [`renderer-media.md`](renderer-media.md).
- **A successful generate writes a Knowledge source; loading an example prompt does not.** `upsertWorkSource` runs only from the two generate helpers (`packages/host/src/studio-generate.ts:393-404` for an image, `:485-498` for a video, which stores the shot and the snapped length); `videos-example-use-*` calls `onPick` → `pickTemplate`, pure React state (`apps/web/components/video-examples.tsx:134-140`, `apps/web/components/videos-studio.tsx:160-165`), and issues no request at all.
- **`/runs/image` and `/runs/video` are not these routes.** They are chat runs that *consume* media: `parseImageRunInput` demands at least one `image_url` part and rejects `video_url` outright (`packages/core/src/content/parse-run-input.ts:57-58`, `:165-167`). Posting a generate body there is a 400 for a completely unrelated reason.

## Why

**Why the studios post to their own route instead of a chat run.** `[Direct]` The run routes are typed the other way round: `parseImageRunInput` "image runs require at least one `image_url` part" and rejects `video_url` on the image route (`packages/core/src/content/parse-run-input.ts:57-58`, `:165-167`), so a generate body cannot be expressed there at all. `[Direct]` `.cursor/skills/verify-agentforge/features/images.md` states the same boundary as a harness rule: "The studio posts to `/api/v1/images`, not `/runs/image`. `/runs/image` is fail-closed attach-and-analyze." `[Inferred]` the practical consequence — no thread row, no SSE, no run-stall guard — follows from `handlePostImages` and `handlePostVideos` being straight-line calls with no `startModalityRun` anywhere in `packages/host/src/handlers/jobs.ts` (the generate call is wrapped only in `withRunSlot`, `:74`, `:118`). **Confidence: high for the mechanism, medium for reading it as a deliberate split rather than an accident of history.**

**Why the non-Seedance video payload is so bare.** `[Direct]` The code comment at `packages/core/src/tools/platform/gateway-media.ts:194-196`: "Toko `/v1/video/generations` uses a strict JSON decoder per upstream. grok-imagine-video rejected OpenAI pixel `size`, then `ratio` (`json: unknown field`). Seedance still needs `ratio` + `resolution`. Keep this branch to prompt/duration/seconds." `[Direct]` The live matrix in `.cursor/skills/verify-agentforge/features/videos.md` records the same result from the other end: "`grok-imagine-video` accepted `prompt` + `duration` and also `seconds` (POST 200) … Seedance `ratio` returned **400** `json: unknown field "ratio"`." **Confidence: high.**

**Why `imageToVideoForModel` exists next to the `still` profile flag.** `[Direct]` The doc comment at `packages/core/src/models/video-capabilities.ts:36-39` names the change: "Honest image-to-video gate (G-20). Unknown ids are false. `still` remains the legacy UI-field flag and may stay true when `imageToVideo` is false." So the profile flag was kept for compatibility and a second, conservative predicate was added in front of the UI rather than editing the profiles. **Confidence: high for the what; the ticket `G-20` itself was not read.**

**Why the studio GETs are ungated while the POSTs are not.** `[Direct]` The comment repeated above both POST handlers (`packages/host/src/handlers/jobs.ts:72`, `:116`): "Every path below reaches the gateway, so a closed gate is a 403 here and not a failed call." `[Direct]` The GET handlers carry the mirror-image comment about prices (`:46-49`): "Nothing here reaches the network." `[Supported]` [`media-cost-estimate.md`](media-cost-estimate.md) and [`settings-and-gateway-gate.md`](settings-and-gateway-gate.md) both record the same rule — the routes that cannot reach the gateway stay open so a blocked desk is still navigable and still recoverable through Settings. **Confidence: high.**
