## Overview

Between those two points the host pulls claims from the question and any pasted text, searches each claim, reads pages, keeps only passages that are on the page, and builds a comparison in code. ## Overview

One Research turn: a question in the studio prompt bar, and a cited dossier on screen that can be downloaded, pushed into the Knowledge Base, or handed to Documents or Presentation. Between those two points the host runs a five-phase pipeline (plan sub-queries, web-search each one, fetch the pages behind the hits, extract verbatim passages, synthesize findings) and streams its progress as `job.*` server-sent events. Since 2026-10-03 the last model call is gated: the synthesis must pass three checks, and gets one repair round if it does not.

Two things to hold onto. **Research needs a gateway key for the model, and it does not need a search key.** A saved Tavily or Brave key is used when one is present; otherwise search is the keyless composite in `packages/core/src/tools/platform/keyless-search.ts` (Wikipedia and OpenAlex in parallel, encyclopedia hits first unless the query looks scholarly, then arXiv and Crossref when that pair is thin or the query looks scholarly, `searchKeyless`, `:85`). A missing search key is not a 503, and the studio does not ask for one. And **the streaming route never returns a non-2xx**: `POST /api/v1/research/stream` answers HTTP 200 and puts the failure in a `job.error` frame, so the studio's error banner is an SSE payload, not an HTTP status. It is not a citation manager and not a live-search chat: the caps in `RESEARCH_CAPS` are fixed and "fully detailed" never means unbounded.

## How it works

### 1. Studio to request

`ResearchStudio` (`apps/web/components/research-studio.tsx:50`) is mounted permanently by `WorkModeKeepAlive` (`apps/web/components/work-mode-keep-alive.tsx:24`); the `/research` route element in `apps/web/src/App.tsx:391` is `null` so the studio is not double-mounted.

`onGenerate` (`:61-83`) trims the prompt, refuses when it is empty, a job is already running or the hosted desk has no key (`:64`), and calls `job.run("/api/v1/research/stream", { prompt, model, modelPinned? })` (`:68-71`). `model` comes from `useJobModel("research")` (`:53`), which seeds the `research-studio-model` select from the chat catalogue and `defaults.research`, overridden by `settings.researchGenModel` (`apps/web/lib/use-job-model.ts:66`, `SETTINGS_KEY` at `:20`). Only a deliberate pick travels as `modelPinned` (`modelPickBody`, `apps/web/lib/model-choice.ts:50`), so a seeded default stays rescuable by the host's fallback. On success the result is split (`:73-79`): the notes go to the Notes tab, `dossier.markdown` to the Dossier tab, and `dossierId ?? artifactId` becomes the artifact the action bar acts on. The `checks` the host returns ride along inside `notes` and nothing reads them (see Gotchas).

`useJobStream` (`apps/web/lib/use-job-stream.ts:114`) owns one `AbortController` at a time, in `createJobRunner` (`:54`). `research-cancel` calls `job.cancel` (`research-studio.tsx:169`), which aborts the fetch (`cancel`, `use-job-stream.ts:58`); the catch arm sees `abort.signal.aborted` and **resets quietly instead of setting an error** (`:89-92`), so a cancelled run shows nothing, not a banner.

### 2. Transport: the same SSE reader as Chat, a different event union

`runJobStream` (`apps/web/lib/job-stream.ts:90`) POSTs through `apiFetch` (so webdev `fetch` and packaged IPC both work), then rejects early if the response is not OK **or** its `Content-Type` is `application/json` (`:102-105`). That is the branch the non-stream JSON errors take. Otherwise it reads the body, feeds `parseJobEvents`, and keeps only frames that pass `isJobEvent` (`:11`, `packages/core/src/jobs/job-events.ts:75`). `settleJobEvents` (`:76`) turns a `job.error` into a thrown `JobStreamError` and a `job.done` into the result. If the stream ends with neither, it throws `stream_ended` / 502 (`:133`).

`reduceJobProgress` (`packages/core/src/jobs/job-events.ts:133`) folds the frames into the `JobProgress` the phase list renders, including the latest `job.round` (`:146`). `JobProgressList` (`apps/web/components/job-progress.tsx:28`) draws one `<li data-testid="research-progress-phase">` per phase (`:64`), a `research-progress-round` line when a repair round is running (`:50-58`, copy `common.jobProgress.round`, "Round {round} of {total} · {label}") and a `research-progress-sources` list of every `job.source` (`:80`). The studio draws the list only while the job is busy or before a result exists (`research-studio.tsx:188`), so the round line is gone once the dossier lands.

### 3. Host: gate, then stream

`packages/host/src/router.ts:370-371` maps both routes:

| Route | Handler | On refusal |
|---|---|---|
| `POST /api/v1/research` | `handlePostResearch` (`packages/host/src/handlers/jobs.ts:262`) | real HTTP status (503 stub, 403 gate) with `{error:{code,message}}` |
| `POST /api/v1/research/stream` | `handlePostResearchStream` (`packages/host/src/handlers/jobs.ts:274`) | **HTTP 200** + one `event: job.error` frame |

Both call `requireGatewayAllowedFor(tenant)` **synchronously, before** the job starts (`:266`, `:278`), so a closed gate is the one failure that is a real `403 gateway_blocked` on the stream route too. See [`settings-and-gateway-gate.md`](settings-and-gateway-gate.md).

Everything after that runs inside `streamJob` (`packages/host/src/job-stream.ts:30`). It returns `{ type: "stream", status: 200 }` immediately and starts `run()` in the background; the promise's rejection becomes `push(jobErrorFromUnknown(error))` (`:57-60`), which maps an `ApiError` to `{type:"job.error", code, message, status}` with the message run through `redactSecrets` (`:8-14`). `emit` drops any `job.done` / `job.error` a job tries to send itself (`:50-55`), and `push` drops everything after the first terminal frame (`:38-48`). The generator also stops as soon as the client aborts (`:65`). The client's abort reaches the job as `abortSignal`: on HTTP the response's `close` event aborts it (`packages/host/src/http-adapter.ts:665-669`), on packaged IPC the disconnect does the same.

### 4. The refusal that stub desks actually see

`generateResearchNotes` (`packages/host/src/research-generate.ts:119`) starts with `requireLiveResearch` (`:77-85`): `resolveRuntimeMode({ settingsHasKey: hasLiveProvider(settings), envRuntime: AGENTFORGE_RUNTIME })`, and `stub` throws `ApiError("runtime_stub", gatewayRequiredMessage("research", locale), 503)`.

Search is not part of that check. `webSearchTool` (`packages/core/src/tools/platform/web-search.ts:66`) uses Tavily or Brave when that route is ready (`:85-100`), and `searchKeyless` otherwise (`:101-107`). A backend the user explicitly selected, with that key missing, still returns an error and does not change vendor (`:78-83`). That is not the first-run path.

The gateway refusal comes from `packages/core/src/output-language.ts` (`GATEWAY_REQUIRED.research`, `:120`), **not** from `apps/web/locales/*/research.json` (see Gotchas). Nothing is written before this point: no artifact, no work card, no search call.

### 5. The pipeline: plan, search, read, extract, synthesize

### 5. The pipeline — claims → search → read → compare in code → the model writes the reading

`runResearchDossier` (`packages/host/src/research-dossier.ts:638-773`) is pure over its `deps`; it never touches settings or the DB. Caps are `RESEARCH_CAPS` (`:54-61`): 5 queries, 5 hits each, 10 pages, 8 000 chars per page, 3 concurrent reads, 5 passages per source. `throwIfJobAborted` (`packages/host/src/job-stream.ts:19-23`) runs between every phase and inside the read loop, so Cancel stops the spend early.

1. **Planning** — `emit({type:"job.phase", phase:"planning"})` (`:645`). One `ask(CLAIMS_SYSTEM, …)` (`:86-90`, `:648`) returns `{"claims": string[]}`. `parseClaims` (`:236-249`) keeps a claim only when that string occurs in the question or the pasted text; anything the model added is dropped. If none survive, `fallbackClaims` (`:252-257`) splits the prompt into sentences. One `ask(PLAN_SYSTEM, …)` still runs (`:83-84`, `:656`). A throw that is not `aborted` is swallowed (`:649-662`). `researchQueries` (`:266-273`) searches the claims first and lets planner queries fill the cap. The question itself is still inside `parsePlan` (`:150-159`), so a dead planner with no pasted claims still searches the question.
2. **Searching** — one `job.step` per query with `current`/`total` (`:672`), then `deps.search(query)` sliced to `hitsPerQuery` (`:673`). That `search` is the one Research already uses: a saved Tavily or Brave key, otherwise Wikipedia (the desk locale) and OpenAlex, then arXiv and Crossref. `dedupeCandidates` (`:175-201`) round-robins across queries so each contributes, drops anything that is not `https://`, dedupes on `normalizeUrlKey` (`:161-170`, hash stripped, trailing slashes trimmed), and numbers the survivors `S1…Sn`. Zero candidates is a hard `tool_failed` / 502 (`:676-678`). Every candidate is announced as `job.source` with status `found` (`:679-681`).
3. **Reading** — `mapWithConcurrency(candidates, 3, …)` (`:547-562`, `:687`). Per source (`readSource`, `:580-635`): `deps.readPage(url)` → `fetchPageText` over `fetchPublicHttps` (`packages/core/src/tools/platform/web-fetch.ts:26-51`: HTTPS-only, 1.5 MB, 10 s, readable content types only), then the injection guard `scanInjection` unless `settings.injectionGuardBypass` (`research-generate.ts:154-160`), then one `ask(EXTRACT_SYSTEM, …)`. **A page that cannot be read is not dropped** — the candidate is kept with `status: "unreachable"` and the search snippet as its only passage (`:619-633`), and a matching `job.source` frame is emitted (`:624`). An unreachable page contributes no claim hit.
4. **Extracting** — `parseExtraction` (`:216-224`) keeps only passages that are at least 20 chars **and actually occur in the page**, comparing through `squash` (`:204-214`: whitespace, case, curly quotes, en/em dashes and ellipsis normalised). A paraphrase silently disappears. `parseClaimPassages` (`:282-314`) keeps a stance only when the passage is on the page and the claim is one that was pulled. `literalSupports` (`:316-328`) counts a kept passage that contains the claim as that source saying it, with no model label.
5. **Comparing** — only if some source was `read` and kept a passage of at least 20 characters (`passageBackedIds`, `:432-445`, `:705-708`). Otherwise the run stops with `invalid_research` / 502 and the locale string `errorNoPassage` (`:37-51`). `job.phase` `comparing` (`:711`) uses `RESEARCH_HOST_COPY` (`Comparing sources` / `Membandingkan sumber`). `buildComparison` (`:340-374`) is the whole verdict. A claim with no kept passage is omitted. One source is `only`. Two or more sources that share one stance are `agree`. A split, or one source that both supports and contradicts, is `contradict`. The model does not write this row.
6. **Drafting** — one `ask(SYNTHESIS_SYSTEM, …)` (`:718-723`) over the comparison rows and the `sourcePromptBlock`s. The model writes the reading. `stripInventedQuotes` (`:377-387`, `:724-729`) removes a quotation that is not a span of a kept passage. `parseSynthesis` (`:400-429`) still unions listed ids with ids in the body and intersects with known ids. A `comparison` field in the model's JSON is ignored.
7. **Citation check, only when a finding needs it** — `findingCitesResolve` (`:448-451`) requires every id in `sources` and in the body to be passage-backed, and at least one such id. When that fails, one `job.phase` `checking` (`:731-733`) and one `ask(CITE_REPAIR_SYSTEM, …)` (`:116-122`, `:735-736`) over the passage-backed sources only. `groundFindings` (`:466-477`) then strips any `[S#]` that still does not resolve (`stripUnresolvedCites`, `:454-463`) and drops a finding that has no cite left. A dropped heading is appended to open questions via `citeGap` (`:767-769`). The repair call goes through the same `ask` as the others, so `withOutputLanguage(system, "research", localeForRun())` still applies (`packages/host/src/research-generate.ts:142`). `locale` on the dossier deps is `localeForRun()` (`packages/host/src/research-generate.ts:136`).
8. `dossierSchema.parse` (`:754-771`) is the last gate and stores `comparison` as `{ claim, verdict, sources }`. `dossierToMarkdown` (`packages/core/src/artifacts/dossier.ts:135-168`) prints `## Comparison` with the verdict phrase for `localeForRun()` (`research-generate.ts:170`). `notesFromDossier` (`:521-534`) derives the preview shape deterministically — each note's sources are looked up by id, and those ids are passage-backed, so **every citation in the Notes tab points at a real passage**.

Claims, plan, extract, synthesis, and the citation repair (when it runs) go through `collectJobAssistantRun` (`packages/host/src/research-generate.ts:137-150`) with `jobMode: "research"` and `withOutputLanguage(system, "research", localeForRun())`. Each is parsed with `extractJsonObject` + `JSON.parse`. A non-JSON claim list or plan is swallowed (`research-dossier.ts:239-242`, `:153-156`). A non-JSON extract or synthesis is `invalid_research` / 502 (`:124-129`). A non-JSON repair is ignored and the code check still runs (`parseRepairFindings`, `:480-499`). The comparison is not a model call.

#### 5a. The synthesis checks and the repair round

`synthesizeChecked` (`research-dossier.ts:371`) wraps the drafting call in `runChecked` (`packages/host/src/harness/run-checked.ts:71`) with three checks (`RESEARCH_SYNTHESIS_CHECKS`, `packages/host/src/research-checks.ts:180`, in the order the repair note lists them) and `repairRounds` from `harnessSpecFor("research")`, which is **1** (`packages/core/src/harness/modes/research.ts:17`):

| Check id | Fails when | Source |
|---|---|---|
| `research-citations-resolve` | The answer cites a source id no source of this run carries (the findings, the summary, a contradiction or an open question) | `citationsResolve`, `research-checks.ts:107` |
| `research-findings-cited` | A finding has no source that resolves | `findingsCited`, `:129` |
| `research-sections-filled` | The summary is empty, or a finding was dropped for an empty heading or body | `sectionsFilled`, `:148` |

A failure becomes an `ERROR` / `WHY` / `FIX` note (`formatRepairNote`, `run-checked.ts:35`) that names the sections (excerpts of 60 characters at most) and lists the allowed ids. The repair call re-sends the same synthesis prompt plus the previous raw answer and the note (`repairPrompt`, `research-dossier.ts:360`). Before each repair the pipeline emits `job.round` with `round`, `total` and a label (`onRound`, `:383-385`), "Repairing the findings" or "Memperbaiki temuan" by desk language (`repairRoundLabel`, `research-checks.ts:61`; the locale is read once in `generateResearchNotes`, `research-generate.ts:151`).

Unlike Documents and Presentation, a repair that goes wrong cannot cost the first answer here. `produce` catches a repair call that throws or returns unreadable text, keeps the earlier synthesis, records the error code as `repairFailure`, and lets the checks fail visibly (`research-dossier.ts:394-401`). Only the first call may throw. A cancel is thrown past that catch (`:395`).

The outcome is a `ResearchChecksReport` `{ passed, rounds, verdicts, repairFailure? }` (`research-checks.ts:46`). It is returned in the job result (`ResearchResult.checks`, `research-generate.ts:38`) **whether it passed or not**, and stored in the artifact `meta.checks` (`persistDossier`, `:101-109`). A dossier that still fails is saved and returned like any other.

#### 5b. Cancel

The abort signal now reaches the model call, not only the gaps between phases: `ask` passes it to `collectJobAssistantRun` (`research-generate.ts:163`), which checks it before each call and after a failed one (`job-regen.ts:255`, `:274`) and hands it to the runtime as `signal` (`:210`), where `linkCallerAbort` aborts the request in flight (`packages/core/src/runtime/ai-sdk-runtime.ts:146`). The page reader takes it too (`fetchPageText(..., { signal })`, `research-generate.ts:172`). The search call does not (`:169-170`), so a search in flight finishes before the next `throwIfJobAborted`. A cancelled job is the job's own `499 aborted`, thrown past the model fallback. Each run also takes the research spec's budget (`job-regen.ts:184`, `:207`), which bounds nothing today because the mode binds no tools.

### 7. Dossier to screen, and the four handoffs

`job.done` resolves `job.run`, and `setShown({kind:"run", ...})` renders (`research-studio.tsx:73-79`):

- `research-tabs` with `research-tab-notes` / `research-tab-dossier` (`:209-230`), only for a fresh run, never for a reopened artifact (`:208`).
- Notes tab: `ResearchPreview` (`apps/web/components/research-preview.tsx:9`), a `research-preview` wrapper (`:13`), one `research-note` `<section>` per finding (`:20`), bodies through `FormattedText`, source links through `safeLinkHref` (`:26`).
- Dossier tab: `research-dossier-preview` (`research-studio.tsx:237`), the raw Markdown through the same `FormattedText`.
- `ArtifactActions` (`apps/web/components/artifact-actions.tsx:21`) above both: `research-download` (`GET /api/v1/artifacts/:id/file`, or a client-side blob when there is no id, `:26`), `research-send-kb` (`POST /api/v1/knowledge/sources` with `type: "Dossier"`, `:42`), and `research-make-document` / `research-make-presentation`, which call `requestModeHandoff` (`apps/web/lib/mode-handoff.ts:47`) and `router.push` to `/documents` / `/presentations` (`artifact-actions.tsx:63-72`).
